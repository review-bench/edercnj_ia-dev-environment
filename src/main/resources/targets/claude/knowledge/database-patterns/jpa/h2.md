## JPA / H2 Integration (Test-Only)

H2 is used exclusively for integration tests. It is **not** a production database.

### Test Dependencies

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>test</scope>
</dependency>
```

### Spring Boot Test Configuration

```properties
# src/test/resources/application-test.properties
spring.datasource.url=jdbc:h2:mem:testdb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=
spring.jpa.database-platform=org.hibernate.dialect.H2Dialect
spring.flyway.enabled=false  # Disable Flyway in unit tests — use spring.jpa.hibernate.ddl-auto=create-drop
spring.jpa.hibernate.ddl-auto=create-drop
```

### Compatibility Modes

H2 supports compatibility modes that approximate production databases:

```
# PostgreSQL compatibility (closest to production)
jdbc:h2:mem:testdb;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DEFAULT_NULL_ORDERING=HIGH

# MySQL compatibility
jdbc:h2:mem:testdb;MODE=MySQL;DATABASE_TO_LOWER=TRUE

# Default (no compatibility)
jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1
```

### @DataJpaTest Pattern

```java
@DataJpaTest
@ActiveProfiles("test")
class MerchantRepositoryTest {

    @Autowired
    private MerchantRepository repository;

    @Autowired
    private TestEntityManager entityManager;

    @Test
    void findByMid_existingMid_returnsMerchant() {
        // Arrange
        var entity = new MerchantEntity();
        entity.setMid("123456789012345");
        entity.setName("Test Merchant");
        entityManager.persistAndFlush(entity);

        // Act
        var result = repository.findByMid("123456789012345");

        // Assert
        assertThat(result).isPresent();
        assertThat(result.get().getName()).isEqualTo("Test Merchant");
    }
}
```

### Flyway with H2 in Integration Tests

When Flyway must run in tests (to validate migrations):

```properties
# src/test/resources/application-integration.properties
spring.datasource.url=jdbc:h2:mem:testdb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1
spring.flyway.enabled=true
spring.flyway.locations=classpath:db/migration
```

PostgreSQL-specific SQL that H2 cannot handle must be guarded with placeholders or maintained in separate migration scripts for H2.

### Known H2 Limitations vs PostgreSQL

| PostgreSQL Feature | H2 Support | Workaround |
|-------------------|-----------|------------|
| `JSONB` type | Partial (MODE=PostgreSQL) | Use `JSON` or `TEXT` in tests |
| `RETURNING` clause | Yes (MODE=PostgreSQL 2.x) | Native query with `@Query(nativeQuery=true)` |
| Custom types / domains | No | Use base type in test DDL |
| `CONCURRENTLY` index | No (ignore in test DDL) | Remove `CONCURRENTLY` from test scripts |
| Partial indexes | Yes (H2 2.x) | Works |
| Window functions | Yes (H2 1.4.200+) | Works |
| Array types (`TEXT[]`) | No | Use `TEXT` in test entities |

### Pitfalls

- H2 `MODE=PostgreSQL` is not 100% compatible — always run integration tests against a real database in CI (Testcontainers)
- `DB_CLOSE_DELAY=-1` is required when multiple test classes share the in-memory database
- Never use H2 for performance testing — it does not represent production database behavior
- H2 case sensitivity differs from PostgreSQL — use `DATABASE_TO_LOWER=TRUE` to approximate
