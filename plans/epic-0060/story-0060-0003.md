## 1. Contexto & Escopo

Como **desenvolvedor do framework e operador humano**, eu quero que ADRs, specs, templates, baselines de governança, steering, contracts e results sejam movidos para seus novos lares canônicos (`docs/`, `governance/`, `.claude/templates/`, `ai/runs/`), garantindo que os 4 Java assemblers afetados emitam nos novos paths e que o histórico git seja preservado via `git mv`.

Esta story executa os movimentos físicos dos artefatos raiz que não são epics de IA — ela reorganiza a documentação humana e os baselines de governança conforme o mapeamento v3→v4 da especificação. É a story de maior impacto em superfície de artefatos (20 ADRs + 10 SPECs + 4 assemblers + 6 templates) mas sem lógica de negócio nova.

Após esta story, os operadores humanos encontram documentação em `docs/`, baselines de governança em `governance/baselines/`, e templates em `.claude/templates/<categoria>/`. O shim `adr/README.md` fica ativo por 1 release para compatibilidade de links externos.

### 1.2 Entrega de Valor

- **Valor Principal:** Centraliza toda documentação humana em `docs/` (único ponto de entrada), todos os templates em `.claude/templates/` (fonte única de verdade), e toda governança em `governance/` (separado de outputs de execução).
- **Métrica de Sucesso:** `find . -maxdepth 2 -type d \( -name adr -o -name specs -o -name audits -o -name steering -o -name contracts -o -name results \) ! -path './docs/*' ! -path './governance/*' ! -path './ai/*'` retorna vazio; `mvn verify` verde.
- **Impacto no Negócio:** Novo colaborador que abre o repo sabe imediatamente onde encontrar ADRs (`docs/adr/`), specs (`docs/specs/`), contratos de API (`docs/contracts/`), e runbooks (`docs/runbooks/`).

## 8. Decision Rationale

**Decisão:** Manter shim `adr/README.md` por 1 release após mover ADRs para `docs/adr/`.

**Motivo:** Links externos (GitHub, Slack, documentação de outros projetos) que apontam para `adr/ADR-NNN-*.md` continuarão funcionando via o shim por 1 release enquanto os links são atualizados.

**Alternativa descartada:** Redirecionar via `.htaccess` ou GitHub redirect. Descartada porque o projeto usa arquivos estáticos no GitHub, não um servidor web com suporte a redirects HTTP.

**Consequência:** Após 1 release, o shim é removido na Story 6. Links externos não atualizados dentro desse período resultarão em 404. Documentar no CHANGELOG com prazo claro.
