## 1. Contexto & Escopo

Como **engenheiro de governança e arquiteto do framework**, eu quero que as Rules 24, 26, 27 e 45, os 6 hooks Shell, e os Java assemblers afetados sejam atualizados com os novos paths canônicos do layout v4, garantindo que os gates de governança continuem funcionando após a migração de baselines e artefatos.

Esta story é a mais crítica para integridade do ciclo de vida. As Rules são carregadas em CADA conversa do LLM e definem os paths de evidência que o CI audita. Se Rule 24 ainda referencia `plans/epic-XXXX/reports/verify-envelope-*.json` mas o artefato agora está em `ai/epics/epic-XXXX-slug/work/stories/story-XXXX-YYYY-slug/reports/verify-envelope.json`, o CI falha para todos os epics v4.

Os hooks Shell (`verify-story-completion.sh`, `verify-phase-gates.sh`, `enforce-phase-sequence.sh`, `telemetry-emit.sh`, `telemetry-phase.sh`, `enforce-no-bypass-flags.sh`) fazem globs em paths físicos em tempo de execução — devem usar PathResolver wrapper Bash para detectar layout corretamente. As fixtures golden sob `src/test/resources/golden/` que contêm paths hardcoded também devem ser atualizadas.

### 1.2 Entrega de Valor

- **Valor Principal:** Governança CI continua operacional após a migração — gates de evidência, hooks de stop e audit scripts verificam artefatos nos novos paths automaticamente.
- **Métrica de Sucesso:** `scripts/audit-execution-integrity.sh --self-check` exit 0; `bash .claude/hooks/verify-story-completion.sh` detecta artefatos em `ai/epics/` para epics v4; `mvn verify` verde com golden fixtures atualizadas.
- **Impacto no Negócio:** Após esta story, o time pode confiar que o CI continua bloqueando PRs sem evidência de execução, mesmo com epics em layout v4. Zero falsos positivos por paths desatualizados em rules.

### 3.2 PathResolver Wrapper Bash (para hooks)

```bash
# Função auxiliar em hooks:
resolve_epic_dir() {
  local epic_id="$1"
  if ls "ai/epics/epic-${epic_id}-"* 2>/dev/null | head -1 | grep -q .; then
    echo "$(ls -d "ai/epics/epic-${epic_id}-"* | head -1)"
  else
    echo "plans/epic-${epic_id}"
  fi
}
```

## 8. Decision Rationale

**Decisão:** Implementar PathResolver wrapper como função Bash em `telemetry-lib.sh` (biblioteca shared para hooks) ao invés de duplicar em cada hook.

**Motivo:** 6 hooks precisam do mesmo probe. Duplicar `resolve_epic_dir()` em cada um cria 6 fontes de verdade que podem divergir. `telemetry-lib.sh` já é sourced por hooks para telemetria — é o ponto natural de extensão.

**Alternativa descartada:** Cada hook implementa seu próprio probe inline. Descartada porque a manutenção de 6 cópias é frágil — uma atualização no probe seria esquecida em pelo menos um hook.

**Consequência:** `telemetry-lib.sh` fica ponto de falha central para todos os hooks. Se a lib não for encontrada (path errado no source), todos os hooks falham silenciosamente. Deve ter `set -euo pipefail` e verificação explícita de existência antes do source.
