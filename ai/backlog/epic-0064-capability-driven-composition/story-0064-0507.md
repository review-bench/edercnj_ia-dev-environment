## 1. Contexto

Adiciona telemetria ao `CapabilityAwareComposer` (análoga à story-0064-0112 do resolver). Métricas:

- `tempoComposeMs` — tempo total do `compose()`.
- `numArtefatosIncluidos` — count de included.
- `numArtefatosPruneados` — count de excluded.
- `numFragmentosResolvidos` — count de fragments injetados.
- `tempoCompose / tempoCopyLegacy` — ratio para baseline (Rule 04 — composer ≤ 1.2× legacy).

Permite Rule 04 enforcement via `audit-capability-determinism.sh` (story-0064-0606): ratio > 1.2× alerta.

## 6. Decision Rationale

**Decisão:** `tempoCopyLegacy` capturado APENAS em CI benchmark runs (flag `--measure-legacy`); produção usa apenas tempo absoluto.
**Motivo:** Manter copy-legacy code rodando em produção apenas para mensuração é overhead permanente desnecessário. CI benchmark periódico (e.g., weekly) basta para detectar regressão de performance.
**Alternativa descartada:** Sempre rodar copy-legacy em paralelo com composer. Rejeitada por (a) overhead 100% (dobro do tempo), (b) copy-legacy será deletado em Phase 7 — manter ativo é débito técnico.
**Consequência:** `audit-capability-determinism.sh` (story-0064-0606) consome últimas 3 medições do CI benchmark; alerta se ratio > 1.2× em 2 medições consecutivas.

## 7. Implementation Notes

`tempoCopyLegacy` é capturado via wrapper que pode ser desativado em produção (apenas em CI capacity benchmark). Default: ratio não calculado, apenas tempo absoluto reportado.

Para baseline real, story-0064-0306 (Spring REST + Postgres golden) carrega num `tempoCopyLegacy = T0` registrado em arquivo fixture.
