## 1. Contexto

Núcleo do Phase 3: `CapabilityAwareComposer` (`dev.iadev.application.composition`) substitui o ramo de assemblers atuais que copiam `.claude/` integralmente. Recebe `ResolvedCapabilitySet` (do Phase 1) + raiz de `targets/claude/`, scaneia todos os artefatos, decide via `CapabilityMatcher` quais incluir/excluir, e produz um `CompositionPlan` de gravações.

API:
```java
CompositionPlan plan(ResolvedCapabilitySet activeSet, Path targetsRoot);
void execute(CompositionPlan plan, Path outputRoot);
```

Não escreve em disco diretamente — `OutputPruner` (story-0064-0302) e `CompositionEngine` (story-0064-0303) consumem o plan. Determinístico (Rule 04).

## 6. Decision Rationale

**Decisão:** API split em `plan()` (puro, retorna immutable) + `execute()` (side-effect, applies plan).
**Motivo:** Plan/execute split permite (a) dry-run reusing only `plan()` (story-0064-0305), (b) testabilidade — `plan()` é unit-testable sem disk I/O, (c) determinismo de plan auditável via JSON.
**Alternativa descartada:** API monolítica `compose(input, outputDir)` que faz tudo. Rejeitada porque mistura concerns; dry-run viraria flag em vez de operação separada (mais frágil).
**Consequência:** `OutputPruner` (story-0064-0302) consome `CompositionPlan`; ele é o único componente com side-effects de filesystem.

## 7. Implementation Notes

`ArtifactScanner` percorre `targetsRoot` recursivamente (Files.walk), parseia frontmatter de cada `.md` / `.sh`. `CapabilityMatcher` resolve glob (`data.database.*`) contra `activeSet` — Set lookup O(1) para atomics, regex match para globs.

`CompositionPlan` é record imutável: `List<ArtifactDescriptor> included, excluded, regenerated`. Ordem alfabética estável (TreeMap interno).
