## 1. Contexto

Expande a property-based test suite para cobrir as **4 invariantes canônicas** do EPIC-0064 com 10K casos cada (40K casos totais — meta do epic, seção 5 / DoD):

1. **Idempotência:** `compose(p) == compose(p)` (já em 0506, mas só 1000 casos).
2. **Determinismo:** mesmo input em 3 builds consecutivos = mesmo output bytewise.
3. **Pruning:** se capability X ausente do `ResolvedCapabilitySet`, output não contém artefato com `requires-capabilities: [X]`.
4. **Inclusion:** se capability X presente, todos os artefatos com `requires: [X]` (e prerequisites satisfeitas) estão no output.

10K casos por invariante = forte garantia estatística (jqwik tries=10000).

## 6. Decision Rationale

**Decisão:** 10K casos por property (vs default 1K do jqwik).
**Motivo:** Catálogo de produção terá ~80 capabilities × ~10 perfis canônicos = espaço de profiles válidos cresce combinatorialmente. 1K casos cobrem distribuição local; 10K aumentam confidence intervals e detectam casos extremos que aparecem ~0.1% do tempo.
**Alternativa descartada:** 1K tries (default jqwik). Rejeitada por confidence interval insuficiente para invariantes hard (determinismo precisa ser bullet-proof).
**Consequência:** Wall clock estimado 3-5min em CI moderno. Aceitável (CI suite total < 10min).
