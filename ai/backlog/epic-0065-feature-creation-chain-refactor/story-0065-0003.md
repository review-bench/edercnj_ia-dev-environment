**Medida:** Eliminar confusão sobre entrada pública; clarificar hierarquia de skills

## 4. Contrato de Dados

**Entrada:**
- `<SPEC-FILE-PATH>`: path para markdown RA9 v2 minimal (gerado por `x-feature-ideate` ou escrito manualmente)
- `--epic-id XXXX`: regex `^[0-9]{4}$`, único no diretório `ai/epics/`
- `[--no-jira]`: opcional, desabilita integração Jira

**Saída — layout v4 (D-R1):**
- Diretório `ai/epics/epic-XXXX-<slug>/` (slug derivado do título da spec)
  - `epic-XXXX.md` (RA9 9-section completo)
  - `story-XXXX-YYYY.md` × N (uma por história identificada na spec)
  - `IMPLEMENTATION-MAP.md` (DAG de dependências, fases, critical path — Mermaid)
- Worktree em `.claude/worktrees/feature-XXXX-<slug>/` (creator-owned, removível só após sucesso)
- Branch `docs/XXXX-<slug>` em origin com 1 commit consolidado
- PR `docs/XXXX-<slug>` → `epic/XXXX` com auto-merge habilitado (D-R6) e merged ao final do CI-watch
- `.claude/state/pr-watch-{PR}.json` (evidência Rule 45)

**NOTA — paths v4:** orchestrator usa `PathResolver.epicDir(String)` para resolver o diretório da epic; a compatibilidade v4→v3 é feita por probe do filesystem do layout disponível, não por `flowVersion` (que vive em `execution-state.json` para Rule 19 / auditoria, separado do `PathResolver`).
