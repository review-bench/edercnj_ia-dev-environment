## 1. Visão

Como **operador**, eu quero **um hook bloqueante PreToolUse que intercepta invocações dos orchestrators de implementação** (`x-story-implement`, `x-epic-implement`, `x-task-implement`, `x-epic-orchestrate`) **e barra a execução** quando `refinementVerdict.status != "approved"` para o alvo, garantindo que enforcement seja **runtime preventivo (Camada 0 — Rule 26)**, não apenas normativo.

## 2. Persona & Cenário

**Persona principal:** operador (dev/PO) prestes a implementar uma story ou um épico — ainda sem ter rodado o refinement.

**Cenário:** operador acidentalmente invoca `Skill(skill: "x-story-implement", args: "story-X")` antes de refinar. O hook detecta via leitura de `execution-state.json` (sem parsear markdown) e bloqueia com mensagem PT-BR clara + comando sugerido.

## 3. Entrega de Valor

- **Valor primário:** zero implementação acidental sobre story não-refinada — bloqueio antes do orquestrador iniciar.
- **Valor secundário:** Camada 0 (preventivo) é o ÚNICO ponto de defesa que pode parar o processo **antes** de o LLM começar a planejar — todas as outras camadas (1-3) detectam após o fato.
- **Métrica primária:** zero merges com `refinementVerdict.status != "approved"` (excluindo Rule 27 Exception 2 hotfix), auditado pela story-0006 em CI.
- **Métrica secundária:** latência do hook < 500ms p95 (medida no smoke + telemetria).

## 5. Contratos & Endpoints

- **Path do hook source-of-truth:** `java/src/main/resources/targets/claude/hooks/PreToolUse/enforce-refinement-gate.sh`.
- **Camada:** 0 (Rule 26 — preventivo, durante o turno do LLM).
- **Trigger event:** `PreToolUse` em `Skill` calls cujo `tool_input.skill` matches `^(x-story-implement|x-epic-implement|x-task-implement|x-epic-orchestrate)$`.
- **Exit codes:**
  - `0` — OK (refinement aprovado OU exception aplicada OU legacy fallback).
  - `33` (working-default — confirmar não-colisão em §6 task) — `REFINEMENT_REQUIRED`. Hook layer permite exit codes livres (Rule 26 só padroniza CI scripts 0-3).
- **Header padronizado:** seguir contrato Rule 26 §Camada 0 + EPIC-0063 (`enforce-preflight-gates.sh` é exemplar).
- **Bypass único:** `CLAUDE_RECOVERY_MODE=1` env var (consistente com Rule 27 — único bypass aceito; warning visível ao usar).
- **Registro em `settings.json`:** via `HooksAssembler` — entry no array `hooks.PreToolUse`.
- **Capability requirement:** header comment do .sh declara `# requires-capabilities: governance.refinement-gate` (lido por `audit-capability-coverage.sh` para hooks com convenção de comentário).

## 8. Decision Rationale

**Decisão D1:** PreToolUse hook centralizado, não validação inline em cada orquestrador.
**Motivo:** centralização — 4 orquestradores não duplicam lógica (drift garantido em 1-2 sprints se inline). Hook é Camada 0 (preventiva), única que bloqueia ANTES do orquestrador iniciar.
**Alternativa descartada:** validação inline no Phase 0 de cada orquestrador.
**Consequência:** hook precisa de `settings.json` + HooksAssembler. Migração de projetos existentes documentada no CHANGELOG.

**Decisão D2:** Exit code working-default `33`, mas verificação obrigatória de não-colisão (D-R7).
**Motivo:** Rule 26 padroniza exit codes 0-3 apenas para CI scripts; hooks são livres mas precisam não-colidir com códigos publicados de outras Rules.
**Alternativa descartada:** pinar 33 sem verificação (memory feedback contra pinning sequencial).
**Consequência:** primeira task da story é a verificação; mudança em cascata se colidir.

**Decisão D3:** Bypass único é `CLAUDE_RECOVERY_MODE=1` (consistente com EPIC-0063 / Rule 27 §Camada 0 contract).
**Motivo:** zero proliferação de variáveis de bypass. Rule 27 Forbidden item: "Introducing a new bypass environment variable without a Rule 27 amendment and a SemVer MINOR bump".
**Alternativa descartada:** flag dedicada `CLAUDE_SKIP_REFINEMENT_GATE=1`.
**Consequência:** alinhamento total com Rule 27 — sem nova entrada no catálogo de bypass vars.

**Decisão D4:** Mensagem em PT-BR.
**Motivo:** Rule 02 (Output Language do projeto cliente) define PT-BR — hooks geram output que é lido pelo operador.
**Consequência:** internacionalização do hook é fora de escopo; PT-BR fixo.
