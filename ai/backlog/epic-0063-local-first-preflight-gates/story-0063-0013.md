## 1. Contexto & Escopo

Como **Operator/LLM**, eu quero que `enforce-preflight-gates.sh` (story-0063-0004) intercepte **todos** os vetores de bypass conhecidos — não só `git push`, `gh pr create`, `Skill x-pr-create` e `git commit -n` —, garantindo que nenhum atalho de Bash permita escapar do gate local.

Story-0063-0004 cobre os entry-points externos primários. Esta história fecha os atalhos que o LLM ou operator pode usar para contornar a Camada 0 ainda na máquina local. Inventário completo de vetores derivado da análise pós-EPIC-0062 e da revisão da árvore de comandos `git`/`gh`/`mvn`:

**Bypass commits (pula pre-commit chain `x-git-commit`):**
- `git commit` direto sem flags (não invoca `x-git-commit` → pula format/lint/compile)
- `git commit --amend` em commits já pushed
- `git rebase --skip` durante conflito (descarta commits)
- `git rebase --continue` com index modificado fora dos hooks

**Bypass build/test:**
- `mvn -DskipTests`, `mvn install -DskipTests`, `mvn -DskipITs`
- `mvn -Dspotless.check.skip=true`, `mvn -Dcheckstyle.skip=true`
- `mvn -Dmaven.test.skip=true`
- `mvn -Pno-tests` (perfil custom)

**Bypass release:**
- `git tag -d <existing-release-tag>` + `git push --delete origin <tag>` (reverte release)
- `gh release delete <release>` (apaga release publicado)
- `mvn release:perform` direto (sem `x-release` orchestrator)
- `git push --force` / `--force-with-lease` em branches protegidas (`main`, `develop`, `epic/*`)

**Bypass PR/merge:**
- `gh pr merge --rebase --admin` (story-0063-0004 cobre `--admin`; aqui adicionamos `--rebase --admin` combinado)
- `gh pr close` em PR de story merged ainda no epic branch (revert encoberto)

A história estende `enforce-preflight-gates.sh` com matcher expandido. **Toda interceptação respeita RULE-004:** apenas `CLAUDE_RECOVERY_MODE=1` libera, com WARNING + evento `recovery_mode_used` registrando o vetor específico (`vector: "mvn-skipTests"`, etc) para análise periódica (story-0063-0017).

A interceptação é **categórica** (matcher por regex sobre `tool_name + command_string`). Cada categoria tem mensagem de erro identificando vetor + alternativa correta:

```
PREFLIGHT_BYPASS_BLOCKED [vector=mvn-skipTests]
  Command: mvn -DskipTests
  Reason: skipping tests bypasses Camada 0 quality gate
  Alternative: invoke /x-test-run for scoped test execution
  Override: set CLAUDE_RECOVERY_MODE=1 (audit-logged, <5% threshold)
```

### 1.2 Entrega de Valor

- **Valor Principal:** Inventário completo de bypass vectors fechado fisicamente — não há atalho local que escape de Camada 0.
- **Métrica de Sucesso:** AC do épico estendido — 0 commits em branches `feat/story-*` produzidos por `git commit` direto (medido via audit telemetry: cada commit tem evento de invocação `x-git-commit`); 0 builds com `-DskipTests` em CI/local sem `CLAUDE_RECOVERY_MODE`.
- **Impacto no Negócio:** Elimina classe inteira de "shortcut commands" do operator/LLM repertoire.

## 3. Contratos & Endpoints

### 3.1 Matchers v2 (regex) — extending story-0063-0004 §3.1

| Vetor | Categoria | Regex (em command_string) | Ação |
| :--- | :--- | :--- | :--- |
| `mvn-skipTests` | build | `mvn .*-DskipTests( |$)` | Bloquear exit 2 (BLOCKED) |
| `mvn-skipITs` | build | `mvn .*-DskipITs( |$)` | Bloquear exit 2 (BLOCKED) |
| `mvn-spotlessSkip` | build | `mvn .*-Dspotless\.check\.skip=true` | Bloquear exit 2 (BLOCKED) |
| `mvn-testSkip` | build | `mvn .*-Dmaven\.test\.skip=true` | Bloquear exit 2 (BLOCKED) |
| `mvn-noTestsProfile` | build | `mvn .*-Pno-tests( |$)` | Bloquear exit 2 (BLOCKED) |
| `git-commit-direct` | commit | `^git commit( |$)` (sem `--allow-empty`) AND não invocado por `x-git-commit` | Bloquear exit 2 (BLOCKED) |
| `git-amend-pushed` | commit | `^git commit --amend` AND HEAD commit já existe em origin | Bloquear exit 2 (BLOCKED) |
| `git-rebase-skip` | commit | `^git rebase --skip` | Bloquear exit 2 (BLOCKED) |
| `git-tag-delete` | release | `^git tag -d ` AND tag matches `v\d+\.\d+\.\d+` | Bloquear exit 2 (BLOCKED) |
| `git-push-delete-tag` | release | `^git push --delete origin v\d+\.\d+\.\d+` | Bloquear exit 2 (BLOCKED) |
| `gh-release-delete` | release | `^gh release delete ` | Bloquear exit 2 (BLOCKED) |
| `mvn-release-perform` | release | `^mvn release:perform` AND não invocado por `x-release` | Bloquear exit 2 (BLOCKED) |
| `git-push-force-protected` | release | `^git push (.*)?--force(-with-lease)? .*(main|develop|epic/)` | Bloquear exit 2 (BLOCKED) |
| `gh-pr-merge-rebase-admin` | merge | `^gh pr merge.*--rebase.*--admin` | Bloquear exit 2 (BLOCKED) |
| `gh-pr-close-merged` | merge | `^gh pr close ` AND PR é referenciado por commit em epic branch | Bloquear exit 2 (BLOCKED) — warn-mode na fase 1 de rollout |

> **Convenção única de exit code (alinhada com story-0063-0004):** o hook PreToolUse usa exclusivamente `0` (OK) ou `2` (BLOCKED) conforme contrato Claude Code. O `vector` específico bloqueado é surfaced em stderr como `PREFLIGHT_BYPASS_BLOCKED [vector=<name>]`, não via exit code distinto.

### 3.2 Detection de "invocado por x-git-commit/x-release"

Hook lê `events.ndjson` da story em curso e verifica se há evento `tool.call skill="x-git-commit"` (ou `x-release`) com timestamp ≤2s antes do `tool_name=Bash`. Match positivo → `git commit` é parte legítima da chain do skill → permite. Match negativo → bloqueia.

### 3.3 Recovery mode payload

Quando `CLAUDE_RECOVERY_MODE=1`, hook emite evento NDJSON:

```json
{
  "timestamp": "...",
  "event": "recovery_mode_used",
  "session_id": "...",
  "pid": ...,
  "vector": "mvn-skipTests",
  "command": "<comando truncado a 200 chars>",
  "story_id": "0063-0099",
  "epic_id": "0063"
}
```

## 8. Decision Rationale

**Decisão:** Detection de "chain legítima" via NDJSON de até 2s atrás (não whitelist por PID).
**Motivo:** PIDs não são previsíveis em multi-shell. NDJSON é fonte autoritária e o hook já lê por outras razões.
**Alternativa descartada:** Whitelist por PID/PPID. Rejeitado por instabilidade.
**Consequência:** Janela de 2s é configurável via env (`PREFLIGHT_CHAIN_WINDOW_S=2`). Default permissivo o suficiente para chains reais.

**Decisão:** Lista de vetores fechada e versionada em `docs/preflight-bypass-vectors.md`.
**Motivo:** Operadores precisam saber o que está bloqueado. Documento é o contrato; hook implementa.
**Alternativa descartada:** Lista somente em código. Rejeitado por opacidade para o operador.
**Consequência:** Adicionar vetor exige PR alterando ambos (doc + script). Aceito.

**Decisão:** `gh-pr-close-merged` em warn-mode na fase 1 e fail-mode na fase 2 (alinhado com RULE-010).
**Motivo:** Heurística pode ter falso positivo (PR fechado legitimamente). Warn permite calibrar antes de bloquear.
**Alternativa descartada:** Bloquear desde dia 1. Rejeitado por risco de UX hostil.
**Consequência:** story-0063-0016 (rollout WARN→FAIL) controla a transição.
