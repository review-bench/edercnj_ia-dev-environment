## 1. Contexto & Escopo

Como **Skill Author**, eu quero declarar **explicitamente** se cada `Skill(...)` / `Agent(...)` invocado dentro de uma SKILL.md é obrigatório, opcional ou condicional, e quero um audit que cruze SKILL.md ↔ telemetria NDJSON garantindo que cada chamada `[required]` tenha um evento `tool.call` correspondente na execução real da story.

A causa raiz do EPIC-0062 e o problema-âncora deste épico: hoje **não existe forma estática** de distinguir "skill pulou um passo" de "skill não precisava executar aquele passo". Rule 24 introduziu `--skip-*` flags em `## Recovery`, e Rule 25 introduziu `<!-- phase-no-gate -->`, mas ambos atuam no nível de phase. **No nível de invocação individual**, qualquer linha `Skill(skill: "x-arch-plan", ...)` pode ser silenciosamente ignorada pelo LLM sem violar regra explícita.

Esta história fecha essa classe completa de bypass introduzindo uma **gramática inline obrigatória** para todo `Skill(...)` / `Agent(subagent_type: "general-purpose", ...)` declarado em SKILL.md de orquestradores (Anexo B do EPIC-0055):

```markdown
Skill(skill: "x-arch-plan", model: "opus", args: "...")  [required]
Skill(skill: "x-threat-model", model: "sonnet", args: "...")  [conditional: scope ∈ {auth, network, persistence}]
Skill(skill: "x-spec-drift", model: "sonnet", args: "...")  [optional]
```

Três marcadores apenas:

- **`[required]`** — DEVE haver `tool.call` no NDJSON da story para esse `skill`. Ausência → audit fail.
- **`[optional]`** — pode ou não haver. Não audita.
- **`[conditional: <expr>]`** — auditado **se e somente se** `<expr>` é verdadeira. Expressões suportadas (whitelist): `scope ∈ {SIMPLE, STANDARD, COMPLEX}`, `scope ∈ {auth, network, persistence}`, `flag.<name>`, `not flag.<name>`. Qualquer expressão fora da whitelist → audit fail (`GRAMMAR_INVALID_EXPR`).

O épico introduz **Rule 28 — Tool-Call Grammar** (extensão de Rule 13) e o script `scripts/audit-tool-call-grammar.sh` rodando em CI. O audit faz duas passadas: estática (lint do SKILL.md — todo `Skill(...)` tem marker) e dinâmica (cruza com `events.ndjson` da story merged).

Marker é exigido para os **8 orquestradores Anexo B**. Skills folha (e.g., `x-code-format`) ficam fora do escopo desta story (futuro epic — `x-internal-*` herdam do parent). Baseline file `audits/tool-call-grammar-baseline.txt` grandfather skills pré-EPIC-0063.

## 3. Contratos & Endpoints

### 3.1 Marker grammar (BNF)

```
marker        ::= "[" kind (":" expr)? "]"
kind          ::= "required" | "optional" | "conditional"
expr          ::= predicate (" and " predicate)*
predicate     ::= scope_pred | flag_pred
scope_pred    ::= "scope ∈ {" identifier ("," identifier)* "}"
flag_pred     ::= ("not " | "") "flag." identifier
identifier    ::= [A-Z][A-Z0-9_]*
```

Exemplos válidos:
- `[required]`
- `[optional]`
- `[conditional: scope ∈ {auth, network}]`
- `[conditional: scope ∈ {COMPLEX} and flag.threat_model_required]`

Marker **DEVE** aparecer no fim da linha do `Skill(...)` ou na linha imediatamente seguinte (regex `^\s*\[(required|optional|conditional[^\]]*)\]\s*$`).

### 3.2 audit-tool-call-grammar.sh contract

| Campo | Tipo | M/O | Validações | Exemplo |
| :--- | :--- | :--- | :--- | :--- |
| `--mode` | enum `static\|dynamic\|both` | M | static = só lint SKILL.md; dynamic = cruza com NDJSON; both = ambos | `--mode=both` |
| `--story-id` | regex | O (M se mode=dynamic\|both) | strict | `--story-id=0063-0012` |
| `--skills-root` | path | O | default `java/src/main/resources/targets/claude/skills/` | — |
| `--baseline` | path | O | default `audits/tool-call-grammar-baseline.txt` | — |
| `--self-check` | flag | O | — | — |

### 3.3 Exit codes

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `OK` | Todas validações verdes |
| 1 | `GRAMMAR_MISSING_MARKER` | `Skill(...)` sem marker em SKILL.md de orquestrador (não-grandfathered) |
| 2 | `GRAMMAR_INVALID_EXPR` | marker conditional com expr fora da whitelist |
| 3 | `GRAMMAR_TELEMETRY_MISSING` | `[required]` declarado mas evento `tool.call skill=X` ausente do NDJSON da story |
| 4 | `GRAMMAR_BASELINE_CORRUPT` | baseline file malformado |
| 5 | `INVALID_ARGS` | argv malformado |

### 3.4 Static check algorithm

Para cada SKILL.md sob `--skills-root` que faça parte do Anexo B:

1. Extrair toda linha matching `Skill\(skill:\s*"x-[a-z-]+"` ou `Agent\(subagent_type:\s*"general-purpose"`.
2. Para cada match, ler até 2 linhas seguintes procurando marker.
3. Se marker ausente E SKILL.md não está no baseline → exit 1.
4. Se marker conditional, validar expr contra whitelist → exit 2 se inválida.

### 3.5 Dynamic check algorithm

Para a story-id passada:

1. Localizar `events.ndjson` via `PathResolver` (v3 = `plans/epic-XXXX/`, v4 = `ai/epics/epic-XXXX-*/`).
2. Extrair conjunto de skills com evento `tool.call` matching `storyId=story-XXXX-YYYY`.
3. Para cada SKILL.md no caminho de execução da story (orquestradores chamados): listar `Skill(...)` com `[required]` e validar presença em (2). Para `[conditional: <expr>]`, avaliar expr contra contexto da story (scope vem de `execution-state.json.storyClassification[storyId]`); se true, exigir presença.
4. Skills ausentes → exit 3.

### 3.6 Baseline (Grandfather List)

Format: `<skill-name> # <reason>` por linha. Skills no baseline são ignoradas pelo static check. **Imutável** após merge do EPIC-0063 (CI separado checa append-only).

## 8. Decision Rationale

**Decisão:** 3 markers fechados (`required`, `optional`, `conditional`) ao invés de gramática livre.
**Motivo:** Whitelist garante que audit script é determinístico. Gramática livre obrigaria parser AST e introduz ambiguidade.
**Alternativa descartada:** Marker livre `[<json>]`. Rejeitado por complexidade de parser e ausência de ganho expressivo.
**Consequência:** Casos exóticos (chamada que depende de runtime decision arbitrária) precisam virar `[optional]` + lógica explícita no body. Aceito.

**Decisão:** Whitelist fechada de predicates em `[conditional: ...]` ao invés de DSL aberta.
**Motivo:** Predicates abertos → audit precisa interpretar expressão arbitrária → vetor de injection + falsos negativos. Whitelist captura ~95% dos casos reais documentados nas SKILL.md atuais.
**Alternativa descartada:** Embedded JS/jq expr. Rejeitado por superfície de ataque.
**Consequência:** Skill author que precisa de predicate fora da whitelist deve abrir story para estendê-la (com revisão).

**Decisão:** Cross-check NDJSON usa `tool.call` events emitidos pelo PreToolUse telemetry hook existente (não inventa novo evento).
**Motivo:** Reuso de infra existente; evita drift entre dois sources-of-truth.
**Alternativa descartada:** Novo evento `skill.invocation`. Rejeitado por duplicação.
**Consequência:** Audit depende de telemetry hook estar registrado em settings.json — verificado por `--self-check`.
