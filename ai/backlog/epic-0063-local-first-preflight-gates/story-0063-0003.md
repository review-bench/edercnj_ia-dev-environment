## 1. Contexto & Escopo

Como **Auditor de Compliance**, eu quero re-introduzir `.claude/hooks/stage-telemetry.sh` como Stop hook (committando NDJSON ao final de cada turno) e estender `scripts/audit-execution-integrity.sh` com `--scope=telemetry` (validando eventos `tool.call x-review` e `x-review-pr` por story merged), garantindo que a telemetria seja prova primária de invocação real de skills.

A causa raiz documentada no SPEC §1.2: arquitetura confunde **prova** com **artefato**. LLM controla o que escreve em arquivos markdown/json; LLM NÃO controla quando hook escreve no NDJSON. Telemetria committed-via-hook é o lado "hard" do dual-evidence rule (RULE-003 do épico). Stub no markdown passa Camada 3 atual mas falharia o audit telemetry porque LLM não consegue forjar evento sem invocar a Skill.

Esta história tem 3 partes: (1) re-introduzir `stage-telemetry.sh` (originalmente em settings.json mas removido em commit anterior — visível em `git status: D .claude/hooks/stage-telemetry.sh`); (2) estender `audit-execution-integrity.sh` com flag `--scope=telemetry` que para cada story merged via gh API exige ≥1 evento `tool.call` com `skill="x-review"` matching `storyId`, ≥1 com `skill="x-review-pr"` matching, ≥1 com `skill="x-internal-story-verify"`; (3) checagem de **integridade do NDJSON** (campos obrigatórios `timestamp`, `event`, `session_id`, `pid`; timestamps monotônicos para detectar edição manual). Exit 1 com `EIE_TELEMETRY_EVIDENCE_MISSING` quando ausência detectada.

## 3. Contratos & Endpoints

### 3.1 stage-telemetry.sh contract

| Trigger | Action | Failure mode |
| :--- | :--- | :--- |
| Stop event | `flock`-protected `git add plans/epic-*/telemetry/events.ndjson` AND `ai/epics/*/telemetry/events.ndjson` | fail-OPEN (RULE-005) — log to stderr, exit 0 |

> **flock contention.** Worktrees paralelos podem invocar Stop quase simultaneamente. Hook usa `flock -n .claude/state/stage-telemetry.lock` (non-blocking) — se lock ocupado, hook log WARN e exit 0 (próxima sessão pega o NDJSON na sua próxima Stop). Ev-LOST events são preservados para o próximo turn de qualquer sessão.

### 3.2 audit-execution-integrity.sh --scope=telemetry contract

| Campo | Tipo | M/O | Validações |
| :--- | :--- | :--- | :--- |
| `--scope` | enum `full\|telemetry` | M | full = legacy behavior, telemetry = new mode |
| `--story-id` | regex | O | filter to single story |
| `--epic-id` | regex | O | filter to single epic |

### 3.3 Exit codes (extended)

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `OK` | Todos eventos presentes |
| 1 | `EIE_TELEMETRY_EVIDENCE_MISSING` | falta evento mandatório para alguma story merged |
| 1 | `EIE_NDJSON_INTEGRITY_VIOLATED` | timestamps não-monotônicos OR campos faltantes |
| 2 | `OPERATIONAL_ERROR` | jq, gh ausentes |
| 3 | `BASELINE_CORRUPT` | baseline malformado |

### 3.4 Required events per merged story

```json
{
  "event": "tool.call",
  "skill": "x-review",
  "storyId": "story-0063-0001",
  "timestamp": "2026-04-28T...",
  "session_id": "...",
  "pid": 12345
}
```

3 eventos obrigatórios: `skill ∈ {x-review, x-review-pr, x-internal-story-verify}`. Audit faz `jq 'select(.event=="tool.call" and .skill==X and .storyId==Y)' events.ndjson` para cada combinação.

### 3.5 NDJSON integrity checks

- Cada linha: `jq -e 'has("timestamp") and has("event") and has("session_id") and has("pid")'`
- Monotonicidade: parseia timestamps em ordem de aparição, asserta cada >= anterior
- Por sessão: agrupa por `session_id`, valida monotonicidade dentro do grupo

## 8. Decision Rationale

**Decisão:** Re-introduzir `stage-telemetry.sh` como Stop hook (originalmente removido em commit `D .claude/hooks/stage-telemetry.sh`).
**Motivo:** Sem o hook, NDJSON fica gitignored e LLM pode editar antes do commit. Hook garante NDJSON é committed turn-by-turn → temporal integrity.
**Alternativa descartada:** Manter NDJSON em volume read-only mounted. Rejeitado por incompatibilidade com worktrees e dev local.
**Consequência:** Histórico de git cresce (~5MB por epic). Mitigação: scrubber preserva privacidade; epic futuro pode tarball NDJSON antigo.

**Decisão:** Validação de monotonicidade de timestamps por session_id (não global).
**Motivo:** Sessões paralelas (worktrees) podem ter timestamps interleaved no mesmo arquivo. Monotonicidade global geraria false positives.
**Alternativa descartada:** Sortar todos eventos por timestamp na leitura. Rejeitado porque destruiria evidência de edição manual.
**Consequência:** Detecção de edição manual fica per-session. Edição que reordena entre sessões não é detectada — backlog futuro.
