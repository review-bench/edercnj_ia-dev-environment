## 1. Contexto & Escopo

**Chave Jira:** —

EPIC-0063 implementa a **Camada 0 — Local Pre-Flight** ao modelo de Execution Integrity (extensão à Rule 24). A causa raiz documentada no SPEC fonte: durante o EPIC-0062, 8 stories foram mergeadas com reviews stub (≤2 linhas, `Verdict: GO`), `verify-envelope.json` placeholder e `dependency-audit.md` vazio — todas passaram a Camada 3 (`audit-execution-integrity.sh`) porque o auditor valida **presença** de arquivo, não **conteúdo**. O problema só foi detectado no PR final (#751), que veio NO-GO com 3 findings Critical, exigindo retrabalho.

Este épico inverte o fluxo: PR deixa de ser "let's see if CI passes" e passa a ser "publicação de código integralmente validado localmente". A inversão tem 5 pilares: (1) `scripts/preflight.sh` que executa format + tests filtered + coverage + content audits + telemetry check antes de qualquer push; (2) PreToolUse hook `enforce-preflight-gates.sh` que intercepta `git push`, `gh pr create` e `Skill x-pr-create` chamando o preflight como gate físico; (3) reviews + verify deslocados para **Phase 2.5** (pré-PR) em `x-story-implement` e nova **Phase 4.5** epic-level review em `x-epic-implement`; (4) auditorias de conteúdo (`audit-review-content.sh`, `audit-verify-envelope.sh`) que rejeitam stubs por heurística sintática (≥50 linhas, ≥3 seções H2, ≥2 refs a arquivos do diff, decisão GO/NO-GO presente); (5) telemetria-como-prova: `stage-telemetry.sh` re-introduzido como Stop hook commitando o NDJSON, com novo `audit-execution-integrity.sh --scope=telemetry` exigindo eventos `tool.call x-review` e `tool.call x-review-pr` por story merged.

**Expansão v2 (10 stories adicionais — fechando "skill pula etapa declarada" como classe).** A v1 cobria os entrypoints externos (`git push`, `gh pr create`) e o conteúdo dos artefatos de review/verify, mas o problema central — *"como impedir que uma SKILL.md declare 12 sub-skills e o LLM execute só 4"* — só era endereçado por Rule 24 (normativa) e Rule 25 (phase gates). Faltava o gate **estático** sobre a invocação individual. A v2 adiciona: (6) **gramática inline** `[required]`/`[optional]`/`[conditional]` em cada `Skill(...)` / `Agent(...)` declarado em SKILL.md de orquestrador (Rule 28), com `audit-tool-call-grammar.sh` cruzando declaração estática ↔ NDJSON; (7) **wave dispatch audit** que valida fan-outs paralelos (Rule 13 Pattern 2 — N siblings devem produzir N eventos); (8) **content audit estendido aos 6 artefatos de Phase 1** (arch/plan/tests/tasks/security/compliance — não só review/envelope); (9) **PreToolUse hook v2** com 15 vetores de bypass adicionais (mvn skips, git commit direto, tag/release, force push em branches protegidas); (10) **rollout WARN→FAIL** com feature toggle explícito + ADR + readiness gate; (11) **recovery audit periódico** com SLO < 5%, dataset committed e dashboard renderizado; (12) **hooks `--self-check` contract** (extensão Rule 26) para detectar hook silenciosamente quebrado; (13) **NDJSON hash chain** (cada evento referencia hash do anterior) tornando edição manual detectável estaticamente; (14) **epic-review reconciliation** (findings críticos/high de stories filhas devem aparecer como `inherited`/`resolved`/`superseded`/`dropped` no review consolidado); (15) **`x-pr-fix` real-diff gate** (fix-loop só re-roda review se houve diff real on-target).

O escopo v2 INCLUI: 1 runner script (gates 1-12), 14 audit scripts/extensões, 1 PreToolUse hook (v1+v2 matchers), 1 Stop hook (NDJSON commit + chain), 5 hooks com `--self-check`, 1 auditor de hooks, modificações em `x-story-implement`, `x-epic-implement`, `x-pr-fix`, `x-pr-fix-epic`, `x-review`, `x-review-pr` SKILL.md, branch protection automation, catálogo de 11 skills bypassáveis, atualização de Rules 13/24/26/28 (nova) + CLAUDE.md, ADR-0016 (rollout), templates de review estendidos (finding-paths + reconciliation), markers nos 8 orquestradores Anexo B, e um teste E2E `Epic0063LocalFirstSmokeTest` com 15 cenários. EXCLUI: AI-based review quality scoring (mantido como tier-2 futuro), cross-epic gates, blindagem das 11 skills do catalog (são EPICs futuros baseados em story-0063-0009), workflow de hotfix branches, e replacement de CI (CI permanece como defesa em profundidade).

## 4. Materialização SOLID

| ID | Título | Descrição |
| :--- | :--- | :--- |
| **[RULE-001]** | Pre-Flight runner é gate único | `scripts/preflight.sh` é o único entry-point para validação local. Hooks PreToolUse o invocam; orchestrators o invocam; operators podem invocar manualmente. Reescritas paralelas da lógica em outros scripts são proibidas. |
| **[RULE-002]** | Content audit por heurística sintática | `audit-review-content.sh` aplica APENAS heurísticas sintáticas (linhas, seções H2/H3, refs a arquivos via grep). Não invoca LLM. Calibrado para SCOPE=SIMPLE permitir <50 linhas via marker `<!-- audit-exempt-content: <reason> -->`. |
| **[RULE-003]** | Telemetry-as-evidence é primária | Eventos `tool.call` no NDJSON são prova primária. Conteúdo do arquivo é secundário (anti-stub). Skill que produz arquivo MAS não emite telemetry → falha audit. Skill que emite telemetry MAS não produz arquivo → falha content audit. **Dual-evidence rule.** |
| **[RULE-004]** | `CLAUDE_RECOVERY_MODE=1` é único bypass | Toda outra var de ambiente (`CLAUDE_SKIP_AUDIT`, `CLAUDE_NO_ENFORCE`, etc) é IGNORADA pelo hook. `CLAUDE_RECOVERY_MODE=1` emite WARNING visível em stderr e permite o tool call. Uso é audit-logged em `events.ndjson` para análise periódica. |
| **[RULE-005]** | Hook fail-CLOSED para gates, fail-OPEN para telemetry | Gates de bloqueio (review, coverage, tests, format) DEVEM fail-CLOSED — hook quebrado bloqueia. Helpers de telemetria DEVEM fail-OPEN — quebra não bloqueia operações. Distinção é semântica de segurança vs continuidade. |
| **[RULE-006]** | Phase shift em x-story-implement preserva ordem temporal | Reviews + verify executam ANTES de `x-pr-create`. Ordem: Phase 2 (impl) → 2.5 (review) → 2.6 (verify) → 2.7 (preflight) → 2.8 (PR). Verificável via timestamps no NDJSON. |
| **[RULE-007]** | Epic-level review consolida findings de N stories | `x-epic-implement` Phase 4.5 invoca `x-review` em scope epic, consumindo todos os `review-story-*.md` e produzindo `review-epic-XXXX.md`. Bloqueia Phase 5 se NO-GO. |
| **[RULE-008]** | Branch protection é defesa-em-profundidade | `setup-branch-protection.sh --apply-strict` é segunda linha. develop exige `required_reviews=1`, `required_status_checks=all`, `required_linear_history=true`, `enforce_admins=true`. Camada 0 (local) é primeira linha. |
| **[RULE-009]** | Stage-telemetry preserva NDJSON commit-signed | Re-introduzido Stop hook `stage-telemetry.sh`. Cada turno encerra com `git add plans/epic-*/telemetry/events.ndjson`. NDJSON committed → não pode ser editado fora de turno → integridade temporal preservada. |
| **[RULE-010]** | Rollout em 2 fases (WARN → FAIL) | Primeiro release: hooks WARN-only para calibrar. Segundo release: FAIL-mode. Operators têm 1 release para ajustar workflow. CI alerta uso de `CLAUDE_RECOVERY_MODE=1` > 5% das stories. **Implementação na story-0063-0016**: feature toggle `CLAUDE_PREFLIGHT_PHASE` (env > file > default), `audit-rollout-readiness.sh` gating release, ADR-0016. |
| **[RULE-011]** | Tool-call grammar é inegociável em orquestradores | Todo `Skill(...)` / `Agent(subagent_type: "general-purpose", ...)` declarado em SKILL.md de orquestrador (Anexo B EPIC-0055) DEVE carregar marker inline `[required]` / `[optional]` / `[conditional: <expr>]`. Rule 28 (story-0063-0012) define BNF + whitelist de predicates. `audit-tool-call-grammar.sh --mode=both` cruza marker estático com NDJSON dinâmico — `[required]` ausente da telemetria de uma story merged falha audit. Skills folha (não-orquestradores) e legacy SKILL.md ficam fora via baseline (imutável). |
| **[RULE-012]** | Wave dispatch (Rule 13 Pattern 2) é auditável | Phases que dispacham N agents siblings em uma única mensagem (e.g., `x-review` com 8 specialists, `x-internal-story-build-plan` com 5 agents) DEVEM declarar `### Wave: <name>` listando os children. `audit-wave-dispatch.sh` valida `count(events.agent.start matching wave) == |children|` na janela do parent skill (delimitada por `phase.start` / `phase.end` de Rule 25). Story-0063-0014 implementa. |
| **[RULE-013]** | Dual-evidence aplicado a artefatos de planejamento | `audit-planning-content.sh` (story-0063-0015) estende as heurísticas anti-stub aos 6 artefatos de Phase 1 (`arch-`, `plan-`, `tests-`, `tasks-`, `security-`, `compliance-`) e cruza presença de cada um com evento `tool.call` da skill correspondente. SCOPE-aware (SIMPLE/STANDARD/COMPLEX adjusta thresholds). |
| **[RULE-014]** | Integridade temporal do NDJSON via hash chain | Cada evento gravado em `events.ndjson` carrega `seq` (monotônico) + `prev_hash` (SHA-256 do evento anterior). Genesis `0000...0000`. `audit-execution-integrity.sh --check-chain` recomputa e detecta edição manual ou reordenação. Story-0063-0019 implementa em `telemetry-emit.sh` (flock atomicidade) e estende auditor. Eventos pré-EPIC-0063 grandfathered via baseline. |
| **[RULE-015]** | Hooks têm `--self-check` obrigatório | Extensão de Rule 26 (story-0063-0018): cada hook em `.claude/hooks/*.sh` DEVE responder a `--self-check` validando dependências (jq, git, sha256sum), arquivos relacionados, e registro em `.claude/settings.json`. `verify-hooks-integrity.sh` itera registered hooks; falha se ≥1 não suporta self-check ou retorna ≠ 0. Hook silenciosamente quebrado deixa de ser bypass invisível. |
| **[RULE-016]** | Epic-review reconcilia findings de stories filhas | Toda `review-epic-XXXX.md` consolidando reviews de N stories DEVE conter seção `## Findings Reconciliation` com mapping per-story de findings críticos/high para um dos status `inherited` / `resolved` / `superseded` / `dropped`. `dropped` exige justificativa ≥30 chars. `audit-review-reconciliation.sh` (story-0063-0020) gateia Phase 4.5 do `x-epic-implement`. |
| **[RULE-017]** | Fix-loop exige diff real on-target | `x-pr-fix` / `x-pr-fix-epic` invocam `audit-pr-fix-diff.sh` (story-0063-0021) entre cada attempt e o re-review. HEAD inalterado → `FIX_NO_DIFF`. Diff trivial (whitespace/comments) com `--strict-trivial` → `FIX_TRIVIAL_DIFF`. Diff existe mas nenhum file de finding tocado → `FIX_OFF_TARGET`. Combina com `GATE_FIX_LOOP_EXCEEDED` (EPIC-0043) para fechar a classe "LLM finge fix". |

## 5. Quality Gates

### Global Definition of Ready (DoR)

- Story tem ID `story-0063-NNNN` e dependências declaradas (Blocked By / Blocks)
- Story tem ACs concretos com exit codes esperados (não "validates correctly")
- Story tem File Footprint (write/read/regen) preenchido per RULE-004 EPIC-0041
- Predecessor stories estão `Concluída` ou são paralelizáveis

### Global Definition of Done (DoD)

- **Cobertura:** ≥ 95% Line, ≥ 90% Branch (Rule 05 — absolute gate, próprio gate de auto-aplicação)
- **Testes Automatizados:** Cada script CLI tem teste shell em `src/test/shell/` ou Java equivalente. Cada hook tem teste de integração simulando o evento (Stop, PreToolUse).
- **Smoke Tests:** `Epic0063LocalFirstSmokeTest` GREEN cobrindo **15 cenários** (AC12 v1 + AC22 v2 expansion).
- **Relatório de Cobertura:** `target/site/jacoco/jacoco.csv` parseado por `audit-coverage-local.sh` (próprio script da story-0063-0007)
- **Documentação:** Rule 24 §Camada 0 + CLAUDE.md atualizados; `docs/audit-bypass-catalog.md` produzido.
- **Self-check obrigatório:** Cada novo `audit-*.sh` implementa `--self-check` (Rule 26 contract).
- **TDD Compliance:** Commits show test-first pattern (test precedes implementation). Explicit refactoring after green. Tests are incremental (TPP).
- **Double-Loop TDD:** Acceptance tests derived from Gherkin scenarios (outer loop). Unit tests guided by TPP (inner loop).

## 8. Decision Rationale

**Decisão:** Heurísticas sintáticas (linhas, seções, grep) ao invés de LLM-judge para detectar reviews stub.
**Motivo:** LLM-judge introduz custo + latência + dependência de modelo. Heurísticas pegam ~80% dos stubs (medido contra stubs do EPIC-0062). Calibração via marker permite exceções legítimas para SIMPLE scope.
**Alternativa descartada:** LLM-as-judge invocado via `x-review-content` skill. Rejeitado por custo (~$0.05 por story) e latência (~30s adicionais ao preflight).
**Consequência:** Stubs verbosos mas vazios podem passar — backlog futuro de iteração de heurísticas (refs concretas a arquivos do diff + densidade de termos técnicos).

**Decisão:** PreToolUse hook como gate físico ao invés de "convenção via SKILL.md".
**Motivo:** Rule 24 (Camadas 1-4) já demonstrou que normativa + audit pós-fato não é vinculante — operadores/LLM podem inlinear ou produzir stubs. Hook PreToolUse é o ÚNICO ponto onde o tool call pode ser bloqueado antes de executar.
**Alternativa descartada:** Audit pós-push com revert automático. Rejeitado por UX hostil (commit já feito, history poluído).
**Consequência:** Hooks são operationally crítical — bug em hook bloqueia todo workflow. Mitigação: testes robustos + `CLAUDE_RECOVERY_MODE=1` como escape hatch + rollout WARN-mode primeiro.

**Decisão:** Phase shift em `x-story-implement` colocando reviews ANTES do PR.
**Motivo:** Hoje reviews executam DEPOIS do PR aberto, descobrindo problemas em CI/post-PR — multiplica time-to-merge. Mover para pré-PR significa "PR é publicação de código já validado".
**Alternativa descartada:** Manter posição atual + audit pós-fato mais agressivo. Rejeitado porque não resolve a UX (operator descobre tarde) nem a causa raiz (artefato vs invocação real).
**Consequência:** `x-story-implement` SKILL.md fica mais longa (1100→1300 lines). Mitigação: extração para `x-internal-*` em epic futuro se ultrapassar 1500.

**Decisão:** Telemetry NDJSON committed como evidência primária (re-introdução de `stage-telemetry.sh`).
**Motivo:** LLM controla o que escreve em arquivos markdown/json mas NÃO controla quando hook escreve no NDJSON. Telemetria assinada por hook é prova mais forte que arquivo de evidência.
**Alternativa descartada:** Manter NDJSON gitignored. Rejeitado porque permite manipulação local pré-push (LLM poderia editar antes do commit).
**Consequência:** NDJSON cresce no histórico (estimativa ~5MB por epic). Mitigação: scrubber preserva privacidade; epic-de-arquivamento futuro pode mover NDJSON antigo para tarball.
