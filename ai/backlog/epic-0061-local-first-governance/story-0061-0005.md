## 1. Contexto & Escopo

Como **maintainer do gerador**, eu quero remover os 8 scripts `scripts/audit-*.sh` do raiz do gerador e deletar definitivamente o workflow `.github/workflows/audit.yml`, garantindo que (a) bash audits vivam apenas como templates em `targets/claude/scripts/{stack}/` (RULE-007), (b) CI do gerador roda apenas `ci.yml` (`mvn verify`), (c) Java auditors da Story 4 substituem completamente o gate detectivo do `audit.yml`.

A remoção é **definitiva** — sem `workflow_dispatch` legacy (decisão Q2 do operador). Antes do `git rm`, criar tag git `pre-local-first-lifecycle` apontando para o último commit pré-remoção, permitindo rollback em caso de regressão. Tag também serve como ponto de referência para `git log` futuro.

Esta story é o ponto de virada do épico: até aqui, o épico foi **additive** (novos templates, novas classes Java). A partir daqui, removemos código existente. Demanda Story 4 mergeada (Java auditors verdes em CI) como pré-requisito hard.

### 1.2 Entrega de Valor

- **Valor Principal:** CI do gerador encolhe ~38% em compute (~7min → ~4min runner-time por PR). Zero flakiness por shell deps.
- **Métrica de Sucesso:** `.github/workflows/audit.yml` ausente. `scripts/audit-*.sh` ausentes. CI do gerador verde com apenas `ci.yml`. Tag `pre-local-first-lifecycle` criada antes do apply.
- **Impacto no Negócio:** PRs do gerador mergeam mais rápido. Custo de runner do GitHub Actions reduzido. Logs únicos facilitam debug.

## 8. Decision Rationale

**Decisão:** Remover `audit.yml` definitivamente, sem `workflow_dispatch` legacy (decisão Q2 do operador).

**Motivo:** `workflow_dispatch` legacy seria carga de manutenção sem valor — manter um workflow "para o caso de" exigiria esforço contínuo para mantê-lo verde quando os bash templates evoluírem por stack. Java auditors no `mvn verify` são suficientes; tag git `pre-local-first-lifecycle` serve como rollback determinístico se necessário (recover via `git show pre-local-first-lifecycle:scripts/X.sh`).

**Alternativa descartada:** Manter `audit.yml` por 2 releases como deprecation window. Descartada conforme decisão do operador na conversa de planejamento (2026-04-27): "Pode remover definitivamente."

**Consequência:** Se uma regressão for descoberta no Java auditor pós-merge, recuperação demanda checkout da tag e re-criação manual do workflow. Risco mitigado por: (a) Wave A + Wave B do Story 4 + smoke equivalence test, (b) tag preservada para reference, (c) bash templates ainda existem em `targets/claude/scripts/java-maven/` como backup conceitual.
