# História: Migrar 4 skills de planejamento paralelo para named subagent dispatch

**ID:** story-0079-0002  
**Chave Jira:** N/A  
**Status:** Pendente

---

## 1. Visão

Como **mantainer das orchestrator skills de planejamento**, quero migrar `x-plan-story`, `x-refine-epic`, `x-refine-story` e `x-internal-build-story-plan` de `Agent(subagent_type: "general-purpose", prompt: "You are a Senior Architect...")` para `Agent(subagent_type: "architect", description: "<task-specific>", prompt: "<task-only>")`, para que a persona de cada papel seja carregada do arquivo canônico do agente — eliminando ~25 cópias inline duplicadas e garantindo o tier de modelo correto via Rule 23.

Esta story constitui a maior parte da migração de persona (25+ invocações em 4 arquivos SKILL.md). Após o merge, qualquer evolução de persona requer editar apenas o agent.md correspondente.

---

## 2. Persona & Cenário

**Persona:** Skill Maintainer editando x-plan-story após uma mudança na definição de papel do Architect  
**Cenário de uso:** Antes desta story, editar o papel do Architect exige encontrar e atualizar 4 skills diferentes. Após o merge, é um único arquivo `architect.md`.  
**Dor atual:** `x-plan-story` contém 7 blocos Agent() com `You are a Senior Architect` / `You are a Senior QA Engineer` etc. duplicados. Drift entre as 4 skills é inevitável.  
**Critério de sucesso pessoal:** "Não há `subagent_type: 'general-purpose'` com persona inline em nenhuma das 4 skills migradas"  
**Contexto técnico relevante:** O `prompt:` do subagent após a migração deve conter apenas a tarefa específica (o que o agente deve fazer), não mais o corpo da persona. O runtime do Claude Code injeta o body do agent.md automaticamente.

---

## 3. Entrega de Valor

- **Valor Principal:** ~25 cópias inline de persona eliminadas; 4 skills reduzidas em ~30-60 linhas cada
- **Métrica de Sucesso:** `grep -rn 'You are a Senior' src/.../skills/plan/` retorna 0 ocorrências nas 4 skills migradas
- **Impacto no Negócio:** Manutenção de persona O(1) em vez de O(N*skills); tier de modelo correto garantido por contrato

## 8. Decision Rationale

**Decisão:** O `prompt:` após migração contém apenas a tarefa específica — nenhum fragmento de persona  
**Motivo:** O Claude Code injeta o body do agent.md automaticamente quando `subagent_type` é um nome registrado; incluir fragmentos de persona no `prompt:` seria duplicação parcial — exatamente o problema que estamos resolvendo  
**Alternativa descartada:** Manter um "reforço de persona" mínimo no prompt (ex: "Lembre-se: você é um Architect") — rejeitado porque cria drift entre o agent.md e o prompt: de forma mais sutil  
**Consequência:** Se o agent.md for deletado ou renomeado, o dispatch falha explicitamente — isso é desejável (fail-fast) em vez de silencioso
