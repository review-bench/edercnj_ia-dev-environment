## 1. Visão

Como **operador legado**, quero `/x-template-migrate <epic-id>` que assiste migração de épico v1 para v2 com diff + perguntas por bloco técnico — para cada bloco "Packages / Contratos / SOLID / Observabilidade técnica" do v1, skill pergunta: "mover para `system.md`? virar ADR? descartar?". Migração não-perde-informação.

## 2. Entrega de Valor

- Migração v1→v2 sem perda de decisão técnica.
- **Métrica:** 100% dos épicos migrados preservam decisões em ADR ou `system.md` update; nenhum bloco técnico é silenciosamente descartado (auditável por log da skill).

## 3. Acceptance Criteria (Gherkin — 4 categorias mandatórias)

```gherkin
Cenario: Happy — migração interativa
  DADO ai/epics/epic-0050/epic-0050.md em formato v1
  QUANDO operador invoca /x-template-migrate epic-0050
  ENTÃO skill mostra diff entre v1 e v2 propostos
  E pergunta para cada bloco técnico (Packages, Contratos, SOLID): "mover para system.md? virar ADR? descartar?"
  E após confirmações, escreve epic-0050.md em v2
  E side-effects executados: ADR criada (se "virar ADR") + system.md atualizado (se "mover")

Cenario: Degenerate — épico já em v2
  DADO ai/epics/epic-0070-*/epic-0070.md já em v2
  QUANDO operador invoca /x-template-migrate epic-0070
  ENTÃO skill detecta v2 e termina com exit 0 + "epic já em v2; nada a fazer"

Cenario: Error — épico v1 com seção corrompida (parser falha)
  DADO ai/epics/epic-0050/epic-0050.md com seção mal-formada
  QUANDO operador invoca /x-template-migrate epic-0050
  ENTÃO skill aborta com PARSER_ERROR indicando linha/seção
  E NÃO escreve nada (atomicidade — falha mantém estado anterior)

Cenario: Boundary — modo dry-run
  DADO ai/epics/epic-0050/epic-0050.md em v1
  QUANDO operador invoca /x-template-migrate epic-0050 --dry-run
  ENTÃO skill mostra diff + perguntas SIMULADAS (resposta default "manter")
  E NÃO escreve epic-0050.md
  E NÃO cria ADR ou modifica system.md
```

## 6. Decision Rationale

**Decisão:** Skill **interativa** com defaults seguros para `--non-interactive`; não automática-sem-pergunta. **Motivo:** decisões "para onde vai esse bloco?" são caso-a-caso e teste manual mostrou que script bash auto-merge gera resultado ruim em ~40% dos casos. **Alternativa descartada:** script bash auto-merge sem perguntas. **Consequência:** migração é opt-in custosa (5-15min por épico em modo interativo); operador escolhe quais épicos vale migrar; baseline pré-rollout fica imune.
