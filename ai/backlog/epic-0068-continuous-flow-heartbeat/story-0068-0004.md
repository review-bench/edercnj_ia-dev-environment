## 1. Contexto & Escopo

Como **mantenedor de governança**, eu quero um teste E2E Java que exerça o hook `enforce-continuous-flow.sh` end-to-end em todos os cenários da matriz de decisão (story-0068-0002 §3.3), garantindo que regressions futuras sejam detectadas em CI antes de merge.

Adicionalmente, esta story adiciona o hook ao `docs/audit-gates-catalog.md` (Rule 26 catalog-before-add — mandatório), e atualiza CHANGELOG.md com entry MINOR.

A justificativa para Java test (e não apenas shell): o smoke test simula o cenário completo — cria um state file fixture, escreve um NDJSON fixture, invoca o hook bash, e valida exit code + stderr capture. Java oferece controle determinístico de fixtures e integração natural com o pipeline `mvn verify`.

## 3. Contratos & Endpoints

### 3.1 Test class structure

```java
class Epic0068ContinuousFlowSmokeTest {

  @Test void hook_emitsNudgeWhen_phaseOpenAndNonInteractive_andLastEventIsToolResult() { ... }

  @Test void hook_skipsWhen_modeIsInteractive() { ... }

  @Test void hook_skipsWhen_findingHighInLastNdjsonEvent() { ... }

  @Test void hook_skipsWhen_taskTrackingOpenTasksEmpty() { ... }

  @Test void hook_skipsWhen_currentBranchIsHotfix() { ... }

  @Test void hook_selfCheck_passesWhenJqAvailable() { ... }

  @Test void hook_selfCheck_failsWhenJqMissing() { ... }
}
```

Cada teste:
1. Cria diretório temp + popula com fixture state file + NDJSON.
2. `cd` para o temp (ou passa via env var).
3. Invoca `bash <hook_path>` com stdin JSON Stop event simulado.
4. Captura exit code + stderr.
5. Asserta exit code esperado + (se aplicável) stderr contém substring `CONTINUOUS_FLOW_INTERRUPT`.
