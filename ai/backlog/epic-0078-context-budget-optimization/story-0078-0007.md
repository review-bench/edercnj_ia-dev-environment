## 1. Contexto & Escopo

Como **Architect**, eu quero migrar o conteúdo extenso de `Rule 26 — Audit Gate Lifecycle` (decision tree, descrição completa de Camada 0 com tabela de characteristics, naming conventions table) para um KP `knowledge/governance/audit-gate-lifecycle.md`, preservando na Rule 26 reduzida (≤50 linhas) apenas a tabela das 5 camadas, naming convention, exit codes 0-3 e `--self-check` contract.

A `Rule 26` atual carrega ~180 linhas com Camada 0 expandida (Property/Value tables, hook contract template Bash, naming prefixes), decision matrix flowchart ASCII, naming conventions tables. Esse conteúdo é referência operacional para autores de novos audit scripts — consultado raramente, apenas em design-time. Migrar para KP economiza ~3.5k tokens always-loaded.

A `Rule 26` final mantém: tabela das 5 camadas (Camada 0-4), naming convention summary (3 linhas), tabela de exit codes 0-3, `--self-check` contract (1 parágrafo), Forbidden, link para o KP. O KP recebe decision-tree completo, Camada 0 details (Property/Value, hook contract template), naming prefixes table.

## 8. Decision Rationale

**Decisão:** Manter tabela de exit codes (0-3) na Rule 26 mesmo após slim, ao invés de mover para o KP.
**Motivo:** Exit codes são parte do contrato normativo — audits referenciam a rule por exit code (e.g., "exit 1 `FLOW_VERSION_VIOLATION`"). Mover quebraria leitura mecânica.
**Alternativa descartada:** Mover tudo para o KP, deixar Rule 26 com apenas link. Rejeitado: contrato precisa estar visível na rule.
**Consequência:** Rule 26 fica ~50 linhas (vs ~30 ideal). Trade-off aceitável: invariância do contrato sobre concisão extrema.
