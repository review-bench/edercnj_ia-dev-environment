## 1. Contexto & Escopo

Como **Architect (colaborador EPIC-0064)**, eu quero anotar `requires-capabilities` em todas as rules e ativar o pruning advisory no `CapabilityAwareComposer`, garantindo que projetos minimalistas (ex.: perfil Python sem Java) podem ter Rule 12 podada com warning, economizando até 8k tokens always-loaded em projetos sem Java.

EPIC-0064 introduziu o frontmatter v3.0 com `requires-capabilities` para skills, KPs e templates — mas rules ainda não foram migradas. Esta story preenche a lacuna: rules universais declaram `[]`; rules específicas de linguagem/domínio declaram capabilities reais (ex.: Rule 12 → `[language.java.*]`). Pruning é **advisory** (warn-only) por 1 release antes de virar hard-prune (RULE-005, mitigando Risco 5 de poda silenciosa).

### 1.1 Regras Transversais Aplicáveis

| ID | Título |
| :--- | :--- |

### 1.2 Entrega de Valor

- **Valor Principal:** Permite poda automática de rules irrelevantes ao stack do projeto, com salvaguarda de warning-only por 1 release.
- **Métrica de Sucesso:** Em smoke test sobre perfil Python hipotético, Rule 12 (slim) é marcada como pruned com warning visível; perfil Java mantém Rule 12 ativa.
- **Impacto no Negócio:** Projetos não-Java economizam ~8k tokens always-loaded; mantém integridade pedagógica (warning permite revisão manual).

## 8. Decision Rationale

**Decisão:** Pruning advisory (warn-only) por 1 release antes de hard-prune.
**Motivo:** Risco 5 do SPEC — poda silenciosa pode esconder rules importantes em perfis novos não totalmente declarados.
**Alternativa descartada:** Hard-prune imediato com flag `--no-prune` para opt-out. Rejeitado: viola RULE-006 (fail-open) e exige operadores conhecerem a flag de antemão.
**Consequência:** Story-0078-0014 entrega valor reduzido no release atual (apenas warnings); hard-prune efetivo só após 1 release de observação.

### 8.1 Hard-Prune Flip Criteria (Decision Cross-Reference)

**Decisão:** O flip advisory→hard-prune ocorre em **story-0078-0016**, simultaneamente à ativação de hard-fail do `audit-context-budget.sh`.

**Rationale:** Ambos os gates são "ponto de não-retorno" da governança de orçamento de contexto:
- `audit-context-budget.sh` advisory→hard-fail (story-0078-0016)
- `CapabilityAwareComposer` advisory→hard-prune (story-0078-0016)

Alinhar os dois numa única story dá ao operador um landmark único de governança ratchet — uma única release marca a transição "warning-only" → "blocking", reduzindo confusão sobre qual versão do gerador é estritamente enforced.

**Mecânica de ativação (em story-0078-0016):**
- Composer default `mode = "hard"` via env var `CLAUDE_PRUNE_MODE=hard` OU
- Flag de configuração permanente em `CapabilityCompositionAssembler` (preferência: flag de configuração — env var é override).

**Esta story (0078-0014):** apenas advisory mode. Envelope sempre carrega `mode: "advisory"`. Hard mode é exercido via tests de integração mas não é o default.
