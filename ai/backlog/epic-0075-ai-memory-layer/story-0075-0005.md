### 3.3 `audit-memory-coverage.sh` — contrato

```bash
audit-memory-coverage.sh [--self-check] [--strict]
```

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | OK | Todo épico em status `Concluída` tem `ai/memory/epic-XXXX-summary.md` correspondente |
| 1 | MEMORY_COVERAGE_VIOLATION | Pelo menos 1 épico Concluída sem summary (e não em baseline) |
| 2 | OPERATIONAL_ERROR | Prerequisites missing (jq, grep) |
| 3 | BASELINE_CORRUPT | `governance/baselines/memory-coverage-baseline.txt` malformado |

Algoritmo:
1. Lista todos `ai/epics/epic-*/epic-*.md` cuja primeira linha `Status:` é `Concluída`.
2. Para cada, computa `epic-XXXX` numérico → checa `ai/memory/epic-XXXX-summary.md`.
3. Lista de gaps ∩ baseline → exit 0; ∖ baseline → exit 1 com lista.

Self-check: verifica `jq`, `grep`, presence de `ai/memory/_index.yaml`.

### 3.4 Baseline imutabilidade

Após merge desta story, `memory-coverage-baseline.txt` é **append-only e imutável** — qualquer remoção/edit é caught por `audit-immutability.sh` (similar ao baseline da Rule 24). Apenas additions via PR review humano explícito.

### 3.5 Hotfix Exception 2 (Rule 27)

Hotfixes em `hotfix/*` que pulem `x-epic-implement` (single-commit fix) **não geram summary** automaticamente. Documentado: hotfixes não constituem épicos; ausência de summary é esperada. `audit-memory-coverage.sh` ignora épicos sem `ai/epics/epic-XXXX-*/epic-*.md` (fonte de verdade é o markdown do épico, não git history).

## 8. Decision Rationale

**Decisão:** posicionamento da invocação em Phase 5.4.5 (após reports commitados, antes do PR ser aberto).
**Motivo:** summary é evidência tão importante quanto verify-envelope/review/techlead-review; precisa estar **commitado** no branch `epic/XXXX` para ser caught pelo CI audit no PR. Se gerado pós-merge, perde-se a Camada 3.
**Alternativa descartada (1):** após o merge para `develop`. Rejeitado: falha em CI audit pré-merge — defeats the purpose.
**Alternativa descartada (2):** dentro do gate interativo (5.6). Rejeitado: gate é decisão humana; geração automática não deve depender disso.
**Consequência:** se summary falha, PR não é aberto — operador pode investigar antes de ter PR sujo no GitHub.

**Decisão:** `audit-memory-coverage.sh` separado de `audit-execution-integrity.sh`.
**Motivo:** SRP. Memory coverage é a story-0075-0005 entregando isoladamente; pode rodar independente.
**Alternativa descartada:** estender `audit-execution-integrity.sh`. Rejeitado: poluição de responsabilidades.

**Decisão:** baseline file imutável (append-only) após merge.
**Motivo:** segue convenção Rule 24/27 — grandfathered list é histórica, não retro-editável.
**Alternativa descartada:** baseline mutável. Rejeitado: drift inevitável.

**Decisão:** hotfix Exception 2 (Rule 27) NÃO requer summary.
**Motivo:** hotfix é fix pontual de produção, não épico estratégico. Forçar summary aqui é over-engineering.
**Alternativa descartada:** auto-gerar summary lite para hotfixes. Rejeitado: complexidade alta para benefício marginal; hotfix justification block na PR já cobre rationale.
