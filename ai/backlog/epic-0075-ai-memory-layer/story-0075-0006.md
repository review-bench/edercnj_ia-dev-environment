## 1. Contexto & Escopo

Como **mantenedor**, quero gerar retroativamente `ai/memory/epic-XXXX-summary.md` para os épicos históricos (range alvo: 0040–0068, ~28 épicos) em batch, alimentando o sistema com volume útil **desde o release 1**.

A story é **conteúdo-pesado** (28 entries) e **conhecimento-pesado** (épicos antigos têm formatos heterogêneos — alguns pré-EPIC-0070 v2 templates, sem `## Decisões Arquiteturais` estruturada). Por isso depende de `--allow-legacy-fallback` da story 0003 e exige spot-check humano.

A lista exata de épicos é determinada em Phase 0 (varredura de `ai/epics/*/epic-*.md` com `Status: Concluída`); 28 é a estimativa atual.

### 1.1 Regras Transversais Aplicáveis

| ID | Título |
| :--- | :--- |
| Rule 19 | Backward Compatibility — épicos legados (pre-v2) tratados via fallback flag |
| Rule 22 | Lifecycle Integrity — summaries gerados respeitam template Story 0002 |

### 1.2 Entrega de Valor

- **Valor Principal:** sistema utilizável imediatamente — `/x-memory-search` retorna resultados úteis logo após release.
- **Métrica de Sucesso:** ≥ 28 summaries gerados; spot-check em 5 amostras com qualidade ≥ "aceitável" (rubrica abaixo); `audit-memory-coverage.sh` exit 0.
- **Impacto no Negócio:** elimina período de "sistema vazio" pós-rollout.

## 3. Contratos & Schema

### 3.1 Helper script `retro-seed-memory.sh`

```bash
scripts/retro-seed-memory.sh [--from EPIC-XXXX] [--to EPIC-YYYY] [--dry-run] [--continue-on-error]
```

| Flag | Default | Descrição |
| :--- | :--- | :--- |
| `--from` | `EPIC-0040` | Lower bound inclusivo |
| `--to` | `EPIC-0068` | Upper bound inclusivo |
| `--dry-run` | false | Imprime quais épicos seriam processados sem invocar a skill |
| `--continue-on-error` | true | Default: continua o batch se 1 falhar (relatório no fim); `false` aborta no primeiro erro |

Algoritmo:
1. Glob `ai/epics/epic-*-*/epic-*.md` filtra range.
2. Para cada, invoca `/x-internal-epic-summary --epic-id EPIC-XXXX --allow-legacy-fallback`.
3. Coleta exit codes; relatório final: success / legacy-fallback / failure por épico.

### 3.2 Rubrica de qualidade (spot-check)

Em `ai/memory/_retro-seed-rubric.md`:

| Critério | Aceitável | Inaceitável |
| :--- | :--- | :--- |
| Why this epic existed | 2-5 linhas que explicam o problema | < 2 linhas, ou texto colado raw sem síntese |
| Decisions taken | ≥ 2 decisões com motivo | 0 decisões e sem placeholder claro |
| Patterns / antipatterns | bullet list (vazia OK se épico não introduziu nada) | array com strings raw extraídas sem id estruturado |
| Frontmatter | `tags`, `capabilities-affected`, `rules-affected` populados ou explicitamente vazios | campos missing |
| Cap 200 linhas | OK | violado (não deveria acontecer — skill 0003 abortaria) |
| Links | epic + ADRs presentes | links 404 ou apontando para `plans/` quando o épico está em `ai/epics/` |

Spot-check humano: amostragem de 5 épicos (1 dos primeiros, 1 mid-range, 1 dos últimos, 1 com fallback legacy disparado, 1 random). Critério de aceitação: 4 de 5 com nota "aceitável" ou superior.

### 3.3 Política para épicos não-aceitáveis

Quando spot-check identifica summary inaceitável: refinamento manual no PR da story (override do summary gerado). Refinamentos manuais documentados em comentário inline `<!-- manually-refined: <reason> -->` no topo do summary.

### 3.4 Out of scope

- Épicos < EPIC-0040: omitidos (sistema é Concluído de fato em EPIC-0034 mas formato pré-v2 e densidade baixa). Caso de uso para retro-seed ampliado: épico futuro.
- Épicos em status `Backlog`/`Em Andamento` mesmo dentro do range — apenas `Concluída` entram.

## 8. Decision Rationale

**Decisão:** range fixo 0040–0068 (Concluídos) na primeira release.
**Motivo:** densidade de decisões aumenta a partir de EPIC-0040 (templates v2 evoluindo); épicos < 0040 têm valor histórico baixo + alto custo de extração.
**Alternativa descartada:** seed completo desde EPIC-0001. Rejeitado: ROI negativo para os primeiros 39 épicos.
**Consequência:** se demanda surgir, épico futuro pode estender retro-seed (range parametrizável já suporta).

**Decisão:** refinamentos manuais marcados com `<!-- manually-refined -->`; **re-execução skipa o épico** (skill 0003 retorna novo exit 7 `MANUAL_REFINEMENT_PRESENT`).
**Motivo:** preservar trabalho humano de override é essencial — overwrite silenciosa destruiria valor.
**Alternativa descartada:** sobreescrever sempre. Rejeitado: hostil a operadores que investiram tempo refinando.
**Consequência:** este é um requisito adicional para a story 0003 (exit 7 + detecção de marker). Documentado como dependency forward.

**Decisão:** batch único com `--continue-on-error` (default).
**Motivo:** maximiza throughput; falhas individuais são raras e fáceis de re-rodar.
**Alternativa descartada:** abortar no primeiro erro. Rejeitado: 1 épico problemático bloqueia 27 outros.

**Decisão:** spot-check humano em 5 amostras (não revisão completa).
**Motivo:** revisão de 28 summaries levaria ~6h humano; 5 amostras cobrem qualidade do gerador, não de cada item.
**Alternativa descartada:** revisão de todos. Rejeitado: custo prohibitivo; auditorias futuras pegam drift.
