# Memory: EPIC-0075 — AI Memory Layer

## Why this epic existed

Every conversation with the LLM began with re-reading full epic markdown files (often 200–500 lines each) to reconstruct context about past decisions, alternatives rejected, and patterns introduced. For a project with 75+ epics, "what did we decide about X in EPIC-0054?" required either: (a) the user manually scanning dozens of files, (b) the LLM receiving all of them in context (blowing the window), or (c) the decision being silently forgotten and re-litigated. There was no indexed, retrievable memory layer — only flat markdown files that grew linearly with project history.

## Hypothesis tested

Introducing a structured memory layer — `ai/memory/epic-XXXX-summary.md` files with deterministic 16-field YAML frontmatter + 7 mandatory H2 sections, auto-generated by `x-internal-epic-summary` (haiku model, exit-7 skip for manual content) and indexed in `_index.yaml`, plus a retrieval skill `/x-memory-search` with 5 search modes — would reduce context retrieval from minutes (re-reading epics) to seconds and prevent re-litigation of past decisions. **Confirmed:** 27 summaries seeded covering 0040–0075; `audit-memory-coverage.sh` blocks merges of concluded epics without summaries; `RetroSeedSmokeIT` (6 rubric criteria) and `Epic0075MemoryLayerSmokeIT` (10 structural scenarios) green in CI.

## Decisions taken (with why)

1. **Haiku model for `x-internal-epic-summary`** (Rule 23) — summary generation is deterministic extraction, not deep reasoning; haiku is sufficient and ~5× cheaper than Opus; rationale: volume of summaries (75+ epics) makes cost a real constraint.
2. **Exit 7 `MANUAL_REFINEMENT_PRESENT`** — skip generation without error when a summary contains `<!-- manual-refinement -->` marker; rationale: allows human-authored summaries (like EPIC-0056 dogfood) to coexist without being overwritten; story-0075-0003 delivered.
3. **16-field YAML frontmatter** — `capabilities-affected`, `rules-affected`, `adrs-referenced`, `patterns-introduced`, `antipatterns-rejected`, `dependencies-of`, `dependencies-for` make summaries machine-queryable across multiple dimensions; rationale: `/x-memory-search` needs structured data to score and filter without reading full bodies.
4. **7 mandatory H2 sections** — Why existed, Hypothesis, Decisions, Alternatives rejected, Reusable patterns, Anti-patterns, Links; rationale: consistent structure enables cross-epic pattern mining; any section missing degrades retrieval quality.
5. **`audit-memory-coverage.sh` as Phase 5 gate** — concluding epics without a summary is a `MEMORY_COVERAGE_VIOLATION`; rationale: Rule 27 surface extension makes memory production a DoD item (not optional).
6. **Retro-seed `--from`/`--to` range** — `scripts/retro-seed-memory.sh` with 5 exit codes seeds the 0040–0068 range retroactively; rationale: memory layer must start with historical depth to be useful immediately.

## Alternatives rejected (with why)

- **Free-form wiki pages per epic** — rejected: undiscoverable without knowing the epic number; no structured frontmatter means `/x-memory-search` cannot score or filter; tends to become stale wiki.
- **Embedding summaries inside existing `epic-XXXX.md` files** — rejected: existing files are planning artifacts under `ai/epics/`; mixing retrieval metadata with planning content pollutes both; also breaks the immutability assumption of planning artifacts.
- **Relying purely on git history and CHANGELOG** — rejected: git log is linear and unindexed; CHANGELOG is release-scoped, not epic-scoped; neither supports tag/capability/pattern search.
- **Storing summaries in CLAUDE.md** — rejected: CLAUDE.md already exceeds 200 lines and compresses poorly; each epic adds ~50 lines; not searchable by the skill layer.

## Reusable patterns produced

- **`epic-summary-frontmatter-16-fields`**: 16-field YAML schema for memory summaries; enables machine-queryable retrieval across tags, capabilities, rules, patterns, ADRs, and dependencies.
- **`x-internal-epic-summary-haiku-deterministic`**: haiku-model internal skill; exit-7 skip for manual content; `--dry-run` for preview; `--allow-legacy-fallback` for pre-v4 layout.
- **`x-memory-search-5-modes`**: public skill with `--by-tag`, `--by-capability`, `--by-rule`, `--by-pattern`, `--by-epic` modes; `--include-archived` opt-in; `--format compact|full`; exit codes 0/1/2.
- **`audit-memory-coverage-phase-5-gate`**: `audit-memory-coverage.sh` Camada 2 script; blocks merges of `Concluída` epics without summaries; `--self-check` contract.
- **`retro-seed-rubric-c1-c6`**: 6 quality criteria in `ai/memory/_retro-seed-rubric.md`; C1 frontmatter, C2 sections, C3 line cap (≤200), C4 index consistency, C5 hypothesis non-empty, C6 superseded-by references exist.
- **`memory-index-bidirectional-consistency`**: `_index.yaml` and `.md` files must be in sync; `RetroSeedSmokeIT.validateIndexConsistency` + `validateIndexEntriesHaveFiles` enforce both directions.

## Anti-patterns observed

- **Re-reading full epic markdown for context** — loading entire planning-artifact files into context window to answer "what did we decide in EPIC-X?" wastes tokens and is slow; summaries reduce this to a single 200-line file.
- **Manual wiki pages undiscoverable** — arbitrary wiki pages without structured frontmatter and an index cannot be retrieved by ID, tag, or capability in O(1); undiscoverability compounds with project age.
- **Context window overflow from epic history** — including multiple full epic files in a single LLM turn to reconstruct history overflows the window; the summary layer keeps each entry under 200 lines with the critical decision data extracted.
