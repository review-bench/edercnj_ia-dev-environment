## 1. Visão

> **As a** Tech Lead reviewing a filed bug,
> **I need** a `/x-refine-bug <bug-id>` skill that runs multi-persona refinement (Developer + Tech Lead + QA) over the bug folder and writes a `## Refinement Verdict` block on `bug.md` with status `approved | needs-changes | rejected`,
> **so that** implementation cannot begin until the bug, its decomposition, and its regression-test plan have all been validated against the bug-specific refinement rubric.

The skill mirrors `/x-refine-story` (EPIC-0069) in shape but uses bug-specific dimensions:
reproduction-recipe completeness, regression-test plan presence, root-cause hypothesis
plausibility, scope correctness, and severity calibration. The verdict block is the
artifact that Camada 0 hook (story-0080-0005) reads to gate `x-implement-story` invocations
on bug stories.

## 2. Persona & Cenário de Uso

**Persona:** Tech Lead (5+ years, oversees 3-5 developers, refines 2-5 bugs per week
plus features). Consumes the bug folder and produces a verdict.

**Cenário:** Developer pings tech lead on the bug-scaffold PR. Tech lead checks out the
`bug/<id>-<slug>` branch, runs `/x-refine-bug bug-000001` from the project root. Skill
spawns 3 parallel sub-agents (Developer-perspective for reproduction completeness, Tech-Lead
for scope and severity calibration, QA for regression-test plan adequacy). Each sub-agent
returns a Pass/Fail+notes verdict. Skill aggregates: all-pass → `approved` written to
`bug.md` and to all child story files; any-fail → `needs-changes` with consolidated notes;
explicit reject → `rejected` (the bug is closed without implementation). Verdict is
committed to the bug branch with a `refine:` Conventional Commit.

## 3. Entrega de Valor

- **Valor Principal:** Mechanically gates bug implementation behind a multi-persona review with bug-specific dimensions.
- **Métrica de Sucesso:** 100% of bug stories that proceed to `x-implement-story` carry `refinementVerdict.status: approved` (KPI-4: 0 violations of `enforce-refinement-gate.sh` exit 33 on bug stories). Verdict completion time ≤ 4 min P75 (skill latency, excluding tech-lead reading time).
- **Impacto no Negócio:** Catches incomplete reproduction recipes and absent regression-test plans before implementation effort is spent. Expected secondary effect: rework rate on bug PRs drops because the regression-test design is validated up-front, not at PR review.

## 4. Critérios de Aceite

### AC-1 (happy-path) — Skill produces an `approved` verdict and propagates to story files

```gherkin
Given a bug folder `ai/bugs/bug-000001/` with complete bug.md (reproduction recipe filled), 2 stories, and IMPLEMENTATION-MAP.md
When the tech lead runs `/x-refine-bug bug-000001`
Then the skill spawns 3 parallel sub-agents (Developer, Tech-Lead, QA) using `Agent(subagent_type: "general-purpose", model: "sonnet", ...)` per Rule 13 Pattern 2
And each sub-agent returns a Pass verdict
And the skill writes `## Refinement Verdict` to `bug.md` with `status: approved`, `verdictHash: <sha256>`, `refinedBy: <author>`, `refinedAt: <ISO-8601>`
And the same `## Refinement Verdict` is written to every `story-NN-*.md` in the folder
And the skill commits with message `refine: bug-000001 approved (3/3 personas pass)`
```

### AC-2 (error/boundary) — Reproduction recipe missing → `needs-changes`

```gherkin
Given a bug folder where bug.md `## Reproduction Recipe` section is empty or contains only `TODO`
When the tech lead runs `/x-refine-bug bug-000001`
Then the Developer-perspective sub-agent returns Fail with reason `REPRO_RECIPE_MISSING`
And the skill writes `## Refinement Verdict` with `status: needs-changes`
And the verdict notes section contains the consolidated reasons from all failing personas
And no `## Refinement Verdict` block on child stories is set to `approved` (gate stays closed)
And the skill commits the needs-changes verdict (developer must address and re-invoke)
```

### AC-3 (performance/SLA) — Refinement completes in ≤ 4 min wall-clock

```gherkin
Given a typical bug folder (≤ 4 stories, bug.md ≤ 200 lines)
When `/x-refine-bug bug-000001` runs end-to-end with 3 parallel sub-agents
Then total wall-clock time from skill invocation to verdict commit is ≤ 4 min P75
And the parallelism is observable in telemetry: `subagent.start` events for the 3 personas overlap by ≥ 60% of the longest sub-agent duration
```

### AC-4 (security/auth) — Verdict cannot be forged by manual edit

```gherkin
Given a bug.md with a manually edited `## Refinement Verdict` block setting `status: approved` and a fabricated `verdictHash`
When `audit-bug-refinement-gate.sh` (story-0080-0005) runs in CI on the bug PR
Then the audit recomputes `sha256(bug.md content excluding the verdict block + sorted story file SHAs)` and compares to `verdictHash`
And the recomputed hash does not match the fabricated hash
And the audit fails with exit 1 `REFINEMENT_GATE_VIOLATION` and message `verdictHash mismatch — verdict was tampered`
```

### 5.2 Verdict block schema (written to bug.md and propagated to story files)

```yaml
status: approved | needs-changes | rejected
verdictHash: <sha256 hex string>
refinedBy: <git author email or "automation" for --auto-approve-trivial>
refinedAt: <ISO-8601 UTC timestamp>
personas:
  developer: { result: pass | fail, notes: "..." }
  techLead:  { result: pass | fail, notes: "..." }
  qa:        { result: pass | fail, notes: "..." }
notes: |
  Aggregated free-text consolidating any fail reasons.
```

### 5.3 Hash computation (canonical)

```text
content = bug.md without `## Refinement Verdict` section, normalized to LF newlines
storyShas = sorted list of sha256 of every story-NN-*.md file in the bug folder
verdictHash = sha256(content || "\n--STORIES--\n" || storyShas.join("\n"))
```

## 8. Decision Rationale

> **Decision:** Use 3 parallel sub-agents (Developer / Tech-Lead / QA personas) rather than 1 monolithic LLM call.
> **Why:** Mirrors the proven pattern of EPIC-0069 (`/x-refine-story` 4-persona). Parallel dispatch enables AC-3 ≤4min P75. Per-persona pass/fail makes the failure reason actionable (developer knows which dimension failed and how to fix).
> **Alternative rejected:** Single LLM call producing a structured verdict — slower (sequential reasoning) and harder to interpret which dimension caused a fail.
