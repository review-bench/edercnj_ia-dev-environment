## 1. Visão

> **As a** Developer who has filed a bug via `/x-create-bug`,
> **I need** the skill to automatically decompose the bug into 1-N implementation stories under `ai/bugs/bug-XXXXXX/story-NN.md`,
> **so that** I do not invent ad-hoc story shapes for bug fixes and the implementation flow plugs into the existing `x-implement-story` orchestrator without modification.

A bug typically maps to: (1) one regression-test story (failing test authored RED), (2) one
fix story (implementation that turns the test GREEN), and optionally (3) a refactor or
documentation story. This story extends `/x-create-bug` (or a sub-skill invoked by it) to
generate these stories deterministically based on the bug's `scope` and `severity` answers,
populating each with bug-specific contracts (reference to the failing reproduction).

## 2. Persona & Cenário de Uso

**Persona:** Developer (same persona as story-0080-0001) who has just completed bug
scaffolding and now wants to start implementation.

**Cenário:** After `/x-create-bug` produces `bug.md`, the skill chain invokes
`x-internal-decompose-bug` (or equivalent) which reads the bug.md and emits 2-3 story
files: `story-01-regression-test.md`, `story-02-fix.md`, optionally `story-03-doc.md`.
Each story carries a Decision Rationale linking back to the parent bug, frontmatter
`requires-capabilities: [governance.bug-lifecycle]`, and a `## Refinement Verdict`
section with status `pending`. The developer then proceeds to `/x-refine-bug` (story-0080-0004)
on the parent bug, which validates the story decomposition.

## 3. Entrega de Valor

- **Valor Principal:** Eliminate manual story-shape invention for bug fixes. Story decomposition becomes a deterministic function of `(scope, severity, has-regression-recipe)`.
- **Métrica de Sucesso:** 100% of bugs created via `/x-create-bug` have at least 1 regression-test story and 1 fix story before refinement begins. Measured by `audit-bug-classification.sh --check-decomposition` over `ai/bugs/bug-*/`.
- **Impacto no Negócio:** Enforces regression-first TDD at the planning layer (KPI-2 enabler) — the regression-test story is materialized BEFORE the fix story, so refinement and implementation order naturally produces the RED-before-GREEN commit ordering required by Rule R-080-5.

## 4. Critérios de Aceite

### AC-1 (happy-path) — Decomposition produces regression-test story before fix story

```gherkin
Given a `bug.md` with severity=high and scope=single-module exists at `ai/bugs/bug-000001/bug.md`
When the decomposition step runs (invoked by `/x-create-bug` or directly via `Skill(skill: "x-internal-decompose-bug", args: "bug-000001")`)
Then the file `ai/bugs/bug-000001/story-01-regression-test.md` is created with kind `[Test]` task as primary
And the file `ai/bugs/bug-000001/story-02-fix.md` is created with kind `[Dev]` task as primary
And `story-02-fix.md` declares `Blocked By: story-01-regression-test` in section 7
And both stories carry `requires-capabilities: [governance.bug-lifecycle]` in frontmatter
And both stories carry `## Refinement Verdict` with `status: pending`
```

### AC-2 (error/boundary) — Decomposition is idempotent and refuses to overwrite

```gherkin
Given `ai/bugs/bug-000001/story-01-regression-test.md` already exists from a prior decomposition run
When the decomposition step is re-invoked for the same bug
Then the skill detects the existing file and exits with code 0 (`OK_IDEMPOTENT`)
And the existing file is not modified (mtime unchanged)
And stdout contains "decomposition already present — skipping"
And no new commit is created
```

### AC-3 (performance/SLA) — Decomposition completes in ≤ 5 seconds

```gherkin
Given a `bug.md` of typical size (≤ 200 lines) at `ai/bugs/bug-000001/bug.md`
When the decomposition step runs end-to-end
Then total wall-clock time from invocation to last story file written is ≤ 5 seconds P95
And the timing is asserted by the smoke test using a millisecond clock
```

### AC-4 (security/auth) — Decomposition refuses path traversal in bug ID

```gherkin
Given an invocation with bug-id `../../../etc/bug-000001`
When the skill resolves the bug folder path
Then the skill rejects the input with exit code 2 `ARGS_INVALID`
And no file is read or written outside `ai/bugs/`
And the rejection happens before any file I/O
And the regex enforced is `^bug-[0-9]{6}$` (matches AC-4 of story-0080-0001)
```

## 5. Contratos

### 5.1 Files to be created

| Path                                                                                | Purpose                                                       |
| :---------------------------------------------------------------------------------- | :------------------------------------------------------------ |
| `src/main/resources/targets/claude/skills/core/internal/plan/x-internal-decompose-bug/SKILL.md` | Internal skill: bug.md → story files. Visibility internal.   |

### 5.2 Decomposition rules table

| `severity` | `scope`         | Stories produced                                                                |
| :--------- | :-------------- | :------------------------------------------------------------------------------ |
| any        | single-file     | `story-01-regression-test`, `story-02-fix`                                      |
| any        | single-module   | `story-01-regression-test`, `story-02-fix`                                      |
| high or critical | cross-module | `story-01-regression-test`, `story-02-fix`, `story-03-doc-update` |
| critical   | any             | `story-01-regression-test`, `story-02-fix`, `story-03-doc-update`, `story-04-rollback-plan` |

### 5.3 Internal skill input/output contract

Invocation:
```text
Skill(skill: "x-internal-decompose-bug", model: "haiku", args: "<bug-id>")
```

Output JSON schema (stdout, last line):
```json
{
  "bugId":        { "type": "string",  "pattern": "^bug-[0-9]{6}$",    "nullable": false },
  "storiesCreated": { "type": "array", "items": { "type": "string" },  "nullable": false },
  "storyCount":   { "type": "integer", "minimum": 2,                    "nullable": false },
  "elapsedMs":    { "type": "integer", "minimum": 0,                    "nullable": false },
  "status":       { "type": "enum",    "values": ["decomposed", "already-present"], "nullable": false }
}
```

Exit codes:
| Code | Name | Condition |
| :--- | :--- | :--- |
| 0 | `OK` | Stories created successfully |
| 0 | `OK_IDEMPOTENT` | Stories already present (status: already-present) |
| 2 | `ARGS_INVALID` | bug-id does not match `^bug-[0-9]{6}$` |
| 3 | `BUG_NOT_FOUND` | `ai/bugs/<bug-id>/bug.md` does not exist |
| 1 | `WRITE_ERROR` | File I/O failure during story creation |

## 8. Decision Rationale

> **Decision:** Decompose into 2-4 stories per bug deterministically by `(severity, scope)` rather than via LLM reasoning.
> **Why:** Determinism makes the audit `audit-bug-classification.sh --check-decomposition` mechanically verifiable; an LLM-driven decomposition would require fuzzy validation. The rules table is short and reviewable.
> **Alternative rejected:** Single all-in-one story per bug — would force regression-test and fix to share a refinement verdict and would not enforce R-080-5 commit ordering.
> **Alternative 2 rejected:** LLM-driven decomposition (ask the model to produce story files based on the bug description) — would produce varied story structures depending on model version and prompt wording, making `audit-bug-classification.sh --check-decomposition` impossible to implement deterministically. Rejected: determinism and testability over flexibility.
