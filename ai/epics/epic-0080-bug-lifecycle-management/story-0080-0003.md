## 1. Visão

> **As a** Developer who has decomposed a bug into stories,
> **I need** an automatically generated `ai/bugs/bug-XXXXXX/IMPLEMENTATION-MAP.md` with phase ordering, dependency matrix, critical path, and Mermaid graph,
> **so that** I and my tech lead can see at a glance the order in which stories must be implemented (regression-test → fix → doc) without re-reading every story file.

The map mirrors the `IMPLEMENTATION-MAP.md` of feature epics in shape but is much smaller
(typically 2-4 stories). It still serves the same purpose: a single visualization
artifact for refinement and PR review. Auto-generation eliminates the manual
maintenance burden — the map is regenerated from story files on every invocation,
preserving truth at the story-file level.

## 2. Persona & Cenário de Uso

**Persona:** Developer (creating) and Tech Lead (consuming during `/x-refine-bug`).

**Cenário:** After decomposition (story-0080-0002) writes story files, the chain invokes
`x-internal-map-bug` (or extends `x-internal-map-epic` to recognize bug folders) which
reads `bug.md` + all `story-NN-*.md` files and emits `IMPLEMENTATION-MAP.md` with: a
dependency matrix, a phase diagram in ASCII, a critical-path trace, a Mermaid graph,
and per-phase summary tables. Tech lead opens the map during refinement to verify
the regression-test story always precedes the fix story.

## 3. Entrega de Valor

- **Valor Principal:** Single visualization artifact for bug fix planning, auto-generated and always in sync with story files.
- **Métrica de Sucesso:** 100% of bugs created via `/x-create-bug` end with a valid `IMPLEMENTATION-MAP.md` whose Mermaid graph parses without error and whose phase ordering places regression-test stories before fix stories. Asserted by `audit-bug-classification.sh --check-map`.
- **Impacto no Negócio:** Reduces refinement review time. Tech lead does not have to read every story file to verify ordering; the map shows it.

## 4. Critérios de Aceite

### AC-1 (happy-path) — Map is generated with valid Mermaid and correct ordering

```gherkin
Given a bug folder `ai/bugs/bug-000001/` with `bug.md` and stories 01-regression-test, 02-fix, 03-doc-update
When `Skill(skill: "x-internal-map-bug", model: "haiku", args: "bug-000001")` is invoked
Then the file `ai/bugs/bug-000001/IMPLEMENTATION-MAP.md` is created
And the file contains a `## Mermaid Dependency Graph` section with a code fence whose body parses as valid Mermaid `graph TD` syntax
And the dependency matrix shows story-02-fix Blocked-By story-01-regression-test
And the critical path traces story-01 → story-02 → story-03 in that order
And the file contains exactly 6 mandatory sections per `_TEMPLATE-IMPLEMENTATION-MAP.md`
```

### AC-2 (error/boundary) — Map generation fails clearly when stories are inconsistent

```gherkin
Given a bug folder where story-02-fix declares Blocked-By story-99-nonexistent
When `x-internal-map-bug` runs
Then the skill exits with code 1 `MAP_INCONSISTENT_DEPS`
And stderr names the offending story file and the missing predecessor
And no `IMPLEMENTATION-MAP.md` file is written (atomic — write only on success)
```

### AC-3 (performance/SLA) — Map generation completes in ≤ 3 seconds

```gherkin
Given a bug folder with up to 5 stories (typical maximum per decomposition rules)
When `x-internal-map-bug` runs end-to-end
Then total wall-clock time is ≤ 3 seconds P95
And the timing is asserted by smoke test
```

### AC-4 (security/auth) — Map generation does not execute story file contents

```gherkin
Given a story file containing a Mermaid code fence with a `<script>alert(1)</script>` payload in a node label
When `x-internal-map-bug` aggregates story files into the map
Then the payload appears in the map verbatim as text inside a fenced block (not interpreted)
And no shell expansion, no template eval, and no Markdown rendering of the payload occurs at generation time
And the audit `audit-bug-classification.sh --check-map` does not flag the verbatim presence as a violation (text-only)
```

## 8. Decision Rationale

> **Decision:** Auto-generate `IMPLEMENTATION-MAP.md` from story files on every chain invocation rather than maintain it manually.
> **Why:** Manual maps drift from story Blocked-By edges within the first refinement cycle. Auto-generation makes the map a derived artifact (truth at story-file level) — the audit can simply re-run generation and diff against the committed map.
> **Alternative rejected:** Manual map maintained by the developer — incurs repeated edit cost and creates a second source of truth.
