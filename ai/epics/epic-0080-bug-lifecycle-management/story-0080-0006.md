## 1. Visão

> **As an** Engineer reviewing or merging a bug PR,
> **I need** the PR review chain (`x-review-pr`) and the merge skill (`x-merge-pr`) to recognize bug PRs (source branch matches `bug/*`) and to apply two bug-specific invariants — (a) a regression test was authored RED before the fix (commit ordering), (b) merge strategy is `--merge` not `--squash` (preserves the ordering for audit) —
> **so that** ≥95% of merged bug PRs ship with verifiable RED-before-GREEN evidence (KPI-2) and the regression-coverage audit can rerun deterministically post-merge.

This story is the final integration. With it, the full bug lifecycle is enforced from
creation (story-0080-0001) through merge. Without it, the regression-test discipline that
the template demands and the refinement validates is observable but not enforced at the
moment of merge.

## 2. Persona & Cenário de Uso

**Persona:** Engineer reviewing the bug PR (could be a peer, a tech lead, or the Copilot
review workflow). Also `x-review-pr` and `x-merge-pr` skills as automated agents.

**Cenário:** A developer pushes a bug PR from `bug/000001-checkout-total-promo` targeting
`develop`. `x-review-pr` runs as part of the PR pipeline. The 45-point checklist gains
3 bug-specific items (regression test exists in PR diff; commit ordering shows test:
before fix:; merge-base shows the test fails on develop). The Tech-Lead verdict GO/NO-GO
gate respects these items. After GO, `x-merge-pr` defaults to `--merge` strategy when the
source branch matches `bug/*`. Post-merge, `audit-bug-regression-coverage.sh` runs in
the develop-branch CI and asserts the same invariants on the unsquashed commit history.

## 3. Entrega de Valor

- **Valor Principal:** RED-before-GREEN TDD for bug fixes is mechanically enforced at PR review and merge.
- **Métrica de Sucesso:** KPI-2: ≥95% of merged bug PRs (sample window: rolling 20 PRs after this story merges) pass `audit-bug-regression-coverage.sh`. Below 95% triggers a Camada 2 ratchet WARN; below 90% blocks new bug PR merges until investigation. Audit latency ≤ 30s P95 per PR.
- **Impacto no Negócio:** Closes the last governance loop. Combined with stories 0080-0001 through 0080-0005, this story makes the entire bug lifecycle deterministic from filing through merge. Recurrence-rate metrics (a regression slipping back in) become trustworthy because every fix has a test.

## 4. Critérios de Aceite

### AC-1 (happy-path) — `x-review-pr` flags bug-specific checklist items

```gherkin
Given a PR from `bug/000001-checkout-total-promo` to `develop` with 2 commits — first `test: add regression for promo total`, then `fix: apply promo before tax`
When `x-review-pr` runs on the PR
Then the 45-point checklist now includes 3 bug-specific items: (a) PR diff contains at least one new test file under the project's test root, (b) git log shows a `test:` Conventional Commit type before any `fix:` commit, (c) `git checkout <merge-base> && <run-test-command>` on the new test FAILS (regression confirmed without the fix)
And all 3 bug-specific items pass for this PR
And the Tech-Lead verdict surface receives GO with the bug-specific items recorded under `## Bug Lifecycle Evidence` in the PR body
```

### AC-2 (error/boundary) — Squash-merge attempt on `bug/*` PR triggers WARN

```gherkin
Given a bug PR has GO verdict and the operator runs `Skill(skill: "x-merge-pr", args: "--strategy=squash --pr-number 123")`
When `x-merge-pr` resolves the source branch and detects pattern `bug/*`
Then the skill emits a WARN log line "bug PR detected; --merge strategy preserves commit ordering for R-080-5 audit; --squash will cause audit-bug-regression-coverage.sh to emit WARN post-merge"
And the skill proceeds with the operator's explicit `--strategy=squash` choice (does not override)
And the post-merge audit `audit-bug-regression-coverage.sh` runs on develop and emits WARN (not FAIL) per Risk-4 mitigation in epic-0080.md
And the audit report flags the squash and points to the operator override as the cause
```

### AC-3 (performance/SLA) — Audit completes in ≤ 30 seconds per PR

```gherkin
Given a bug PR with up to 20 commits and a test suite of typical size (≤ 5 minutes full run)
When `audit-bug-regression-coverage.sh --pr-number 123` runs in CI
Then the audit completes in ≤ 30 seconds P95 wall-clock (excluding the test-run portion which is timeout-bounded separately at 5 min)
And the audit checks: (a) test file presence in PR diff (no test execution required, ≤ 2s), (b) commit ordering via `gh pr view --json commits` (≤ 5s), (c) optional merge-base test re-run (deferred to a follow-on job, not counted in the 30s budget)
```

### AC-4 (security/auth) — Audit refuses to follow attacker-supplied test paths

```gherkin
Given a bug PR diff that adds a "test file" at `/etc/cron.d/malicious-test.sh`
When `audit-bug-regression-coverage.sh` enumerates added test files
Then the audit normalizes every path via `realpath --relative-to=<repo-root>` and rejects any path whose normalized form starts with `..` or is absolute
And only paths under the project's configured test roots (`src/test/`, `tests/`, etc., from project YAML) count toward the "regression test exists" check
And the audit logs a SECURITY WARN line for any rejected path
And exit code reflects the regression-coverage check, not the rejection (rejection is informational; check stays whatever it was based on legitimate paths)
```

| Item    | Check                                                                        | Source                            |

## 8. Decision Rationale

> **Decision:** Use `--merge` (not `--squash`) as default merge strategy for `bug/*` PRs to preserve unsquashed commit ordering for `audit-bug-regression-coverage.sh`.
> **Why:** Squash collapses the test:/fix: pair into one commit, destroying the ordering evidence that R-080-5 audits. Mitigation already documented in epic-0080.md Risk-4: WARN on operator override rather than hard-block, because some teams may prefer squash and accept the audit WARN cost.
> **Alternative rejected:** Always squash (matching existing develop convention) — would silently destroy the audit signal for KPI-2.
