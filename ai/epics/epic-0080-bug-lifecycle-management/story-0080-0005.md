# História: Refinement-gate enforcement extended to bug stories

**ID:** story-0080-0005
**Chave Jira:** TBD
**Status:** Pendente

> **Status Transitions (Rule 29 — refinement-gate):**
> valores permitidos `Pendente | Refinada | Planejada | Em Andamento | Concluída | Falha | Bloqueada`.

---

## 1. Visão

> **As an** Orchestrator (Camada 0 hook + Camada 2 CI audit),
> **I need** the existing `enforce-refinement-gate.sh` (Camada 0) and a new `audit-bug-refinement-gate.sh` (Camada 2) to recognize and enforce the verdict on bug-folder artifacts in addition to epic-folder artifacts,
> **so that** invoking `x-implement-story` against a bug story without an `approved` verdict on the parent bug.md is blocked at exit 33 `REFINEMENT_REQUIRED` (Camada 0) and at CI exit 1 `REFINEMENT_GATE_VIOLATION` (Camada 2).

This story is the integration point: the gate exists today for epic stories (Rule 29 +
EPIC-0069). Extending it to bug stories is the surface that turns the verdict from "a
file the tech lead writes" into "a hard gate before implementation." Without this story,
story-0080-0004 produces verdicts that nobody reads.

## 2. Persona & Cenário de Uso

**Persona:** SRE/Governance Engineer (3+ years, owns CI pipeline, responds to lifecycle gate alerts, reviews and approves bypass justifications). Maintains `enforce-refinement-gate.sh` and `audit-bug-refinement-gate.sh`. Does not file bugs; ensures the enforcement infrastructure is correct and observable.

**Cenário:** A developer attempts `x-implement-story` on `ai/bugs/bug-000001/story-02-fix.md`
before refinement. The Camada 0 PreToolUse hook `enforce-refinement-gate.sh` runs; it
discovers the parent bug folder, reads `bug.md` `## Refinement Verdict`, finds
`status: pending`, exits 33 `REFINEMENT_REQUIRED`. The skill invocation is blocked
before any implementation work begins.

## 3. Entrega de Valor

- **Valor Principal:** The verdict produced by `/x-refine-bug` is mechanically enforced. Bypassing refinement on a bug story is impossible without explicit recovery-mode escape.
- **Métrica de Sucesso:** KPI-4: 0 bug PRs merged where the parent bug.md verdict status is not `approved` at merge time. Measured by `audit-bug-refinement-gate.sh` running on every bug PR. Camada 0 hook latency overhead ≤ 200ms P95 (so it does not slow down legitimate refined-bug invocations).
- **Impacto no Negócio:** Closes the loop on the entire bug lifecycle. The refinement gate is what gives `/x-refine-bug` its teeth; without it the verdict is decorative.

## 4. Critérios de Aceite

### AC-1 (happy-path) — Approved bug story proceeds to implementation

```gherkin
Given a bug folder with bug.md `## Refinement Verdict` `status: approved` and a valid verdictHash
And the developer invokes `Skill(skill: "x-implement-story", args: "ai/bugs/bug-000001/story-02-fix.md")`
When the PreToolUse hook `enforce-refinement-gate.sh` runs
Then the hook detects the bug folder via the `find-refinement-target` dispatcher (returns `{kind: "bug", targetPath: "ai/bugs/bug-000001/", verdictFile: "ai/bugs/bug-000001/bug.md"}`)
And the hook reads `bug.md` `## Refinement Verdict` and finds `status: approved`
And the hook exits 0, allowing the `x-implement-story` invocation to proceed
And no output is emitted to stderr (approved path is silent)
```

### AC-1b (error/boundary) — Pending verdict blocks implementation

```gherkin
Given a bug folder with bug.md `## Refinement Verdict` `status: pending`
And the developer attempts to invoke `Skill(skill: "x-implement-story", args: "ai/bugs/bug-000001/story-02-fix.md")`
When the PreToolUse hook `enforce-refinement-gate.sh` runs
Then the hook detects `status: pending` and blocks with exit code 33 `REFINEMENT_REQUIRED`
And stderr contains a message pointing the user to `/x-refine-bug bug-000001`
```

### AC-2 (error/boundary) — Hook fail-open on dispatcher error blocks conservatively

```gherkin
Given the `find-refinement-target` dispatcher encounters an unexpected I/O error (e.g., permission denied on `ai/bugs/`)
When `enforce-refinement-gate.sh` runs against a story argument that begins with `ai/bugs/`
Then the hook treats the dispatcher error as a BLOCK (conservative fail-closed for bug paths): exits 33 `REFINEMENT_REQUIRED` with message "bug-target dispatcher failed: <reason>; blocking conservatively — resolve dispatcher error or use CLAUDE_RECOVERY_MODE=1"
And for story arguments that begin with `ai/epics/` (clearly an epic story), the hook degrades to the existing epic-only resolution path (Rule 19 fallback semantics) and does NOT block on dispatcher error
And the hook emits a WARN log line distinguishing the two cases: "bug-path block (conservative)" vs "epic-path fallback (legacy)"
And the hook does not crash with an unhandled error (all dispatcher errors are caught and logged)
```

### AC-3 (performance/SLA) — Hook latency stays within 200ms P95

```gherkin
Given a typical project with 50 bug folders and 100 epic folders
When `enforce-refinement-gate.sh` is invoked (PreToolUse) on any of the existing bug stories
Then the hook completes in ≤ 200ms P95 wall-clock
And the timing is measured by a benchmark harness that runs the hook 1000 times and asserts the P95
And the dispatcher implementation uses early-exit on path-prefix match (`ai/bugs/` vs `ai/epics/`) rather than scanning both trees
```

### AC-4 (security/auth) — CI audit detects forged verdict via verdictHash recomputation

```gherkin
Given a merged bug PR where bug.md was tampered to set `status: approved` with a fabricated `verdictHash`
When `audit-bug-refinement-gate.sh` runs in CI against the merged commit
Then the audit recomputes the canonical verdictHash per story-0080-0004 §5.3
And the recomputed hash does not match the fabricated hash
And the audit fails with exit 1 `REFINEMENT_GATE_VIOLATION` and message `verdictHash mismatch on bug-000001`
And the audit reports the recomputed and stored hashes side-by-side for forensic clarity
```

### AC-5 (security/auth) — Dispatcher rejects path traversal in story argument

```gherkin
Given an invocation where the story argument is `ai/bugs/../../etc/passwd`
When `enforce-refinement-gate.sh` passes the argument to `find-refinement-target.sh`
Then `find-refinement-target.sh` normalizes the path via `realpath --relative-to=<repo-root>` and rejects any path whose normalized form does not start with `ai/bugs/` or `ai/epics/`
And the dispatcher exits 2 `ARGS_INVALID` with message "path outside known prefixes: <normalized-path>"
And the hook treats exit 2 as a block (conservative) — exits 33 `REFINEMENT_REQUIRED` with the dispatcher error reason
And no file I/O occurs outside `ai/bugs/` or `ai/epics/` at any point
```

### 5.2 Dispatcher contract

```bash
# find-refinement-target.sh
# Input: $1 = story file path (e.g., ai/bugs/bug-000001/story-02-fix.md or ai/epics/epic-XXXX/story-YYYY.md)
# Output (stdout JSON): {"kind": "epic"|"bug", "targetPath": "<dir>", "verdictFile": "<path>"}
```

### 5.4 Recovery mode contract (Rule 19 Bypass 3)

When `CLAUDE_RECOVERY_MODE=1` is set:
- `enforce-refinement-gate.sh` emits `WARN [recovery-mode] refinement gate bypassed for <story-path>` to stderr and exits 0.
- The bypass event MUST be emitted to `ai/bugs/<bug-id>/telemetry/events.ndjson` as: `{"eventType":"refinement-gate-bypass","mode":"CLAUDE_RECOVERY_MODE","storyPath":"<path>","timestamp":"<ISO-8601>"}`.
- `audit-bug-refinement-gate.sh` (Camada 2) flags any merged bug PR whose NDJSON contains a `refinement-gate-bypass` event with WARN (not FAIL): the bypass is visible but not blocking post-merge.

## 8. Decision Rationale

> **Decision:** Use a small dispatcher `find-refinement-target` rather than inlining bug-vs-epic resolution into `enforce-refinement-gate.sh`.
> **Why:** Single source of truth for "where is the parent verdict for this story file?" — used by both the hook and the audit. Avoids two divergent implementations of the same prefix-match logic. Makes the bug extension testable in isolation without touching the proven epic gate code paths.
> **Alternative rejected:** Inline the resolution into both the hook and the audit. Rejected because Risk-3 (mitigation) explicitly calls out the regression risk on the existing epic gate; isolating the change to a small new file minimizes blast radius.
> **Alternative 2 rejected:** Inline the bug-vs-epic resolution directly into `enforce-refinement-gate.sh` and `audit-bug-refinement-gate.sh` as separate code paths in each file — avoids a new `find-refinement-target.sh` file. Rejected: two divergent implementations of the same prefix-match logic create a drift risk; the dispatcher is tested independently and sourced by both, guaranteeing a single canonical implementation (DRY).
