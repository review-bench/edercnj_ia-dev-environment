## 1. Visão

> **As a** Developer who just discovered a regression,
> **I need** a `/x-create-bug "<short-description>"` skill that scaffolds a complete `ai/bugs/bug-XXXXXX/` folder with a populated `bug.md` template,
> **so that** I can file a complete, refinement-ready bug report in ≤ 8 minutes instead of inventing folder layouts and section structures ad-hoc.

The current state forces developers to copy a feature epic folder, rename files, delete
inapplicable sections, and invent reproduction-step formatting. The result is inconsistent
bug reports that fail refinement on first review. This story delivers the deterministic
scaffold: a frontmatter v3.0 template, a `_TEMPLATE-BUG.md` with 9 RA9 sections plus
bug-specific subsections (reproduction recipe, observed vs. expected, root-cause hypothesis,
regression-test slot), and a skill that creates the folder, opens the `bug/<id>-<slug>`
branch, and produces a docs PR for refinement.

## 2. Persona & Cenário de Uso

**Persona:** Developer (mid-level engineer, ~6 months on team, has seen the regression in
local testing or in a customer report). Not a tech lead. Not yet familiar with refinement.

**Cenário:** Developer runs `/x-create-bug "checkout total wrong when promo applied"` from
the project root on `develop`. Skill prompts for severity (low/med/high/critical), scope
(single-file/single-module/cross-module), and observed-vs-expected behavior. Within 90
seconds skill produces: `ai/bugs/bug-000001/bug.md`, opens `bug/000001-checkout-total-promo`
branch from `develop`, commits the scaffold, opens a docs PR labeled `bug-scaffold` for
refinement review. Developer fills reproduction steps interactively (or post-creation in
the editor) and pushes a follow-up commit. Total time-to-refinement-ready ≤ 8 min P75.

## 3. Entrega de Valor

- **Valor Principal:** Deterministic, time-bounded bug-filing path replacing ad-hoc folder invention.
- **Métrica de Sucesso:** P75 time-to-file ≤ 8 min measured by telemetry (`tool.call` event for `/x-create-bug` start → `git push` of refinement-ready commit on `bug/*` branch). Baseline measurement committed to `governance/baselines/bug-creation-time.json` after first 10 invocations.
- **Impacto no Negócio:** Removes the activation-energy barrier to filing bugs. Expected secondary effect: bug-reporting volume rises (more defects captured rather than silently lost), which feeds KPI-3 (defect MTTR) measurement once enough data accumulates.

## 4. Critérios de Aceite

### AC-1 (happy-path) — Skill scaffolds a complete bug folder

```gherkin
Given the developer is on `develop` with a clean working tree
When the developer runs `/x-create-bug "checkout total wrong when promo applied"` and answers severity=high, scope=single-module
Then the skill creates `ai/bugs/bug-000001/bug.md` populated from `_TEMPLATE-BUG.md`
And the skill creates branch `bug/000001-checkout-total-promo` from `develop`
And the skill commits the scaffold with message `bug: scaffold bug-000001 — checkout total wrong when promo applied`
And the skill opens a docs PR labeled `bug-scaffold` targeting `develop`
And the file frontmatter contains `requires-capabilities: [governance.bug-lifecycle]` (Rule 28)
And the bug.md `## Refinement Verdict` section contains `status: pending`
```

### AC-2 (error/boundary) — Skill aborts cleanly on dirty working tree

```gherkin
Given the developer is on `develop` with uncommitted changes in the working tree
When the developer runs `/x-create-bug "<description>"`
Then the skill exits with code 15 (`WORKTREE_AMBIGUOUS`, per Rule 20 §Working-Tree Guard)
And no `ai/bugs/bug-XXXXXX/` directory is created
And no git branch is created
And stderr contains the message "working tree not clean — commit or stash before creating a bug"
```

### AC-3 (performance/SLA) — Scaffolding completes in ≤ 90 seconds wall-clock

```gherkin
Given the developer invokes `/x-create-bug "<short description>"` with answers piped via stdin (non-interactive mode)
When the skill runs end-to-end (folder creation, branch creation, commit, PR open)
Then the total wall-clock time from invocation to PR URL printed to stdout is ≤ 90 seconds P95
And the timing is measured by `time` wrapper in the smoke test and asserted as `< 90s`
```

### AC-4 (security/auth) — Skill rejects path-traversal in description

```gherkin
Given the developer runs `/x-create-bug "../../../etc/passwd injection"`
When the skill normalizes the description into a slug
Then the slug-generation step strips `../`, `/`, and other path separators (CWE-22)
And the resulting branch name matches regex `^bug/[0-9]{6}-[a-z0-9-]{1,40}$`
And the resulting folder name matches regex `^bug-[0-9]{6}$`
And the skill rejects descriptions whose normalized slug is empty (e.g., `///`) with exit code 2 `ARGS_INVALID`
```

### 5.2 Skill input schema

```yaml
name: x-create-bug
description: Scaffold a bug-XXXXXX folder with refinement-ready bug.md and bug/* branch.
model: sonnet
allowed-tools: [Bash, Skill, Write, Edit]
visibility: public
user-invocable: true
requires-capabilities: [governance.bug-lifecycle]
args:
  - name: description
    required: true
    type: string
    minLength: 8
    maxLength: 120
    validation: "must produce non-empty slug after path-separator stripping"
  - name: severity
    required: false
    type: enum
    values: [low, medium, high, critical]
    default: medium
  - name: scope
    required: false
    type: enum
    values: [single-file, single-module, cross-module]
    default: single-module
  - name: --non-interactive
    type: flag
    default: false
counter:
  mechanism: atomic-mkdir
  description: >
    Bug ID is generated by atomically attempting `mkdir ai/bugs/bug-XXXXXX/`
    (mkdir fails if the directory already exists, guaranteeing uniqueness under
    concurrent invocations). Counter value = `ls ai/bugs/ | grep -cE '^bug-[0-9]{6}$'` + 1,
    zero-padded to 6 digits. On collision (concurrent mkdir), retry up to 5 times
    with 50ms exponential backoff. After 5 retries → exit 1 `COUNTER_COLLISION`.
```

## 8. Decision Rationale

> **Decision:** Use folder pattern `ai/bugs/bug-XXXXXX/` with 6-digit zero-padded numeric ID instead of slugified-only directory names.
> **Why:** Numeric ID gives stable cross-reference (PR titles, audit logs, git messages) independent of description rewording. 6 digits supports 1M bugs without collision. Slug appears in branch name only.
> **Alternative rejected:** `ai/bugs/<slug>/` only — slug rewording during refinement would force directory rename and break links.
> **Alternative 2 rejected:** UUID-based ID (e.g., `bug-a3f2c1d7`) — guarantees global uniqueness without retry logic. Rejected: UUIDs in commit messages, PR titles, and audit logs are opaque and unsortable; sequential 6-digit IDs (`bug-000042`) are scannable in `ls` output and meaningful in `git log --oneline`.
