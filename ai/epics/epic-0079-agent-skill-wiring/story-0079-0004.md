# História: Reclassificar 11 checklist-agents como knowledge packs

**ID:** story-0079-0004  
**Chave Jira:** N/A  
**Status:** Pendente

---

## 1. Visão

Como **generator architect responsável pela estrutura de artefatos gerados**, quero mover os 11 arquivos em `agents/checklists/` (graphql-api, grpc-api, helm-devops, hipaa-security, iac-devops, mesh-devops, pci-dss-security, privacy-security, registry-devops, sox-security, websocket-api) para `knowledge/checklists/`, remover o frontmatter de agente deles, e atualizar o generator para emitir esses arquivos na localização correta, para que esses artefatos sejam tratados como o que são — dados de referência estática — e não como personas de orquestração.

---

## 2. Persona & Cenário

**Persona:** Generator Architect avaliando estrutura de artefatos gerados  
**Cenário de uso:** Um novo colaborador abre o repositório e vê `agents/checklists/hipaa-security.md`. Razoavelmente assume que existe uma persona "hipaa-security" despachável via `subagent_type: "hipaa-security"`. Não existe. É um checklist estático. Esta confusão deve ser eliminada.  
**Dor atual:** 11 arquivos em `agents/checklists/` têm frontmatter de agente mas nunca são despachados como agentes. Contribuem para 16/29 (55%) de taxa de agentes órfãos.  
**Critério de sucesso pessoal:** "O diretório `agents/checklists/` não existe mais; todos os 11 arquivos estão em `knowledge/checklists/` sem frontmatter de agente"  
**Contexto técnico relevante:** Esses arquivos são consumidos por skills via `Read` como dados de referência — não via `Agent(subagent_type: ...)`. A move não afeta o conteúdo, apenas a localização e a remoção do frontmatter de agente.

---

## 3. Entrega de Valor

- **Valor Principal:** Taxa de agentes órfãos reduzida de 55% para ≤29% (apenas os 5 órfãos reais restantes de story-0079-0006); estrutura de repositório corretamente comunicada
- **Métrica de Sucesso:** `ls src/.../agents/checklists/` retorna "No such file or directory"; `ls src/.../knowledge/checklists/` lista 11 arquivos
- **Impacto no Negócio:** Elimina sinal falso para novos colaboradores; estrutura de diretório corretamente comunica intenção arquitetural

## 8. Decision Rationale

**Decisão:** Remover frontmatter de agente dos checklists movidos (não apenas mover os arquivos)  
**Motivo:** Manter frontmatter de agente em `knowledge/` criaria inconsistência — o schema de KP e o schema de agente são diferentes; um KP não deve ter `name:` de agente  
**Alternativa descartada:** Manter frontmatter de agente nos checklists mas mover para `knowledge/` — criaria confusão entre KP e agente no mesmo diretório  
**Consequência:** Qualquer skill que consumia os checklists via `Read` não é afetada — apenas o caminho muda; skills que tentariam fazer `Agent(subagent_type: "hipaa-security")` receberão dispatch error (comportamento correto — nunca deveriam ter feito isso)
