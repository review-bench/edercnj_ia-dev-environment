**ID:** story-0079-0007  
**Chave Jira:** N/A  
**Status:** Pendente

---

## 1. Visão

Como **documentation maintainer responsável pela integridade das regras de governança**, quero atualizar Rule 13 (Skill Invocation Protocol) para documentar o Pattern 2 Named-Subagent como variante oficial de SUBAGENT-GENERAL — com a forma canônica `Agent(subagent_type: "<agent-name>", description: "...", prompt: "...")`, as implicações de telemetria (campo `role` passa a ser o `name` do agente registrado), e o link para o ADR desta feature — para que futuros maintainers entendam quando usar dispatch nomeado vs general-purpose e como o telemetry tracking muda.

---

## 2. Persona & Cenário

**Persona:** Documentation Maintainer adicionando uma nova skill com dispatch de subagente  
**Cenário de uso:** O maintainer lê Rule 13 para entender como despachar um subagente especializado. Antes desta story, o padrão documentado é apenas `subagent_type: "general-purpose"`. Após o merge, Rule 13 documenta explicitamente `subagent_type: "<agent-name>"` como Pattern 2b, com exemplos e implicações de telemetria.  
**Dor atual:** Rule 13 documenta apenas SUBAGENT-GENERAL (general-purpose). Named dispatch não tem documentação normativa — os maintainers que migrarmos em stories anteriores o fizeram sem guia formal.  
**Critério de sucesso pessoal:** "Posso ler Rule 13 e entender exatamente quando usar named dispatch vs general-purpose, sem precisar consultar histórico de PRs"  
**Contexto técnico relevante:** Rule 13 é carregada em TODAS as conversas (listada em CLAUDE.md). A atualização afeta imediatamente como o LLM gera novas skills — deve ser precisa e não ambígua.

## 8. Decision Rationale

**Decisão:** Adicionar Pattern 2b como sub-padrão de Pattern 2 (não como Pattern 4 novo)  
**Motivo:** Named dispatch é variante de SUBAGENT-GENERAL — mesma forma de tool call, diferença apenas no valor de `subagent_type`; criar Pattern 4 seria numeração excessiva  
**Alternativa descartada:** Criar "Pattern 4 — SUBAGENT-NAMED" como padrão numerado separado — rejeitado porque confunde hierarquia dos padrões e obriga atualização de Rule 28 (que referencia Pattern 2 por número)  
**Consequência:** Rule 13 fica ligeiramente mais longa mas mantém a hierarquia Pattern 1/2/3 existente intacta; "Pattern 2b" é a convenção de sub-padrão
