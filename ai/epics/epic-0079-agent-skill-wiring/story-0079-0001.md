# História: Formalizar frontmatter de agentes e JSON Schema para todos os agentes core/conditional/developers

**ID:** story-0079-0001  
**Chave Jira:** N/A  
**Status:** Pendente

---

## 1. Visão

Como **arquiteto responsável pelo agent registry**, quero que todos os 17 arquivos de agente sob `agents/core/`, `agents/conditional/` e `agents/developers/` carreguem frontmatter canônico completo (`name`, `description`, `tools`, `model`, `requires-capabilities`), e que um JSON Schema valide esse contrato em CI, para que o runtime do Claude Code possa registrar e despachar agentes por nome — eliminando a necessidade de duplicar personas inline em skills.

Esta story é a fundação do EPIC-0079: sem frontmatter correto, nenhum named subagent dispatch funciona. O conjunto `checklists/` (11 arquivos) está fora de escopo — eles serão reclassificados como knowledge packs na story-0079-0004.

---

## 2. Persona & Cenário

**Persona:** Architect / CI Maintainer configurando o agent registry  
**Cenário de uso:** Após o merge desta story, qualquer skill pode chamar `Agent(subagent_type: "architect", ...)` e o Claude Code carregará a persona do arquivo `architect.md` registrado — com o modelo correto e o toolset correto.  
**Dor atual:** Os agentes existentes têm apenas `name` e `requires-capabilities` no frontmatter. Faltam `description` (necessário para auto-delegation), `tools` (whitelist de tools permitidas), e `model` (tier Rule 23). Sem esses campos, o runtime ignora os arquivos.  
**Critério de sucesso pessoal:** "Posso chamar `audit-agent-frontmatter.sh --self-check` e ele reporta 17/17 agentes com todos os campos obrigatórios preenchidos"  
**Contexto técnico relevante:** O schema de frontmatter canônico do Claude Code para agentes usa os campos `name`, `description`, `tools` (list), e opcionalmente `model`. O campo `requires-capabilities` é adição do EPIC-0064 (Rule 28).

---

## 3. Entrega de Valor

- **Valor Principal:** 17 agentes operacionais como entidades despacháveis pelo runtime; zero arquivos de agente inoperantes
- **Métrica de Sucesso:** `audit-agent-frontmatter.sh --strict` exit 0 com 17/17 agentes validados contra `agent-frontmatter-1.0.json`
- **Impacto no Negócio:** Habilita named subagent dispatch em stories subsequentes (0002, 0003); elimina o bloqueador técnico para a migração completa de personas

## 8. Decision Rationale

**Decisão:** `additionalProperties: true` no JSON Schema — campos extras são tolerados  
**Motivo:** Rule 28 §Permitted explicitamente permite campos extra em frontmatter para extensibilidade; rejeitar campos extra causaria breaking changes em futuras extensões  
**Alternativa descartada:** `additionalProperties: false` — forçaria validação estrita mas quebraria agentes com campos legítimos não especificados no schema v1.0  
**Consequência:** O schema não é um contrato fechado — campos não listados são aceitos silenciosamente; isso é intencional e documentado
