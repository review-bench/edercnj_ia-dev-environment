# História: Adicionar audit-agent-skill-wiring.sh Camada-2 gate com baseline e integração pre-commit

**ID:** story-0079-0005  
**Chave Jira:** N/A  
**Status:** Pendente

---

## 1. Visão

Como **CI Maintainer responsável pela integridade do agent registry**, quero um script `scripts/audit-agent-skill-wiring.sh` (Rule 26 Camada 2) que detecta skills sob escopo declarado que usam `Agent(subagent_type: "general-purpose", ...)` com `prompt:` contendo "You are a \<Senior|Specialist|Principal\>" — heurística para personas inline que deveriam ser agentes nomeados — para que regressões sejam bloqueadas automaticamente em CI antes de atingirem `develop`.

O script opera com um baseline file (`audits/agent-skill-wiring-baseline.txt`) que grandfathering exceções aceitáveis no dia do merge; novas violações falhm CI.

---

## 2. Persona & Cenário

**Persona:** CI Maintainer revisando um PR de nova skill  
**Cenário de uso:** Um desenvolvedor adiciona uma nova skill com `Agent(subagent_type: "general-purpose", prompt: "You are a Senior DevOps Engineer...")`. Antes desta story, o PR passa sem detecção. Após o merge, o CI bloqueia com `INLINE_PERSONA_VIOLATION` e o desenvolvedor é direcionado a usar `subagent_type: "devops-engineer"`.  
**Dor atual:** Zero detecção automática de regressões de persona inline. O problema só é detectado em code review manual — se detectado.  
**Critério de sucesso pessoal:** "Nenhum PR com `You are a Senior \*` inline em blocos Agent() chega a `develop` sem ser detectado"  
**Contexto técnico relevante:** A heurística deve ser suficientemente específica para evitar false-positives em prosa legítima (ex: documentação que menciona "You are a Senior..." em exemplos). O baseline file mitiga o risco de false-positives no período de transição.

---

## 3. Entrega de Valor

- **Valor Principal:** Gate preventivo de regressão — inline personas nunca voltam silenciosamente após a migração do EPIC-0079
- **Métrica de Sucesso:** `audit-agent-skill-wiring.sh --strict` exit 0 com zero baseline entries no merge do EPIC-0079
- **Impacto no Negócio:** Custo de token correto garantido por contrato; persona governance enforced automaticamente em CI

## 5. Contratos

### 5.1 CLI Contract do audit script

```bash
# Self-check
scripts/audit-agent-skill-wiring.sh --self-check

# Scan com strict mode
scripts/audit-agent-skill-wiring.sh --skills-root src/.../skills/ --strict [--baseline audits/agent-skill-wiring-baseline.txt]

# Warn mode (deprecation window)
scripts/audit-agent-skill-wiring.sh --skills-root src/.../skills/ --warn
```

### 5.2 Exit Codes (Rule 26 §Standardized)

| Exit | Named Code | Condição |
| :--- | :--- | :--- |
| 0 | OK | Zero violações fora do baseline |
| 1 | INLINE_PERSONA_VIOLATION | Skill com persona inline detectada fora do baseline |
| 2 | OPERATIONAL_ERROR | grep ausente, baseline corrompido, args inválidos |
| 3 | BASELINE_CORRUPT | baseline file malformado |

### 5.3 Heurística de detecção

```
Pattern: grep -E 'subagent_type: "general-purpose"' SKILL.md
Followed by: grep -E '"You are a (Senior|Specialist|Principal)' within next 10 lines
```

Casos que devem ser grandfathered no baseline inicial:
- `x-troubleshoot-operations` (dispatch sem persona — roleless, legítimo)
- Qualquer skill de utility que use `general-purpose` sem persona

## 8. Decision Rationale

**Decisão:** Baseline file permite grandfathering no dia do merge, mas é append-only após esse ponto  
**Motivo:** A janela de depreciação (Rule 19) permite exceções transitórias; o baseline file é o mecanismo canônico do projeto para isso (padrão estabelecido em tool-call-grammar-baseline.txt, task-hierarchy-baseline.txt etc.)  
**Alternativa descartada:** Zero tolerância desde o início (baseline vazio imutável) — rejeitado porque pode haver utilities legítimos usando `general-purpose` sem persona que precisam de grandfathering inicial  
**Consequência:** Uma vez que o baseline inicial é fechado no merge do EPIC-0079, nenhuma nova entrada é permitida — novas violações devem ser corrigidas, não grandfathered
