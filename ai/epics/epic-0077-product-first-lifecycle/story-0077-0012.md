# História: Skill x-promote-ideation (x-feature-ideate output → persistent)

**ID:** story-0077-0012
**Chave Jira:** —
**Status:** Pendente

## 1. Contexto & Escopo

Como **PM**, eu quero promover ideação transiente (output de x-feature-ideate) para artefato persistente (_IDEATION.md), garantindo que ideações geradas interativamente sejam capturadas e rastreáveis.

x-feature-ideate é skill existente (CLI interativo para capturar ideação); x-promote-ideation permite: após usar x-feature-ideate, executar x-promote-ideation para salvar resultado em ai/ideations/ideation-NNNN.md, validar contra _TEMPLATE-IDEATION.md, registrar em índice. Permite que ideações criadas interativamente não se percam, transformando output transiente em artifact persistente.

Valor: connecão entre existing x-feature-ideate e novo Product-First Lifecycle; PMs podem use interactive tool, depois persist resultado com 1 comando.

## 3. Contratos & Endpoints

### 3.1 CLI Command

```
x-promote-ideation [--from-file <PATH>] [--from-stdin] [--ideation-id <ID>] [--validate]
```

| Param | Tipo | M/O | Validações |
| :--- | :--- | :--- | :--- |
| `--from-file` | `Path` | `O` | arquivo temp ou last-output |
| `--from-stdin` | `Boolean` | `O` | read from stdin |
| `--ideation-id` | `String(15)` | `O` | `ideation-\d{4}`, default: auto |
| `--validate` | `Boolean` | `O` | validate only, no write |

## 8. Decision Rationale

**Decisão:** x-promote-ideation é separado de x-feature-ideate; dois comandos distintos.

**Motivo:** Separation of concerns: x-feature-ideate é captura interativa, x-promote-ideation é persistência. Usuários podem rodar ideate múltiplas vezes antes de promoter.

**Alternativa descartada:** Automático persist em x-feature-ideate (força persistência prematura).

**Consequência:** Dois passos para usuário, mas maior flexibilidade.
