## 1. Contexto & Escopo

Como **Engenheiro de Automação**, eu quero implementar skill x-create-capability, que decompõe Produtos em Capabilities com herança RNF explicita + C2 (segunda capability) stub, garantindo decomposição automática produto→capabilities.

x-create-capability lê _PRODUCT.md, exibe interface para PM refinar capabilities (ou auto-decompõe via prompt), valida RNF herança, gera capability-NNNN artifacts com seção 2 (Inherited RNFs) populada e marcações "no-relax", cria C2 stub. Execução requer input (3-7 capability names/descriptions) ou --auto-decompose flag.

Valor: automação de decomposição produto → 3-7 capabilities coerentes, com rastreabilidade RNF herança explícita.

### 3.1 CLI Command

```
x-create-capability --product-id product-0001 [--capabilities <JSON>] [--auto-decompose] [--output-dir <PATH>]
```

| Param | Tipo | M/O | Validações |

| `--product-id` | `String(15)` | `M` | `product-\d{4}` |

| `--output-dir` | `Path` | `O` | default: product dir |

## 8. Decision Rationale

**Decisão:** MVP usa heurística simples (não LLM) para --auto-decompose; LLM vem em future story.

**Motivo:** Heurística (decompose por domain model concepts extraídos de product) é deterministik, não gasta tokens. LLM pode vir depois com feature flag.

**Alternativa descartada:** Requer manual input sempre (overhead), LLM on day-1 (cost/latency).

**Consequência:** --auto-decompose gera ~4 capabilities; PM pode refinar manualmente ou use --capabilities para override.
