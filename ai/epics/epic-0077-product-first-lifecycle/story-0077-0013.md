# História: Refator x-arch-plan: C4Context+Container+Component obrigatórios

**ID:** story-0077-0013
**Chave Jira:** —
**Status:** Pendente

## 1. Contexto & Escopo

Como **Arquiteto de Soluções**, eu quero refatorar skill x-arch-plan para tornar C4 Context + Container + Component levels obrigatórios (não opcionais), garantindo que toda arquitetura produto-first tenha diagrama C4 completo.

Atualmente x-arch-plan gera C4 diagrams opcionalmente. EPIC-0077 requer C4 como obrigatório: Context (sistema vs. mundo externo), Container (aplicações/DBs/queues), Component (classes/packages de negócio). Refactor envolve: validador que rejeita x-arch-plan output sem 3 levels, generator que produz placeholders C4 se missing, documentação que explica cada level com exemplos.

Valor: arquitetura produto-first é C4-complete desde o início, permitindo que stakeholders entendam sistema, containers, componentes sem ambiguidade.

| Campo | Tipo Java | M/O | Descrição |

### 5.2 Acceptance Criteria (Gherkin)

```gherkin
Cenário: x-arch-plan rejeita output sem Context+Container+Component
  DADO que x-arch-plan roda
  QUANDO output falta seção Context
  ENTÃO erro "C4 Context mandatory missing" reportado
  E x-arch-plan pede input para Context

Cenário: C4 complete architecture valida
  DADO que x-arch-plan output tem Context, Container, Component
  QUANDO validador processa
  ENTÃO validation passa
  E diagrama C4 pode ser renderizado

Cenário: Placeholder C4 auto-gerado se missing
  DADO que usuário não fornece detalhes Component
  QUANDO x-arch-plan finaliza
  ENTÃO placeholder "Component TBD — refine in story-0077-0015" é inserido
  E warning "Component-level details needed for story-0077-0015" é mostrado

Cenário: Pipeline de validação C4 3-levels completa dentro do SLA
  DADO que x-arch-plan-product recebe --product-id "product-0001" e --output-format mermaid
  QUANDO o pipeline completo executa (geração Context+Container + C4LevelValidator + C4ModelMandatory)
  ENTÃO o comando retorna exit code 0
  E o tempo de validação em memória (C4LevelValidator.validate) é ≤ 50ms p99
  E o tempo total da invocação CLI (incluindo startup picocli) é ≤ 500ms p95

Cenário: Injeção HTML via --product-id é neutralizada no diagrama gerado
  DADO que o usuário fornece --product-id "<script>alert('xss')</script>" para x-arch-plan-product
  QUANDO o diagrama C4 Context é gerado pelo ProductC4Planner
  ENTÃO o conteúdo do diagrama contém "&lt;script&gt;" (escaped) e NÃO contém "<script>" literal
  E o conteúdo do diagrama NÃO contém "</script>" literal
  E o exit code retornado é 0 (geração sucede com label sanitizado)
```

**Método de medição:**
- `c4_level_validation_duration_ms`: cronometrado via `System.nanoTime()` em `ArchitectureRefactoringUseCase` antes e após `C4LevelValidator.validate()`.
- `x_arch_plan_command_duration_ms`: wall-clock entre início e fim de `XArchPlanProductCommand.call()` / `XArchPlanCapabilityCommand.call()`.
- `c4_placeholder_insertion_rate` e `c4_completeness_rate`: calculados por assertivas em `XArchPlanC4MandatorySmoke`.

## 8. Decision Rationale

**Decisão:** C4 Context+Container obrigatório; Component obrigatório mas pode ter placeholder "TBD".

**Motivo:** Context+Container são fundamentais; Component pode ser refinado em story-0077-0015 (task-plan).

**Alternativa descartada:** Tudo obrigatório com detalhes (overhead), nenhum obrigatório (loses governance).

**Consequência:** Placeholder C4 components refinados em story-0077-0015.
