**ID:** story-0077-0013
**Chave Jira:** —

## 1. Contexto & Escopo

Como **Arquiteto de Soluções**, eu quero refatorar skill x-arch-plan para tornar C4 Context + Container + Component levels obrigatórios (não opcionais), garantindo que toda arquitetura produto-first tenha diagrama C4 completo.

Atualmente x-arch-plan gera C4 diagrams opcionalmente. EPIC-0077 requer C4 como obrigatório: Context (sistema vs. mundo externo), Container (aplicações/DBs/queues), Component (classes/packages de negócio). Refactor envolve: validador que rejeita x-arch-plan output sem 3 levels, generator que produz placeholders C4 se missing, documentação que explica cada level com exemplos.

Valor: arquitetura produto-first é C4-complete desde o início, permitindo que stakeholders entendam sistema, containers, componentes sem ambiguidade.

### 3.2 Output Schemas — `ProductC4Model` e `CapabilityC4Model`

`ArchitectureRefactoringUseCase` retorna **dois records distintos** para evitar campos condicionalmente nulos em um único VO (Rule 03 §Forbidden).

**`ProductC4Model`** — retornado por `XArchPlanProductCommand`:

| Campo | Tipo Java | M/O | Descrição |
| :--- | :--- | :--- | :--- |
| `productId` | `String` | `M` | Identificador do produto |
| `format` | `C4OutputFormat` | `M` | Formato aplicado a todos os diagramas |
| `contextDiagram` | `C4Diagram` | `M` | Nível Context; placeholder se não fornecido |
| `containerDiagram` | `C4Diagram` | `M` | Nível Container; placeholder se não fornecido |
| `componentDiagram` | `C4Diagram` | `M` | Nível Component; placeholder "Component TBD — refine in story-0077-0015" se ausente |
| `placeholders` | `List<String>` | `M` | Imutável via `List.copyOf(...)` no compact record constructor; levels com conteúdo auto-gerado |

**`CapabilityC4Model`** — retornado por `XArchPlanCapabilityCommand`:

| Campo | Tipo Java | M/O | Descrição |
| :--- | :--- | :--- | :--- |
| `capabilityId` | `String` | `M` | Identificador da capability |
| `format` | `C4OutputFormat` | `M` | Formato aplicado a todos os diagramas |
| `containerDiagram` | `C4Diagram` | `M` | Nível Container; placeholder se não fornecido |
| `componentDiagram` | `C4Diagram` | `M` | Nível Component; placeholder se ausente |
| `placeholders` | `List<String>` | `M` | Imutável via `List.copyOf(...)` no compact record constructor |

### 3.3 `C4LevelValidator` — Validation Result

`C4LevelValidator.validate(List<C4Diagram>)`:

| Campo | Tipo Java | Descrição |
| :--- | :--- | :--- |
| `valid` | `boolean` | `true` apenas quando Context + Container + Component presentes |
| `missingLevels` | `List<C4Level>` | Levels obrigatórios ausentes |
| `presentLevels` | `List<C4Level>` | Levels encontrados |
| `message` | `String` | Mensagem para log/CLI output. Ex: `"C4 mandatory levels missing: [COMPONENT]"` |

### 3.4 Tipo `C4Diagram` — Record Schema

`C4Diagram` é um record imutável com os campos:

| Campo | Tipo Java | M/O | Descrição |
| :--- | :--- | :--- | :--- |
| `level` | `C4Level` | `M` | Nível do diagrama (CONTEXT, CONTAINER ou COMPONENT) |
| `title` | `String` | `M` | Título legível; ex: `"System Context — product-0001"` |
| `content` | `String` | `M` | Conteúdo Mermaid ou PlantUML gerado; nunca nulo (pode ser placeholder) |
| `isPlaceholder` | `boolean` | `M` | `true` quando `content` é auto-gerado por `C4DiagramGenerator` |

### 3.5 Enums

| Enum | Membros | Uso |
| :--- | :--- | :--- |
| `C4Level` | `CONTEXT`, `CONTAINER`, `COMPONENT` | Identifica o nível C4 em `C4Diagram.level` e `C4LevelValidator` |
| `C4OutputFormat` | `MERMAID`, `PLANTUML` | Determina o renderer em `C4DiagramGenerator`; `--output-format mermaid` → `MERMAID` |

### 3.6 Boundary Skill-CLI

`x-arch-plan` é uma **skill** (LLM-driven, `SKILL.md`). Ela orquestra os comandos Java via chamada CLI:

```
x-arch-plan (SKILL.md)
  └── invoca: XArchPlanProductCommand    (picocli → ArchitectureRefactoringUseCase → ProductC4Model)
  └── invoca: XArchPlanCapabilityCommand (picocli → ArchitectureRefactoringUseCase → CapabilityC4Model)
```

Os comandos Java são os **únicos pontos de entrada autoritativos** para geração e validação C4. A skill não duplica lógica de validação — ela passa argumentos ao CLI e propaga exit codes (`0`, `1`, `2`) ao operador.

  E o tempo total da invocação CLI (incluindo startup picocli) é ≤ 500ms p95

Cenário: Injeção HTML via --capability-id é neutralizada no diagrama gerado

## 6. Segurança & Riscos

### 6.1 Registro de Riscos

| ID | Risco | Probabilidade | Impacto | Mitigação |
| :--- | :--- | :--- | :--- | :--- |
| R-01 | **Schema drift de story-0077-0008** — se story-0077-0008 alterar o modelo C4 (campos de `C4Diagram`, membros de `C4Level`), o `C4LevelValidator` desta story pode silenciosamente falhar ou retornar resultados incorretos para as stories dependentes (0077-0014, 0077-0015, 0077-0017) | Médio — story-0077-0008 está em desenvolvimento ativo | Alto — 3 stories bloqueadas dependem do contrato C4 | Declarar `C4Level`, `C4Diagram` e `C4OutputFormat` como tipos canônicos nesta story; story-0077-0008 importa esses tipos, nunca redefine. Testes de contrato via `C4LevelValidatorContractTest` |
| R-02 | **PlantUML directive injection** — valores de `--product-id` ou `--capability-id` contendo `!include`, `@startjson` ou `!define` podem alterar a semântica do diagrama PlantUML ou provocar SSRF em sistemas de CI que renderizam diagramas | Baixo — entrada vem de arquitetos internos | Alto — SSRF em CI/CD ou adulteração de diagrama | `ProductC4Planner.escape()` e `CapabilityC4Planner.escape()` sanitizam caracteres especiais PlantUML (`!`, `@`, `#`) além de entidades HTML; diretivas `!include` são removidas antes de passar ao gerador |
| R-03 | **Proliferação de placeholders Component TBD** — se a taxa de `c4_completeness_rate` ficar abaixo de 70% em produção, o valor da obrigatoriedade do Component é degradado; downstream stories (0077-0015) herdam placeholders expirados | Médio — Component é complexo e frequentemente adiado | Médio — degradação de qualidade de arquitetura | Gate de CI em `XArchPlanC4MandatorySmoke` bloqueia quando `c4_completeness_rate < 70%` no conjunto de testes; alerta `WARN` em log quando `c4_placeholder_insertion_rate > 30%` |

### 6.2 Controles de Segurança

| Área | Controle | Status |
| :--- | :--- | :--- |
| Diagram label (HTML) | `ProductC4Planner.escape()` / `CapabilityC4Planner.escape()` — HTML entity encoding | Required |
| Diagram source (PlantUML) | Remoção de diretivas `!include`, `!define`, `@start*` em inputs livres | Required |
| SVG output | Conteúdo gerado não inclui `<script>` nem event handlers — validado por `XArchPlanC4MandatorySmoke` | Required |

## 7. Observabilidade

### 7.1 Structured Logging

| Evento | Level | Campos obrigatórios |
| :--- | :--- | :--- |
| C4 validation started | `INFO` | `trace_id`, `epic_id` |
| C4 level validated | `INFO` | `trace_id`, `level`, `status` |
| C4 placeholder inserted | `WARN` | `trace_id`, `level`, `reason` |

### 7.2 Metrics

| Métrica | Tipo | Tags | SLO |
| :--- | :--- | :--- | :--- |
| `c4_level_validation_duration_ms` | `histogram` | `entity_type` (PRODUCT/CAPABILITY), `valid` (true/false) | p99 ≤ 50ms |
| `x_arch_plan_command_duration_ms` | `histogram` | `command` (product/capability), `outcome` (success/validation_error) | p95 ≤ 500ms |
| `c4_placeholder_insertion_rate` | `gauge` | `level` (CONTEXT/CONTAINER/COMPONENT) | ≤ 30% |
| `c4_completeness_rate` | `gauge` | `entity_type` | ≥ 70% |

**Método de medição:**
- `c4_level_validation_duration_ms`: cronometrado via `System.nanoTime()` em `ArchitectureRefactoringUseCase` antes e após `C4LevelValidator.validate()`.
- `x_arch_plan_command_duration_ms`: wall-clock entre início e fim de `XArchPlanProductCommand.call()` / `XArchPlanCapabilityCommand.call()`.
- `c4_placeholder_insertion_rate` e `c4_completeness_rate`: calculados por assertivas em `XArchPlanC4MandatorySmoke`.

## 8. Decision Rationale

**Decisão:** C4 Context+Container obrigatório; Component obrigatório mas pode ter placeholder "TBD".

**Motivo:** Context+Container são fundamentais; Component pode ser refinado em story-0077-0015 (task-plan).

**Alternativa descartada:** Tudo obrigatório com detalhes (overhead), nenhum obrigatório (loses governance).

**Consequência:** Placeholder C4 components refinados em story-0077-0015.
