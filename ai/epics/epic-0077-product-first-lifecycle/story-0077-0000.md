## 1. Contexto & Escopo

Como **Arquiteto de Plataforma**, eu quero emendar Rule 14 (Project Scope Guard) para autorizar explicitamente as classes de domínio de negócio introduzidas pelo EPIC-0077 (Product-First Lifecycle), garantindo que todos os PRs subsequentes que adicionem entidades `Product`, `Capability`, `Feature` e RNF não sejam bloqueados pela scope guard do repositório.

Rule 14 declara que o projeto `ia-dev-env` é um **CLI code generator** e proíbe explicitamente código Java que não serve ao pipeline de geração. As novas entidades `domain/products/`, `domain/capabilities/`, `domain/features/` e `domain/planning/rnf-validation/` representam modelo de domínio de negócio da hierarquia Product-First — categoricamente diferentes das entidades `domain/model/` existentes, que modelam configuração de projeto. Sem uma emenda normativa com ADR aprovado, qualquer PR do EPIC-0077 contendo essas classes será bloqueado pela Rule 14 scope guard durante o code review.

A entrega desta story é o fundamento normativo para todo o EPIC-0077: sem a emenda de Rule 14, nenhuma das stories subsequentes (0001-0028) pode ser implementada sem violação de regra.

### 3.2 Critério de Elegibilidade (Rule 14 Extension)

Código Java é elegível para inclusão no `ia-dev-env` sob a emenda quando satisfaz TODAS as condições:

1. Serve ao pipeline de geração `ia-dev-env generate` ou `ia-dev-env validate`
2. Modela entidades da hierarquia Product-First necessárias para geração dos artefatos `.claude/`
3. É lido durante a composição de artefatos (skills, agents, templates) pela hierarquia upstream

## 8. Decision Rationale

**Decisão:** Emendar Rule 14 via ADR formal para autorizar packages `domain/products/`, `domain/capabilities/`, `domain/features/` e `domain/planning/rnf-validation/`, estabelecendo critério explícito de elegibilidade para entidades da hierarquia Product-First.

**Motivo:** Rule 14 existe para proteger o repositório de acúmulo de código Java não relacionado ao pipeline de geração. O EPIC-0077 introduz entidades de domínio de negócio que **servem ao pipeline** (Product/Capability/Feature determinam quais artefatos `.claude/` são gerados), mas não se encaixam nas categorias existentes de `domain/model/` (que modela configuração de projeto, não hierarquia de produto). Uma emenda explícita mantém o princípio de Rule 14 intacto enquanto cria espaço controlado para a hierarquia Product-First.

**Alternativa descartada:** Tratar as novas entidades como extensões do `domain/model/` existente sem emenda (viola single source of truth; Rule 14 seria silenciosamente contornada). Incluir a emenda no escopo de story-0077-0001 (confunde fundação normativa com fundação técnica; a revisão de Rule 14 é pré-requisito, não co-entregável). Criar uma rule separada (desnecessário — Rule 14 já cobre scope; emenda é mais coesa que nova rule).

**Consequência:** Todo PR do EPIC-0077 que adicionar entidades nos packages listados deve referenciar esta story e a emenda de Rule 14 como justificativa normativa. A scope guard original permanece ativa para todos os outros packages.
