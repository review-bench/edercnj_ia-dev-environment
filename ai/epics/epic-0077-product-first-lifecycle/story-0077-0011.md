## 1. Contexto & Escopo

Como **Engenheiro de Automação**, eu quero implementar skill x-create-feature, que decompõe Capabilities em Features coerentes com Acceptance Criteria em Gherkin, garantindo que features sejam pronta para story planning downstream.

x-create-feature lê _CAPABILITY.md, valida context (inherited RNFs, constraints), interativo prompt PM para definir 4-8 features (ou --auto-decompose com heurística), gera feature-NNNN artifacts com 7 seções + 10+ AC Gherkin. Execução em < 20s per capability.

Valor: automação capability → features rastreáveis, AC em Gherkin viabiliza testing automático downstream.

## 3. Contratos & Endpoints

### 3.1 CLI Command

```
x-create-feature --capability-id <ID> [--features <JSON>] [--auto-decompose] [--output-dir <PATH>]
```

| Param | Tipo | M/O | Validações |
| :--- | :--- | :--- | :--- |
| `--capability-id` | `String(50)` | `M` | slug-format |
| `--features` | `JSON array` | `O` | `[{name, useCases:[]}]` |
| `--auto-decompose` | `Boolean` | `O` | heuristica |
| `--output-dir` | `Path` | `O` | default: capability dir |

### 3.2 Feature Output Schema

```json
{
  "featuresCreated": 5,
  "featureDetails": [
    {
      "featureId": "feature-0001",
      "capabilityId": "capability-0001",
      "useCaseCount": 3,

    }
  ]
}
```

### 5.2 Acceptance Criteria (Gherkin)

```gherkin
Cenário: x-create-feature com --features JSON gera 4 features com AC Gherkin
  DADO que capability-0001 ("Auth") existe
  QUANDO x-create-feature --capability-id capability-0001 --features '[{name:"BasicAuth"}]' executa
  ENTÃO feature-0001 é criado com 10+ AC em Gherkin
  E seção 5 tem Given/When/Then válidos
  E AC cobre: degenerate, happy path, error, boundary

Cenário: --auto-decompose decompõe capability "Auth" em 4 features
  DADO que capability-0001 é "Authentication"
  QUANDO x-create-feature --capability-id capability-0001 --auto-decompose executa
  ENTÃO 4 features: "Basic Auth", "OAuth2", "MFA", "Session Management"
  E cada tem 10+ AC
  E AC são semantically coerentes (MFA tests MFA, não Basic Auth)

Cenário: GherkinACGenerator cria AC cobrindo 4 categorias TPP
  DADO que feature "OAuth2 Integration" é input
  QUANDO AC gerado
  ENTÃO GH scenarios cobrem: degenerate (missing token), happy (valid token), error (invalid), boundary (token ttl)
  E scenarios são executable (Cucumber-compatible)

Cenário: Boundary: capability com 50+ requisitos → 8 features em < 20s
  DADO que capability_0001 é grande (50+ reqs)
  QUANDO x-create-feature --auto-decompose executa
  ENTÃO 8 features criadas em < 20s
  E cada feature tem 10+ AC
```

**Mandatory scenario categories:**
- [ ] Degenerate (capability não encontrado, features JSON inválido)
- [ ] Happy path (4 features com AC Gherkin)
- [ ] Error (invalid GH syntax, capability sem requisitos)
- [ ] Boundary (50+ requisitos → 8 features)

## 8. Decision Rationale

**Decisão:** AC geradas automaticamente via heurística (não manual); usuário pode refinar post-generation.

**Motivo:** Automação AC economiza 50% tempo de feature definition; heurística baseada em use cases + domain patterns.

**Alternativa descartada:** Manual AC (slow), LLM-generated (cost/latency).

**Consequência:** AC generated pode precisar refinamento PM; template includes refinement checklist.
