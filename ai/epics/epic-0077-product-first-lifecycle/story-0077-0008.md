## 1. Contexto & Escopo

Como **Arquiteto de Padrões**, eu quero refatorar _TEMPLATE-EPIC.md para versão 3, adicionando campos explícitos para Source Feature e herança de RNFs, garantindo que épicos criados via x-epic-create --from-feature (story-0077-0024) capturem contexto completo.

O template EPIC v3 evolui v2 para integrar Product-First Lifecycle: novo campo "Source Feature" traceia linhagem épico ← feature; seção "Inherited RNFs" mostra RNFs que devem permear todas as stories do épico (não relaxáveis sem aprovação). Esta mudança permite que x-epic-create --from-feature gere épicos com RNFs já contextualizados.

Valor: rastreabilidade completa feature → epic → stories, com governança RNF integrada.

## 8. Decision Rationale

**Decisão:** SourceFeature é opcional (O) não obrigatório (M); RNFs inherited são read-only.

**Motivo:** Alguns épicos são organizacionais (não source feature); read-only RNFs força governança e evita surpresas.

**Alternativa descartada:** SourceFeature obrigatório (quebraria épicos existentes), RNFs override-able (governance fraca).

**Consequência:** Requer migration script v2 → v3; alguns épicos antigos setados "N/A" para sourceFeature.
