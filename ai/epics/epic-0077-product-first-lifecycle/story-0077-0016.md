## 1. Contexto & Escopo

Como **QA Especialista**, eu quero implementar skill interna x-internal-c4-validate que valida integridade de C4 diagrams (Context, Container, Component, Code), garantindo que hexagonal architecture rules (inward-only dependencies, layer separation) são respeitadas.

x-internal-c4-validate é read-only (não modifica artifacts); apenas valida:
- Contexto: external systems mapeados
- Container: aplicações/DBs/queues separadas
- Component: classes/packages dentro de containers
- Code: inward-only dependency flow (adapter → application → domain)

Valor: C4 quality gate que previne arquitetura degradation; automatiza o que seria manual code review.

## 3. Contratos & Endpoints

### 3.1 Validation Rules

| Rule | Violação | Severidade |
| :--- | :--- | :--- |
| Inward-only dependencies | adapter→application é OK, application→adapter é ERRO | ERROR |
| Layer separation | class em adapter não pode usar @Service de domain | ERROR |
| Container isolation | container1 não pode depender de private class em container2 | WARN |
| External system reference | external system deve estar em C4 Context | WARN |

## 4. Materialização SOLID

- **SRP:** C4IntegrityValidator valida syntax, HexagonalArchitectureValidator valida rules.

## 5. Quality Gates

### 5.2 Acceptance Criteria (Gherkin)

```gherkin
Cenário: x-internal-c4-validate detecta outward dependency
  DADO que C4 Code tem adapter/inbound/Controller chamando domain/Service (OK)
  E application/UseCase chamando adapter/outbound/Adapter (ERRO)
  QUANDO validador executa
  ENTÃO erro "Outward dependency detected: application→adapter" reportado
  E severidade = ERROR, bloqueante

Cenário: x-internal-c4-validate valida layer separation
  DADO que domain/Entity é usada apenas em domain/Service
  QUANDO validador verifica
  ENTÃO OK

Cenário: Boundary: 200+ classes com 500+ dependencies validam em < 5s
  DADO que large system C4
  QUANDO validador executa
  ENTÃO completa em < 5s
  E todas violações reportadas
```

## 8. Decision Rationale

**Decisão:** Validador é read-only; violations são reported, não auto-fixed.

**Motivo:** Auto-fix pode quebrar intencionalidade de design; manual review é melhor.

**Alternativa descartada:** Auto-fix violations.

**Consequência:** Humanos corrigem violations; validador é advisor, não enforcer.
