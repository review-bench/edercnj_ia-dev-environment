## 1. Visão

Como **arquiteto de governança**, eu quero **um CI script que verifique pós-merge se cada story implementada teve `refinementVerdict.status="approved"`**, garantindo defesa em profundidade contra bypass via `--legacy-refinement` indevido.

## 2. Persona & Cenário

CI roda em PR para `develop` ou `epic/*`; se algum merged commit pertence a story sem refinement aprovado (e fora de exceções), build falha.

## 3. Entrega de Valor

- **Valor:** Camada 2 (CI script — Rule 26) defendendo o contrato em profundidade.
- **Métrica:** zero falsos positivos em 10 PRs pós-rollout; zero falsos negativos em 1 sprint.

## 4. Acceptance Criteria (Gherkin — esboço)

```gherkin
Cenario: PR sem refinement aprovado falha
  DADO PR merge story-X com refinementVerdict.status="rejected"
  QUANDO audit-refinement-gate.sh roda em CI
  ENTÃO exit 1 com REFINEMENT_GATE_VIOLATION

Cenario: PR com refinement aprovado passa
  DADO PR merge story-Y com status="approved"
  QUANDO audit roda
  ENTÃO exit 0

Cenario: --self-check valida pré-requisitos
  QUANDO audit-refinement-gate.sh --self-check roda
  ENTÃO exit 0 se jq na PATH e governance/baselines/refinement-gate-baseline.txt legível
  E exit 2 (OPERATIONAL_ERROR) se faltam pré-requisitos
```
