## 8. Decision Rationale

**Decisão D1:** Smoke E2E em Java (`*IT.java`) + fixtures, não shell (`tests/smoke/*.sh`).
**Motivo:** consistência com padrão `Epic*SmokeTest` / `AuditEquivalenceSmokeIT` existente no projeto; rodam sob `mvn verify` integrado ao pipeline.
**Alternativa descartada:** smoke shell.
**Consequência:** dev de novo smoke é mais caro, mas alinhado a `mvn verify` e às convenções do projeto.

**Decisão D2:** Versão MINOR no CHANGELOG é **TBD** — não pinar.
**Motivo:** memory feedback consolidado — versão é derivada por `x-release` no momento do corte, não pré-determinada durante implementação.
**Alternativa descartada:** pinar e.g. `4.0.0` aqui.
**Consequência:** entry de CHANGELOG é redigida com placeholder `[Unreleased]` até o release real.

**Decisão D3:** Dogfood pós-merge é task **separada**, não bloqueia esta story.
**Motivo:** o smoke valida que o sistema funciona; o dogfood valida que ele funciona **bem** (UX). Misturar atrasa o épico.
**Alternativa descartada:** exigir dogfood antes do merge.
**Consequência:** primeiro PR pós-EPIC-0069 inclui dogfood report como artefato.
