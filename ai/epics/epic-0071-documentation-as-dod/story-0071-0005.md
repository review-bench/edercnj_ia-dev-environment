## 1. Visão

Como **CI guardian**, quero CI script `audit-doc-freshness.sh` que valida freshness de docs em PR e **falha** quando código tocou features que requerem doc-update mas docs não foram atualizadas. Script segue Rule 26 §Standardized (exit codes nomeados, `--self-check` mandatório, entry simultânea em `docs/audit-gates-catalog.md` — **D-R5**).

Defesa em profundidade: este é o **layer CI script** (Camada 2 — Rule 26); a skill `/x-doc-validate` (story-0071-0002) é o **layer pre-flight** (Camada 0). Os dois cooperam — skill bloqueia durante a turn do LLM; CI script bloqueia no merge.

## 2. Entrega de Valor

- **Valor primário:** Camada 2 (CI script) defendendo o gate — mesmo que LLM bypasse a skill, CI bloqueia o merge.
- **Valor secundário:** registro em `ScriptsAssembler.AUDIT_SCRIPTS` instala o gate em projetos cliente automaticamente.
- **Métrica:** zero PRs merged com staleness detectável pós-rollout (medido semanalmente nos primeiros 4 sprints).

## 3. Acceptance Criteria (Gherkin — 4 categorias mandatórias)

```gherkin
Cenario: Happy — PR com doc atualizada passa
  DADO PR adiciona endpoint REST + entry em openapi.yaml
  QUANDO audit-doc-freshness.sh roda em CI
  ENTÃO exit 0 com mensagem "OK — todas dimensões atualizadas"

Cenario: Degenerate — PR só de docs sem código não dispara violação
  DADO PR toca apenas docs/adr/ADR-XXXX-*.md
  QUANDO audit-doc-freshness.sh roda
  ENTÃO exit 0 (nada para validar — mudança apenas em doc)

Cenario: Error — PR sem doc-update bloqueia
  DADO PR toca adapter/inbound/rest/ adicionando endpoint
  E openapi.yaml NÃO tocado
  QUANDO audit-doc-freshness.sh roda
  ENTÃO exit 1 com DOC_FRESHNESS_VIOLATION
  E stderr lista os files do PR e o target esperado (openapi)

Cenario: Boundary — `--self-check` valida prerequisites
  QUANDO audit-doc-freshness.sh --self-check roda
  ENTÃO exit 0 se grep, jq, git presentes em PATH e governance/baselines/doc-freshness-baseline.txt legível
  E exit 2 OPERATIONAL_ERROR se prerequisite ausente
```

## 6. Decision Rationale

**Decisão:** Camada 2 (CI script) **separada** da skill `x-doc-validate` (Camada 0). **Motivo:** defesa em profundidade — Camada 0 bloqueia durante a turn do LLM (preventiva); Camada 2 bloqueia no merge mesmo que LLM bypasse (detectiva). Diferentes mecanismos, mesmo gate. **Alternativa descartada:** só skill (sem CI script) — bypass via direct push ou via merge admin overrides. **Consequência:** dois pontos de manutenção; mitigação: heurísticas centralizadas em `knowledge/documentation/targets.md` para evitar drift.

## 7. Refinement Notes (consolidadas)

- **Padrões de detecção:** regex em `git diff <base>...HEAD --name-only`. Lista de detectores cresce por stack — começar com Java/Spring + Node/Express + Python/FastAPI + Go/gRPC.
- **Exclusões:** PRs `chore/*` que tocam apenas `docs/`, `CHANGELOG.md`, `README.md`, `ai/epics/**` são auto-skipped (changes-only-in-docs). PRs `test/*` que tocam apenas `**/test/**` ou `**/__tests__/**` são auto-skipped. Detectado via path-glob no diff.
- **Integração com `<!-- audit-exempt -->`:** marker no body do PR (não no código) com reason obrigatória; review humano necessário para merge.
- **Baseline imutável:** `governance/baselines/doc-freshness-baseline.txt` lista PRs grandfathered antes de EPIC-0071 merge (initial empty); pós-merge, append-only via separate immutability check.
- **Self-check:** `audit-doc-freshness.sh --self-check` valida `grep`, `jq`, `git`, baseline file readable, this rule file exists. Falha = exit 2 `OPERATIONAL_ERROR`.
