# EPIC-0065 — Feature Creation Chain Refactor

> **Status:** Pendente  
> **Jira:** —  
> **Branch:** `epic/0065`  
> **Base:** `develop` (pós-EPIC-0062)

---

## 1. Visão Geral

Refatorar a chain de criação de feature/épico/story do `ia-dev-environment` para tornar a entrada do pipeline mais natural, consolidar responsabilidades em skills públicas bem definidas (`x-feature-ideate`, `x-feature-create`), e rebaixar sub-skills à categoria interna. Remover commit direto em `epic/XXXX` e introduzir PR com audit trail. Adicionar branch `docs/` ao modelo de branching e formalizar hard-cut em Rule 19 para renames que mudam papel semântico.

| Layer | Pacote | Skills | Responsabilidade |

| **Core** | `x-feature-create` | `x-feature-create`, `x-internal-epic-create`, `x-internal-epic-map`, `x-internal-story-create` | Criar feature inteira (épico + stories + map) com worktree + PR |

## 3. Escopo e Limites

### Escopo incluído:
- Criar skill pública `x-feature-ideate` (ideação pré-épico)
- Renomear `x-epic-decompose` → `x-feature-create` com worktree + PR para `epic/XXXX`
- Rebaixar `x-epic-create`, `x-epic-map`, `x-story-create` a `x-internal-*`
- Adicionar branch type `docs/` (2 padrões: ideação e criação)
- Adicionar worktree patterns (2 novos)
- Atualizar Rule 09, 14, 19, 22
- Atualizar scripts de audit
- Clarificar role de `x-epic-orchestrate`
- Smoke test E2E

### Escopo excluído:
- `x-story-plan`, `x-arch-plan`, `x-test-plan`, `x-task-plan` — permanecem com commit direto sem PR (RULE-007)
- Parallelism constraints — já coberto por EPIC-0041
- Task hierarchy — já coberto por EPIC-0055

## 4. Regras Transversais (RULE-001..010)

| ID | Título | Descrição |
|----|--------|-----------|
| **RULE-001** | Worktree único por chain | `x-feature-create` cria `.claude/worktrees/feature-XXXX-<slug>/`; sub-skills herdam via Rule 14 §3. `x-feature-ideate` usa `feature-ideation-<slug>` |
| **RULE-002** | Branch da chain | `docs/<epic-id>-<slug>` (base `epic/XXXX`, alvo `epic/XXXX`) ou `docs/feature-<slug>` (ideação, alvo `develop`) |
| **RULE-003** | Naming | Skills internas: `x-internal-*` (Rule 22). Públicas: `x-{subject}-{action}`. Hard-cut em 4 nomes |
| **RULE-004** | Hard-cut autorizado | `x-epic-decompose`, `x-epic-create`, `x-epic-map`, `x-story-create` desaparecem sem alias (Rule 19 new clause) |
| **RULE-005** | Composição explícita | `x-feature-ideate` termina em spec + PR. NÃO chama `x-feature-create`. Operador revisa, depois invoca manualmente |
| **RULE-006** | `x-epic-orchestrate` sem mudança | Permanece pública, planning-only. SKILL.md ganha nota esclarecendo que NÃO cria épico/story |
| **RULE-007** | Planning standalone | `x-story-plan`, `x-arch-plan`, etc. — commit direto, sem PR adicional (fora desta epic) |
| **RULE-008** | Tipo `docs/` no branching | Rule 09: `docs/<epic-id>-<slug>` + `docs/feature-<slug>` |
| **RULE-009** | Audit scripts | `audit-skill-visibility.sh`, `audit-epic-branches.sh` reconhecem 3 internals + `docs/` type |
| **RULE-010** | DoR/DoD | Cada story roda audits + testes; 10 stories ao final com definição de qualidade global |

## 8. Decisões Arquitetônicas

| ID | Decisão | Alternativas | Rationale |
|----|---------|--------------|-----------|
| **D-001** | Idealização fora de épico: texto → spec em branch `docs/feature-<slug>` → PR develop | Incluir no fluxo x-feature-create | Permite input humano/aprovação antes de alocar epic-id |
| **D-002** | Hard-cut em 4 nomes (sem deprecation window) | Deprecation window 2 releases | RULE-004 autoriza quando muda papel semântico (public→internal, fusão taxonomy) |
| **D-003** | 3 skills internas vs 1 grande | 1 skill monolítica x-feature-create | Modularidade, reusabilidade, testabilidade. Padrão EPIC-0049 RULE-005 (thin orchestrator) |
| **D-004** | `docs/` type em lugar de `feature/` | Usar `feature/` para ideação + criação | `docs/` explicitamente sinaliza planning artifacts; não pollui namespace de feature branches |
| **D-005** | Worktree `feature-XXXX-<slug>` criado por x-feature-create | Criado por x-internal-epic-create | Orquestrador dono do worktree (RULE-001); sub-skills herdam via Rule 14 §3 |
| **D-006** | `x-epic-orchestrate` sem mudança | Rebaixar também | Planning-only é papel diferente de creation; espaço de design orthogonal |
