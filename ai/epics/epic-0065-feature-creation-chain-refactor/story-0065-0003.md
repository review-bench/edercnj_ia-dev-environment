# STORY-0065-0003 — Renomeação x-epic-decompose → x-feature-create

> **Status:** Pendente  
> **Jira:** —  
> **Epic:** EPIC-0065  
> **Bloqueadores:** story-0065-0001

---

## 1. User Story

Como **Operador**  
Preciso de um único ponto de entrada público para "criar a feature inteira"  
Para que não fique confuso entre `x-epic-create`, `x-epic-decompose` e `x-epic-orchestrate`

---

## 2. Contexto Técnico

- Renomeia `java/src/main/resources/targets/claude/skills/core/plan/x-epic-decompose/` → `x-feature-create/` via `git mv`
- Atualiza frontmatter: `name: x-feature-create`, mantém `argument-hint: [SPEC-FILE-PATH]`
- Adiciona Phase P1.5: criação worktree `feature-XXXX-<slug>` via `x-git-worktree create --branch docs/<epic-id>-<slug> --base epic/XXXX`
- Substitui Phase P5 (push epic branch) por Phases P5/P6: push branch `docs/<epic-id>-<slug>` + criação PR `→ epic/XXXX` com `--auto-merge merge` e label `docs`
- Mantém commit consolidado (1 commit por decomposição)
- Atualiza referências internas aos sub-skills (epic-create → x-internal-epic-create, etc.)
- Hard-cut: nome antigo `x-epic-decompose` não mais existe

---

## 3. Entrega de Valor

**Medida:** Eliminar confusão sobre entrada pública; clarificar hierarquia de skills  
**Impacto:** Operadores invocam o nome correto primeira vez; audit trail claro via PR em `epic/XXXX`  
**Risco mitigado:** Conflito semântico entre 3 entry-points

---

## 4. Contrato de Dados

Entrada: `<SPEC-FILE-PATH>`, `--epic-id XXXX`, `[--no-jira]`  
Saída: epic-XXXX.md, 10 story files, IMPLEMENTATION-MAP.md em `plans/epic-XXXX/`, com PR mergeado contra `epic/XXXX`
