## 1. Contexto & Escopo

Como **operador de orchestrators** (`x-epic-implement`, `x-story-implement`, `x-release`, `x-review-pr`), eu quero que invocações executem sem prompts por padrão e que estados ambíguos do working tree falhem com exit code estável, garantindo que sessões LLM nunca travem em menus de 3 opções e que o agente não entre em "confirmação defensiva".

A Rule 20 (Interactive Gates Convention, EPIC-0043) hoje define menus 3-opções (PROCEED/FIX-PR/ABORT) como default, com `--non-interactive` como opt-in. Operadores reportaram que invocações via `/x-epic-implement EPIC-XXXX` sem flag explícita travam por minutos esperando input que ninguém digita. Esta story **inverte a polaridade**: non-interactive vira o default, `--interactive` vira o opt-in. Adicionalmente, introduz `x-internal-worktree-precheck` que detecta working tree suja, branch divergente ou escopo ambíguo e retorna exit code `WORKTREE_AMBIGUOUS=15` em vez de pedir confirmação ao operador via menu textual.

Backward compat preservado via env `CLAUDE_LEGACY_INTERACTIVE=1` (deprecation 2 releases). Skills retrofitadas em uma única operação para evitar drift.

### 1.2 Entrega de Valor

- **Valor Principal:** Sessões LLM nunca mais travam em menus 3-opções por default. Operador que quiser modo interativo pede explicitamente via `--interactive`.
- **Métrica de Sucesso:** Zero ocorrências de "menu hang" reportadas em telemetria de sessões pós-merge. `WorktreePrecheckTest` verde com 100% line coverage.
- **Impacto no Negócio:** Reduz tempo médio de execução de epic em ~15min (eliminação de gates pendurados). Aumenta confiabilidade de CI agents (Claude Code + automação) que hoje precisam passar `--non-interactive` em cada invocação.

## 3. Contratos & Endpoints

### 3.1 Contract Change — Rule 20 Default Flip

| Antes | Depois |
| :--- | :--- |
| `/x-epic-implement EPIC-0061` → menu interativo aparece | `/x-epic-implement EPIC-0061` → executa direto, sem menu |
| `/x-epic-implement EPIC-0061 --non-interactive` → executa sem menu (atual opt-in) | `/x-epic-implement EPIC-0061 --interactive` → menu aparece (novo opt-in) |
| `--non-interactive` flag | **DEPRECATED** — emite warning, comportamento idêntico ao novo default. Removido em 2 releases. |

### 3.2 `WorktreePrecheck` API

| Método | Parâmetros | Retorno | Comportamento |
| :--- | :--- | :--- | :--- |
| `precheck(allowDirty)` | `boolean allowDirty` | `PrecheckResult` | Lê `git status --porcelain` + `git rev-parse --abbrev-ref HEAD`. Classifica em `CLEAN`, `DIRTY`, `DIVERGENT`, `AMBIGUOUS`. Quando `AMBIGUOUS` e `allowDirty=false`, lança `WorktreeAmbiguousException`. |
| `currentBranch()` | — | `String` | Branch atual via git. |
| `dirtyFiles()` | — | `List<String>` | Linhas de `git status --porcelain` (filename + status flags). |

### 3.3 PrecheckResult enum

| Valor | Condição | Exit code suggested |
| :--- | :--- | :--- |
| `CLEAN` | Working tree limpo, branch upstream alinhada | 0 |
| `DIRTY` | Há modificações não-commitadas mas não há divergência de upstream | 0 (warning apenas) |
| `DIVERGENT` | Branch tem commits ahead/behind do upstream | 15 (`WORKTREE_AMBIGUOUS`) |
| `AMBIGUOUS` | Estado misto (dirty + divergent) | 15 (`WORKTREE_AMBIGUOUS`) |

### 3.4 Error Codes

| Exceção | Condição | Mensagem |
| :--- | :--- | :--- |
| `WorktreeAmbiguousException` | `precheck(false)` em estado `AMBIGUOUS` ou `DIVERGENT` | `WORKTREE_AMBIGUOUS: working tree has uncommitted changes and branch divergence. Use --allow-dirty to bypass or git stash to resolve.` |
| `IllegalStateException` | git binário não encontrado | `OPERATIONAL_ERROR: git not found on PATH` |

## 6. Segurança

| Área | Controle | Status |
| :--- | :--- | :--- |
| Process execution | `WorktreePrecheck` invoca `git` via `ProcessBuilder` com argumentos individuais (sem shell). Zero risco de command injection. | Required |
| Input validation | Flag `--interactive` é booleana — sem string parsing arbitrário. Env `CLAUDE_LEGACY_INTERACTIVE` é validada como `=1` exato. | Required |
| Sensitive data | `git status --porcelain` pode incluir paths de arquivos. Nenhum conteúdo é loggado em telemetria — apenas counts (Rule 06). | Required |

**Forbidden (Rule 06):** Construção de comando git via concatenação de string. Sempre `ProcessBuilder.command(List.of("git", "status", "--porcelain"))`.

## 8. Decision Rationale

**Decisão:** Inverter a polaridade do default da Rule 20 (non-interactive vira default) em vez de adicionar configuração no `settings.json`.

**Motivo:** Configuração em `settings.json` exigiria que cada projeto-alvo fosse atualizado individualmente, e operadores que esquecessem de atualizar continuariam vendo o problema. Default flip é universal e mais simples de comunicar ("não passe nada e funciona"). Backward compat preservada via deprecation flag + env legacy escape.

**Alternativa descartada:** Manter o default atual e introduzir um hook que detecta sessões automatizadas (CI bot, headless mode) e suprime menus apenas nelas. Descartada porque adiciona complexidade detectiva (heurísticas para "isso é uma sessão automatizada?") e não resolve o problema da sessão humana que esquece a flag.

**Consequência:** Operadores que **realmente queriam** o menu (raros — operadores experimentais, debugging) precisam passar `--interactive` explicitamente. Comunicado via CHANGELOG MINOR + deprecation warning ativa por 2 releases. Pós-deprecation, a flag legada é removida.
