## 1. Contexto & Escopo

Como **CI do gerador `ia-dev-environment`**, eu quero que os 8 audits sejam executados como `*AuditorTest.java` em `mvn verify`, garantindo veredicto único no log do Maven, eliminação de dependências shell (`jq`, `gh`, `bash`) no CI runner do gerador, e feedback rápido para developers em qualquer SO (Windows/Mac/Linux).

Os bash audits (Story 2) são a forma canônica de governance entregue aos projetos-alvo. Esta story cria um **espelho Java** que vive **apenas no gerador**, valida (a) os templates em `targets/claude/skills/**/SKILL.md` antes de empacotar, (b) os próprios artefatos do gerador em `plans/epic-*/`. A equivalência bash↔Java é provada uma vez por `AuditEquivalenceSmokeIT` que roda ambas as implementações sobre fixture corpus em `framework/src/test/resources/audit-corpus/` e compara exit codes + violations textuais.

A implementação é dividida em 2 sub-waves: Wave A (5 markdown audits — `model-selection`, `skill-visibility`, `bypass-flags`, `task-hierarchy`, `phase-gates`) e Wave B (3 runtime audits — `flow-version`, `epic-branches`, `execution-integrity`). Cada wave produz um sub-PR para o branch da story (Rule 22 §parallelism waves).

### 1.2 Entrega de Valor

- **Valor Principal:** CI do gerador roda audits sem dependência de shell tooling. Veredicto único no log do `mvn verify`. Smoke test prova paridade.
- **Métrica de Sucesso:** 8 `*AuditorTest` verdes, `AuditEquivalenceSmokeIT` verde para todos os 8 audits sobre fixture corpus de ≥ 20 entries.
- **Impacto no Negócio:** Reduz ~3min de runner-time por PR no gerador (eliminação do `audit.yml` paralelo — Story 5). Zero flakiness por shell deps ausentes.

## 3. Contratos & Endpoints

### 3.1 `Auditor` interface comum

```java
public interface Auditor {
    AuditResult audit(AuditCorpus corpus);
    String name();              // "model-selection"
    Path bashEquivalent();      // targets/claude/scripts/java-maven/audit-model-selection.sh.tpl
}
```

### 3.2 `AuditResult` record

```java
public record AuditResult(
    int exitCode,                     // 0=OK, 1=violation, 2=operational, 3=baseline
    String exitName,                  // "OK" | "MODEL_SELECTION_VIOLATION" | etc.
    List<AuditViolation> violations
) {}

public record AuditViolation(
    Path file,
    int line,
    String rule,                      // "MISSING_MODEL"
    String message
) {}
```

### 3.3 `AuditCorpus` API

| Método | Retorno | Comportamento |
| :--- | :--- | :--- |
| `walkSkills()` | `Stream<Path>` | Lista todo `SKILL.md` sob `targets/claude/skills/` |
| `walkAgents()` | `Stream<Path>` | Lista todo `*.md` sob `targets/claude/agents/` |
| `loadExecutionStates()` | `Stream<ExecutionState>` | Carrega `plans/epic-*/execution-state.json` |
| `mergedStories()` | `Stream<Story>` | Stories com PR mergeado (lê via JGit) |

### 3.4 `AuditEquivalenceSmokeIT` Contract

Para cada audit name, executa:

```
1. bash framework/src/main/resources/targets/claude/scripts/java-maven/audit-{name}.sh \
       --corpus src/test/resources/audit-corpus/{name}/
   → captura exit code + linhas de stdout/stderr

2. {Name}Auditor.audit(new AuditCorpus(src/test/resources/audit-corpus/{name}/))
   → captura AuditResult

3. assertThat(bashExit).isEqualTo(javaResult.exitCode())
4. assertThat(bashViolations).containsExactlyInAnyOrderElementsOf(
       javaResult.violations().stream().map(v -> v.file() + ":" + v.line()).toList())
```

Divergência fail o build com mensagem que cita o audit name + tipo de divergência.

### 4.2 Princípios SOLID

- **SRP:** Cada `*Auditor` valida UMA regra. `AuditCorpus` apenas walks paths.
- **OCP:** Novo audit = nova classe `Auditor` + novo nome em `AuditEquivalenceSmokeIT.AUDIT_NAMES`. Sem modificar existentes.
- **LSP:** Todas implementam `Auditor` — substituíveis no smoke test.
- **DIP:** `Auditor` recebe `AuditCorpus` via parâmetro de método (não inline `Files.walk`).

### 4.3 Coding Constraints

- Cada `*Auditor.java` ≤ 150 linhas
- `AuditCorpus.java` ≤ 200 linhas
- Tests usam fixtures externalizadas (sem inline strings de SKILL.md)

## 8. Decision Rationale

**Decisão:** Implementar 8 classes Auditor separadas em vez de 1 classe `MultiAuditor` configurável.

**Motivo:** Cada audit tem regras distintas (regex específico, walker específico, exit code específico). Single-class viraria 800+ linhas com switch/case. 8 classes pequenas (~120 linhas cada) são mais fáceis de testar, documentar e manter — e seguem SRP estrito.

**Alternativa descartada:** Reuse Maven Enforcer Plugin com regras customizadas. Descartada porque Enforcer é caixa-preta, regras customizadas são pouco flexíveis para parsing de markdown estruturado, e debugging via Maven plugin é mais difícil que JUnit puro.

**Consequência:** Adicionar um novo audit demanda criar uma nova classe + entry em `AuditEquivalenceSmokeIT.AUDIT_NAMES` + fixture corpus. Esforço: ~3 horas por audit novo. Listed audits cobrem 100% das Rules 19, 21, 22, 23, 24, 25, 27, 45 — adições raras.
