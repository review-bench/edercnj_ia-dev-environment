## 3.1 Type Contracts (Java records)

The `QualityConfig` and its sub-records are immutable Java records under `dev.iadev.config`. All fields are explicitly typed; YAML keys (snake_case) map to record components (camelCase) via the configuration-parsing layer.

```java
package dev.iadev.config;

import java.util.Map;

public record QualityConfig(
    PerformanceConfig performance,
    MutationConfig mutation,
    ContractConfig contract
) {}

public record PerformanceConfig(
    boolean enabled,
    SloConfig slo,
    int baselineTolerancePct,
    Map<String, Object> toolVersions
) {}

public record SloConfig(
    RestSlo rest,
    GrpcSlo grpc,
    CliSlo cli
) {}

public record RestSlo(
    int p50Ms,
    int p95Ms,
    int p99Ms,
    int throughputRps
) {}

public record GrpcSlo(
    int p50Ms,
    int p95Ms,
    int p99Ms
) {}

public record CliSlo(
    int genTimeP95Ms
) {}

public record MutationConfig(
    boolean enabled,
    int threshold,
    int runtimeCapMin,
    Map<String, Object> toolVersions
) {}

public record ContractConfig(
    boolean enabled,
    boolean pact,
    boolean openapiBreaking,
    boolean protoBreaking
) {}
```

YAML ↔ Java mapping (representative):

| YAML key | Java component |
| :--- | :--- |
| `quality.performance.enabled` | `QualityConfig.performance().enabled()` |
| `quality.performance.slo.rest.p95_ms` | `QualityConfig.performance().slo().rest().p95Ms()` |
| `quality.performance.slo.grpc.p99_ms` | `QualityConfig.performance().slo().grpc().p99Ms()` |
| `quality.performance.slo.cli.gen_time_p95_ms` | `QualityConfig.performance().slo().cli().genTimeP95Ms()` |
| `quality.performance.baseline_tolerance_pct` | `QualityConfig.performance().baselineTolerancePct()` |
| `quality.mutation.threshold` | `QualityConfig.mutation().threshold()` |
| `quality.mutation.runtime_cap_min` | `QualityConfig.mutation().runtimeCapMin()` |
| `quality.contract.openapi_breaking` | `QualityConfig.contract().openapiBreaking()` |
| `quality.contract.proto_breaking` | `QualityConfig.contract().protoBreaking()` |

Defaults sãos (when bloco `quality:` ausente OR sub-bloco ausente — Rule 19): every `enabled` field is `false`; numeric SLO fields default to the per-stack reference values listed in §1.3 of the epic; `toolVersions` defaults to empty map.

## 6. Decision Rationale

**Decisão:** Schema agrupado sob `quality:` top-level (não 3 chaves top-level separadas). **Motivo:** evita YAML explosion no `ProjectConfig`; mantém os 3 sub-blocos próximos semanticamente (todos são "quality gates"); facilita iteração (operador lê uma seção, não três espalhadas). **Alternativa descartada:** 3 sub-blocos top-level (`performance:`, `mutation:`, `contract:`) — rejeitado por (a) cada uma seria "uma chave a mais no nível raiz" complicando o schema YAML; (b) drift entre as 3 inevitável quando alguma evoluir. **Consequência:** futuras dimensões de quality (chaos, fuzz, property) entram como `quality.<sub>:` sem novo top-level.

### 6.1 Alternativa adicional — placement de `QualityConfig.java` (config/ vs domain/model/)

**Decisão:** `QualityConfig` reside em `dev.iadev.config` (camada de configuração).
**Alternativa descartada:** colocar em `dev.iadev.domain.model` para que `ProjectConfig` o exponha como campo direto do agregado de domínio.
**Motivo da rejeição:** `QualityConfig` é uma preocupação de **parsing de configuração**, não uma entidade de domínio. Ele agrupa thresholds, SLOs e versions de ferramentas — dados externos ao modelo de negócio do gerador. Seu lugar natural é a camada `config/`, junto a outros assemblers/configs (RULE-004 §architecture-summary: dependency direction inward).
**Consequência:** `ProjectConfig.fromMap(...)` recebe um `QualityConfig` já construído como valor (record imutável, zero dependências de framework), preservando a pureza de domínio. A camada `domain/` não importa nada de `config/` — o fluxo é `config/ConfigLoader` → constrói `QualityConfig` → injeta em `ProjectConfig` via construtor canônico.
