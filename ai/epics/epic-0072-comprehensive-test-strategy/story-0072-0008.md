## 6. Decision Rationale

**Decisão:** Conditional via YAML (`quality.<sub>.enabled=true`), NÃO sempre-on. **Motivo:** projetos sem SLA (CLI internos, ferramentas de devops, scripts) não devem ser forçados a manter baseline de performance ou rodar mutation testing (caro). Opt-in declarativo respeita a heterogeneidade dos projetos cliente. **Alternativa descartada:** sempre-on com `--skip-perf`/`--skip-mutation`/`--skip-contract` flags — rejeitado por (a) viola Rule 24 §Forbidden (`--skip-*` outside `## Recovery` é violation); (b) opt-out via flag é frágil (pode ser esquecido), opt-in via YAML é explícito. **Consequência:** Rule 24 §Mandatory Evidence Artifacts ganha 3 entries condicionais (artefato exigido SE gate enabled).

**Decisão complementar:** Sequência sequencial perf → mutation → contract (D-R11). **Motivo:** (a) mutation drena CPU e gera jitter no perf p95 — paralelizar invalida medição; (b) fast-fail reduz custo em CI quando uma falha; (c) ordering reflete custo crescente (perf é segundos, mutation é minutos, contract é segundos — perf primeiro é o "smoke fast"); (d) abort-code mapping é trivial (1 falha por etapa).
