# História: CI script `audit-contract-breaking.sh` + entry no audit-gates-catalog

**ID:** story-0072-0007
**Status:** Refinada
**Refinement Verdict:** Approved (2026-04-30)

## 1. Visão

Como **developer on a generated project**, quero CI script `audit-contract-breaking.sh` (Camada 2 — Rule 26) que:
1. Detecta breaking change em OpenAPI/proto/event-schema cruzando branch base vs PR (mesma classificação aplicada pela skill `x-test-contract`, story-0072-0004).
2. Verifica se PR documenta migração via entry "## Breaking" em `CHANGELOG.md` (formato compatível com `_TEMPLATE-CHANGELOG-ENTRY.md` que será entregue por EPIC-0071).
3. Bloqueia merge se breaking detectado E sem migration doc; passa com WARN se breaking detectado E migration doc presente.
4. Implementa `--self-check` (Rule 26).
5. Entry simultânea em `docs/audit-gates-catalog.md` (RULE-004 — Catalog-before-Add).

…porque skill `x-test-contract` roda em Phase 3 (story-0072-0008), mas Camada 2 (CI script independente) protege contra bypass — operador que ignora a skill via flag ainda é pego pelo audit.

## 2. Entrega de Valor

- **Valor primário:** Prevents undocumented breaking changes from reaching production releases. Without this gate, a developer can merge a PR that removes an API field or changes a proto message without any migration note, causing downstream consumers to break silently at deploy time.
- **Valor secundário:** Establishes a bidirectional contract between code changes and CHANGELOG entries — developers who document a migration pass the gate with a warning; those who do not are blocked before merge.
- **Métrica:** Contract-breaking escape rate = 0% post-rollout, measured by quarterly `git log` analysis of tagged releases: count releases containing at least one breaking contract change (OpenAPI field removal, proto field deletion, event schema incompatibility) whose CHANGELOG lacks a corresponding `## Breaking` entry. Target: 0 escapes per release cycle. Baseline before gate: unmeasured (no enforcement). Measurement method: `git diff` between consecutive release tags filtered to contract artifact paths, cross-referenced with CHANGELOG `## Breaking` sections.

```gherkin

  DADO PR não modifica openapi.yaml/proto/avsc
  QUANDO audit-contract-breaking.sh roda

  DADO repositório sem openapi.yaml E sem **/*.proto E quality.contract.enabled=true
  QUANDO audit-contract-breaking.sh roda
  ENTÃO exit 0 (OK) com WARN "no contract artifacts found"

  DADO PR muda openapi.yaml com breaking (campo removido)
  E sem entry "## Breaking" no CHANGELOG.md modificado pelo PR
  QUANDO audit-contract-breaking.sh roda
  ENTÃO exit 1 (CONTRACT_BREAKING_VIOLATION) com mensagem "breaking change detected; CHANGELOG.md needs '## Breaking' entry"
  E reporta diff completo dos artefatos de contrato

Cenario: Boundary — breaking documentado em CHANGELOG passa com WARN
  DADO PR muda proto3 com breaking (field removal)
  E PR adiciona entry "## Breaking" em CHANGELOG.md (regex match em "^##\\s+Breaking" no diff do CHANGELOG)
  QUANDO audit-contract-breaking.sh roda
  ENTÃO exit 0 (OK) com WARN "breaking change detected — documented migration accepted"
  E loga a justificativa para auditoria (path do log = TBD: `audits/` não existe na árvore atual; sugerir `governance/audits/contract-breaking-history.log` ou criar `audits/` — decidir em task-0072-0007-006 antes do impl)

Cenario: Security — path traversal em artifact path rejeitado
  DADO PR contém artefato de contrato com path "../../../etc/passwd" no diff
  QUANDO audit-contract-breaking.sh normaliza o path
  ENTÃO rejeita com exit 2 (OPERATIONAL_ERROR) e mensagem "invalid contract artifact path: traversal detected"
  E NÃO tenta ler arquivo fora do repositório

Cenario: Security — command injection via malformed filename
  DADO PR contém artefato de contrato com filename "openapi$(whoami).yaml" ou "proto;rm -rf /.proto"
  QUANDO audit-contract-breaking.sh processa a lista de artefatos
  ENTÃO sanitiza o filename antes de qualquer shell expansion
  E NÃO executa comandos embutidos no nome do arquivo
  E exit 2 (OPERATIONAL_ERROR) com mensagem "invalid contract artifact filename: rejected by sanitizer"

Cenario: Security — tool error output does not leak internal paths
  DADO openapi-diff falha com erro interno contendo paths absolutos do servidor
  QUANDO audit-contract-breaking.sh captura stderr do openapi-diff
  ENTÃO NÃO propaga o stderr completo para stdout do script
  E emite apenas "openapi-diff failed — see CI log for details" com exit 2

Cenario: Performance — script execution within SLA for large repo
  DADO repositório com 50 artefatos de contrato (openapi.yaml + proto + avsc)
  E histórico git com 500+ commits
  QUANDO audit-contract-breaking.sh roda
  ENTÃO completa em menos de 5 segundos (wall-clock)
  E NÃO faz full-repo scan — opera apenas sobre artefatos modificados no PR diff
```

## 6. Typed Contracts

### 6.1 Exit Codes

| Exit | Constant | Condition |
| :--- | :--- | :--- |
| 0 | `OK` | No breaking change detected, or breaking change detected with valid `## Breaking` entry in CHANGELOG.md (WARN emitted). |
| 1 | `CONTRACT_BREAKING_VIOLATION` | Breaking change detected in contract artifacts AND no `## Breaking` entry found in the PR's CHANGELOG.md diff. |
| 2 | `OPERATIONAL_ERROR` | Prerequisites missing (`jq`, `git` not on PATH), invalid artifact path (traversal detected), malformed filename, or `openapi-diff` internal failure. |
| 3 | `BASELINE_CORRUPT` | Baseline file `governance/baselines/contract-breaking-baseline.txt` is malformed or non-readable. |

### 6.2 Log Schema (`governance/audits/contract-breaking-history.log`)

Append-only, tab-delimited. One record per boundary-case detection (breaking change detected AND documented in CHANGELOG).

| # | Field | Type | Format | Example |
| :--- | :--- | :--- | :--- | :--- |
| 1 | `timestamp` | ISO-8601 | `YYYY-MM-DDTHH:MM:SSZ` | `2026-05-01T14:30:00Z` |
| 2 | `commit_sha` | string(40) | 40-char lowercase hex git SHA | `a1b2c3d4e5f6...` |
| 3 | `author_email` | string | Git author email | `dev@example.com` |
| 4 | `breaking_type` | enum | One of: `FIELD_REMOVED`, `FIELD_TYPE_CHANGED`, `ENDPOINT_REMOVED`, `MESSAGE_REMOVED`, `ENUM_VALUE_REMOVED`, `SCHEMA_INCOMPATIBLE` | `FIELD_REMOVED` |
| 5 | `artifact_path` | string | Repo-relative path to the changed contract artifact | `api/openapi.yaml` |
| 6 | `justification` | string | Double-quoted content of the `## Breaking` CHANGELOG entry | `"Removed deprecated /v1/users endpoint"` |

### 6.3 CHANGELOG Regex Specification

The script detects a "migration doc" entry by matching the following regex against the PR's diff of `CHANGELOG.md`:

```
^##\s+(Breaking(\s+Changes?)?|BREAKING)\s*$
```

- **Case sensitivity:** The match on "Breaking" is case-insensitive (`grep -iE`). The literal "BREAKING" (all-caps) is also accepted.
- **Spacing:** Zero or more trailing spaces after the header text are tolerated.
- **Level:** Only H2 headers (`##`) are accepted. H3 (`###`) or deeper are NOT recognized as migration doc entries.
- **Variants accepted:** `## Breaking`, `## Breaking Changes`, `## Breaking Change`, `## BREAKING`.
- **Variants rejected:** `## breaking changes in v2` (trailing text), `### Breaking` (wrong level), `## Breaking:` (trailing colon).

### 6.4 Alternatives Considered

| Alternative | Verdict | Rationale |
| :--- | :--- | :--- |
| Block this epic until EPIC-0071 delivers `_TEMPLATE-CHANGELOG-ENTRY.md` + `audit-changelog-presence.sh` | **Rejected** | Scope-creep and dependency circular: EPIC-0071 references this audit as an example of "gate Doc-as-DoD". Decoupling via local regex allows day-1 functionality with future-wired migration path. |
| Use `buf breaking` as the sole detection mechanism for proto files | **Rejected** | Adds a hard runtime dependency on `buf` CLI which may not be present in all CI environments. The script uses `buf` opportunistically (when available) and falls back to regex heuristics for proto changes. |
| Detect breaking changes via commit message `BREAKING CHANGE:` footer only (no CHANGELOG scan) | **Rejected** | Conventional Commits footer is author-dependent and easy to omit. CHANGELOG entry is a durable, reviewable artifact visible in release notes. The script accepts `BREAKING CHANGE:` footer as a secondary signal but requires the CHANGELOG entry as the primary migration doc. |

## 7. Risks

### 7.1 Technical Risks

| # | Risk | Likelihood | Impact | Mitigation |
| :--- | :--- | :--- | :--- | :--- |
| T1 | `openapi-diff` tool absent in CI runner | Medium | Medium | Fail-open with WARN (`exit 0` + message "openapi-diff not found — falling back to regex heuristics"). `--self-check` surfaces the absence. |
| T2 | Shallow clone (`--depth=1`) breaks `git diff` against base branch | Medium | High | Script detects shallow clone via `git rev-parse --is-shallow-repository`; if true, runs `git fetch --unshallow` or emits `exit 2` with actionable message. |
| T3 | CHANGELOG regex false-positive on non-standard headers (e.g., `## Breaking Down the Architecture`) | Low | Medium | Regex anchored with `$` — only accepts `## Breaking` variants with no trailing text. Documented in §6.3. |
| T4 | Command injection via crafted contract artifact filenames | Low | Critical | All filenames passed through `--` argument separator and shell-quoted. Path normalization rejects `..` traversal. AC scenarios validate this explicitly. |
| T5 | Concurrent PR race on `contract-breaking-history.log` (two PRs appending simultaneously) | Low | Low | Log is append-only; each CI run appends at most one line. Git merge conflict on simultaneous appends is auto-resolvable (both lines kept). CI retries handle transient conflicts. |

### 7.2 Product Risks

| # | Risk | Likelihood | Impact | Mitigation |
| :--- | :--- | :--- | :--- | :--- |
| P1 | False-positive blocking on compatible refactors (e.g., field rename with deprecation marker classified as breaking) | Medium | Medium | Gate passes with WARN when CHANGELOG `## Breaking` entry is present. Developer documents the compatible refactor in CHANGELOG and is unblocked. False-positive rate tracked via `contract-breaking-history.log`. |
| P2 | Adoption friction if `openapi-diff` is unavailable and regex heuristics produce poor results | Low | Medium | Regex heuristics cover the 80% case (field removal, endpoint removal). `--self-check` warns about missing tooling. Documentation in the generated project's audit-gates-catalog explains the recommended toolchain. |

## 8. Decision Rationale

**Decisão:** Integração com CHANGELOG via regex local (`^##\s+Breaking\s*$`) **enquanto** EPIC-0071 não merge; quando 0071 entregar `_TEMPLATE-CHANGELOG-ENTRY.md` + audit dedicado, integração migra para invocação do audit de 0071. **Motivo:** desacopla este épico do timeline de 0071; gate funcional desde dia 1; migração futura é additiva. **Alternativa descartada:** bloquear este épico até 0071 mergear — rejeitado por scope-creep e dependência circular (0071 também referencia este audit como "exemplo de gate Doc-as-DoD"). **Consequência:** documentação clara de "future-wired" no script + KP da story-0072-0004.
