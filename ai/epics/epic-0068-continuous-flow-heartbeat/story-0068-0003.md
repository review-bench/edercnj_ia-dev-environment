## 1. Contexto & Escopo

Como **LLM operador**, quando o Stop hook `enforce-continuous-flow.sh` emite nudge, eu quero saber **exatamente qual tool call** retomar — não apenas "retome a fase". Isso elimina ambiguidade e evita drift adicional.

A Tool-Call Grammar rule (introduzida por EPIC-0063 `story-0063-0012`; rule number TBD — colide atualmente com `28-capability-frontmatter-contract.md` de EPIC-0064) introduzirá markers inline em SKILL.md de orquestrador:

```markdown
Skill(skill: "x-arch-plan", model: "opus", args: "...")  [required]
Skill(skill: "x-threat-model", model: "sonnet", args: "...")  [conditional: scope ∈ {auth, network, persistence}]
Skill(skill: "x-spec-drift", model: "sonnet", args: "...")  [optional]
```

Esta story estende `enforce-continuous-flow.sh` (story-0068-0002) com lógica que:

1. Identifica o orquestrador ativo via state file.
2. Lê o SKILL.md correspondente.
3. Para cada `Skill(...) [required]` na fase corrente, cruza com NDJSON da story para identificar quais ainda **não** foram emitidas.
4. Inclui o nome da próxima `[required]` ausente no nudge (mensagem stderr).

Quando a Tool-Call Grammar rule não estiver disponível (EPIC-0063 `story-0063-0012` não merged ainda), o hook degrada para o fallback genérico definido em `story-0068-0002` §3.4. A implementação acopla aos markers (sintaxe `[required]`/`[optional]`/`[conditional]`), não ao número da rule — sobrevive à eventual renumeração.

- **Valor Principal:** Nudge específico (skill name + razão) em vez de genérico ("retome a fase").
- **Métrica de Sucesso:** Em smoke test, nudge identifica corretamente a próxima `[required]` ausente em 100% dos cenários onde a Tool-Call Grammar rule está disponível. Fallback funciona em 100% dos cenários onde não está.
- **Impacto no Negócio:** Nudges acionáveis reduzem tempo de retomada de minutos para segundos.

## 3. Contratos & Endpoints

### 3.1 Função `derive_next_mandatory_call`

**Input:**

| Var | Tipo | Descrição |
| :--- | :--- | :--- |
| `$1` | string | Path do SKILL.md do orquestrador ativo |
| `$2` | string | Phase name corrente (e.g., `"Phase 3"`) |
| `$3` | string | Path do `events.ndjson` da story corrente |

**Output stdout:**

- Caso (a) — markers Tool-Call Grammar presentes E fase identificada: nome da próxima skill `[required]` ausente do NDJSON (e.g., `"x-review-pr"`).
- Caso (b) — markers Tool-Call Grammar ausentes (EPIC-0063 `story-0063-0012` não merged): string vazia (caller usa fallback).
- Caso (c) — todos `[required]` da fase já emitidos: string `"PHASE_COMPLETE"` (caller suprime nudge — provavelmente fase fechando).

**Exit codes:**

- 0: lookup completed (stdout contém resultado)
- 1: SKILL.md não encontrado ou phase não identificada (caller usa fallback)
- 2: NDJSON malformado (caller usa fallback)

### 3.2 Algoritmo

```
1. Open SKILL.md at $1
2. Locate "## Phase N" matching $2
3. Within phase block, extract all lines matching:
     /^\s*Skill\(skill:\s*"([^"]+)".*\[required\]/
   into REQUIRED_SET
4. If REQUIRED_SET empty → exit 1 (no markers)
5. Open events.ndjson at $3
6. Extract set of tool.call events with skill name into EMITTED_SET
7. MISSING = REQUIRED_SET - EMITTED_SET
8. If MISSING empty → echo "PHASE_COMPLETE" → exit 0
9. Echo first element of MISSING (in declaration order from SKILL.md) → exit 0
```

### 3.3 Integração com nudge mensagem

Story-0068-0002 §3.4 fica:

```
CONTINUOUS_FLOW_INTERRUPT
Orchestrator: <name>
Open tasks: <N>
Phase: <phase>
Next mandatory tool call: <result of derive_next_mandatory_call>
Action: emit the next tool call immediately. Do NOT generate prose.
```

Quando função retorna `PHASE_COMPLETE`, hook **suprime** o nudge — exit 0 em vez de exit 2 (fase está naturalmente fechando, próxima ação será TaskUpdate de fechamento + mover para próxima fase).

Quando função retorna string vazia (markers ausentes), nudge usa fallback:

```
Next mandatory tool call: see SKILL.md of <orchestrator>, ## Phase <name>
```
