## 1. Contexto & Escopo

Como **Operator/LLM**, eu quero um Stop hook `enforce-continuous-flow.sh` que dispara em todo evento `Stop` do Claude Code e, quando detecta orquestrador rodando em `--non-interactive` com fase aberta + último turno terminado em prosa (não em tool call), emite um WARNING via stderr (exit 2) que Claude Code surfaca para o LLM no próximo turno como nudge para retomar.

O hook é **distinto de `verify-story-completion.sh`** (Rule 24 Camada 2) — esse checa evidência ao final do orquestrador; o novo checa progresso intra-fase. Os dois rodam no mesmo `Stop` event sem conflito (separação de responsabilidades — Rule 03 SRP).

A lógica de decisão consome:

1. `execution-state.json.interactiveMode` (story-0068-0001).
2. `execution-state.json.taskTracking.openTasks` (Rule 25).
3. NDJSON `events.ndjson` da story corrente (Rule 13 telemetry).

E aplica matriz de decisão precisa (§3.3 abaixo) para evitar falsos positivos.

### 1.1 Regras Transversais Aplicáveis

| ID | Título |
| :--- | :--- |
| Rule 26 | Hook runtime layer — naming `enforce-*.sh` + `--self-check` mandatory |
| Rule 19 | Field ausente / inválido → fallback `interactive` (no-op) |
| Rule 27 | Hotfix branch detection → no-op (Exception 2) |

### 1.2 Entrega de Valor

- **Valor Principal:** LLM travado mid-fase recebe nudge automático no próximo turno — operador não precisa intervir.
- **Métrica de Sucesso:** Hook exit 2 + stderr `CONTINUOUS_FLOW_INTERRUPT` em 100% dos cenários onde matriz de decisão indica "fase aberta sem progresso em modo non-interactive". Zero falsos positivos em smoke test.
- **Impacto no Negócio:** Fecha a janela cega entre EPIC-0061 e EPIC-0063.

## 3. Contratos & Endpoints

### 3.1 Hook input format (Claude Code Stop contract)

```json
{
  "session_id": "abc-123",
  "transcript_path": "/path/to/transcript.jsonl",
  "stop_hook_active": false
}
```

Hook lê stdin JSON, mas a lógica primária consome state file + NDJSON, não o input.

### 3.2 Hook exit codes

| Exit | Code | Meaning |
| :--- | :--- | :--- |
| 0 | `OK` | No nudge needed |
| 2 | `CONTINUOUS_FLOW_INTERRUPT` | Nudge emitted to stderr |

Exit 2 é o contrato Stop hook do Claude Code que faz o WARNING aparecer para o LLM no próximo turno.

### 3.3 Matriz de Decisão

Hook resolve o estado em ordem (short-circuit no primeiro match):

| Condição | Resultado |
| :--- | :--- |
| (a) `execution-state.json` ausente em `ai/epics/epic-*` e `plans/epic-*` | exit 0 (no orchestrator active) |
| (b) Branch atual é `hotfix/*` | exit 0 (Rule 27 Exception 2) |
| (c) `interactiveMode` resolvido para `"interactive"` (campo absente, valor `"interactive"`, ou inválido) | exit 0 (no-op clássico) |
| (d) `taskTracking.openTasks` vazio ou ausente | exit 0 (orchestrator concluído ou sem tracking) |
| (e) Último evento NDJSON da story corrente é `finding.critical` ou `finding.high` | exit 0 (pausa legítima para decisão humana) |
| (f) Último evento NDJSON é `error` ou `tool.error` | exit 0 (erro tratado por outro hook) |
| (g) Último evento NDJSON é `tool.call` (não `tool.result`) — ainda em flight | exit 0 (LLM ainda processando) |
| (h) Caso contrário: orchestrator non-interactive, fase aberta, último evento foi `tool.result`, sem erro pendente | **exit 2 + nudge** |

### 3.4 Output stderr (caso h)

```
CONTINUOUS_FLOW_INTERRUPT
Orchestrator: <name from state>
Open tasks: <N>
Phase: <current phase from state — "Phase 3 (Review)" etc.>
Next mandatory tool call (Rule 28 grammar): <derived in story-0068-0003 — fallback "Skill from SKILL.md ## Phase N">
Action: emit the next tool call immediately. Do NOT generate prose.
Reference: feedback memory `continuous-flow-non-interactive`, Rule 24/27, EPIC-0068.
```

Quando story-0068-0003 não estiver merged, hook usa fallback: "next mandatory tool call: see SKILL.md of <orchestrator>".

### 3.5 `--self-check` (Rule 26)

```bash
case "${1:-}" in
  --self-check)
    command -v jq >/dev/null 2>&1 || { echo "OPERATIONAL_ERROR: jq required" >&2; exit 2; }
    [[ -d "ai/epics" ]] || [[ -d "plans" ]] || { echo "OPERATIONAL_ERROR: no epic dirs" >&2; exit 2; }
    exit 0
    ;;
esac
```

### 3.6 Locking / Concurrency

Hook é read-only (não modifica state file). Sem lock necessário. Idempotent — múltiplas execuções em sequência produzem o mesmo resultado.

## 4. Materialização SOLID

### 4.1 Princípios Aplicáveis

- **SRP:** Hook tem uma única razão de mudar — lógica de detecção de fluxo travado. Não checa evidência (responsabilidade de `verify-story-completion.sh`).
- **OCP:** Matriz de decisão é tabela de regras (§3.3) — novas condições adicionam linhas sem modificar lógica existente.
- **DIP:** Hook consome state + NDJSON via `jq` — não acopla a implementação dos orquestradores.

### 4.2 Coding Constraints

- Hook ≤ 200 linhas de bash (target: 120-150).
- Funções ≤ 25 linhas (Rule 03).
- Zero usage de `System.exit()` equivalent — sempre `exit <code>` explícito.
- `set -euo pipefail` no topo (defesa contra bash drift).
