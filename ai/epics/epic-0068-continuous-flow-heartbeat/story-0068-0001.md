## 1. Contexto & Escopo

Como **operador automatizado**, eu quero que `execution-state.json` carregue um campo discriminador `interactiveMode` que reflita se o orquestrador está rodando em modo interativo ou não-interativo, para que o Stop hook `enforce-continuous-flow.sh` possa filtrar quando emitir nudge sem ambiguidade.

Hoje os 8 orquestradores Anexo B (Rule 25) inicializam `execution-state.json` com `flowVersion`, `epicId`, `taskTracking`, mas **não persistem** se o caller passou `--interactive` ou `--non-interactive` (default pós-EPIC-0061). Sem esse campo, o Stop hook não consegue distinguir "modo interativo legítimo (humano vai responder gate)" de "modo non-interactive travado (LLM precisa retomar)".

Esta story adiciona o campo, escreve nos 8 orquestradores, e estende Rule 19 fallback matrix.

### 1.1 Regras Transversais Aplicáveis

| ID | Título |
| :--- | :--- |
| RULE-001 | Field opcional com fallback |
| RULE-002 | Escrita centralizada via `x-internal-status-update` |

### 1.2 Entrega de Valor

- **Valor Principal:** Campo discriminador disponível para Stop hook + audits futuros classificarem comportamento de orquestradores.
- **Métrica de Sucesso:** 100% dos `execution-state.json` criados pós-merge têm `interactiveMode` presente; legacy state files continuam funcionando via fallback.
- **Impacto no Negócio:** Pré-requisito técnico para Story-0068-0002 (hook). Sem este, o hook não tem como filtrar.

## 3. Contratos & Endpoints

### 3.1 Schema field

```json
{
  "flowVersion": "4",
  "epicId": "EPIC-0068",
  "interactiveMode": "non-interactive",
  "taskTracking": { "enabled": true, "phaseGateResults": [] },
  ...
}
```

### 3.2 Valores permitidos

| Valor | Quando | Fonte |
| :--- | :--- | :--- |
| `"non-interactive"` | Orquestrador invocado sem `--interactive` (default pós-EPIC-0061-0001) | Default ou flag explícita `--non-interactive` (deprecated mas equivalente) |
| `"interactive"` | Orquestrador invocado com `--interactive` ou env `CLAUDE_LEGACY_INTERACTIVE=1` | Flag explícita |

### 3.3 Rule 19 Fallback Matrix entry (NEW)

| Condition on `interactiveMode` | Resolved value | Behavior | Warning? |
| :--- | :--- | :--- | :--- |
| Field absent | `"interactive"` | Comportamento legacy preservado — hook é no-op | No |
| Field = `"interactive"` (explícito) | `"interactive"` | Hook é no-op | No |
| Field = `"non-interactive"` (explícito) | `"non-interactive"` | Hook ativo (story-0068-0002) | No |
| Field = qualquer outro valor | `"interactive"` + warning | Fallback safe | **Yes** |

### 3.4 Escrita do campo (cada orquestrador)

Cada orquestrador, na sua Phase 0 (initialization), invoca:

```text
Skill(skill: "x-internal-status-update",
      args: "--key interactiveMode --value <interactive|non-interactive>")
```

Onde `<interactive|non-interactive>` é derivado do parsing de `--interactive` flag (default = `non-interactive` pós-EPIC-0061-0001).
