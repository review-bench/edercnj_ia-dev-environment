## 1. Contexto & Escopo

Como **desenvolvedor que mantém as skills do framework**, eu quero que todas as 42 SKILL.md substituam referências a paths hardcoded (`plans/epic-`, `audits/`, `results/`, `specs/`, `adr/`, `steering/`, `contracts/`) por placeholders resolvidos em runtime via `PathResolver`, garantindo que skills funcionem corretamente tanto com layout v3 (legacy) quanto v4 (novo).

Skills são arquivos Markdown que descrevem workflows executados pelo LLM. Quando uma skill contém a string `plans/epic-XXXX/`, ela assume o layout v3. Com o novo PathResolver, as skills usam placeholders como `{{epicDir}}` que são resolvidos em runtime — ou, nas skills de implementação Java, chamadas a `PathResolver.epicDir(epicId)`.

O inventário completo de skills afetadas é gerado por grep:
```bash
grep -rnE "plans/epic-|audits/|results/|specs/|adr/|steering/|contracts/" \
  java/src/main/resources/targets/claude/skills/ --include=SKILL.md
```

Cada match é avaliado: se está em `## Triggers` ou `## Examples` (seção user-facing), é mantido como histórico/documentação. Se está no corpo de execução (fase de implementação), é substituído pelo helper correspondente.

### 1.2 Entrega de Valor

- **Valor Principal:** Skills funcionam com ambos os layouts (v3 e v4) sem configuração adicional. Zero breaking changes para operadores que têm epics legados e epics novos co-existindo.
- **Métrica de Sucesso:** `grep -rnE "plans/epic-|audits/|results/|specs/[A-Z]" java/src/main/resources/targets/claude/skills/ --include=SKILL.md | grep -v "## Triggers\|## Examples\|# legacy"` retorna 0 linhas.
- **Impacto no Negócio:** Após esta story, `/x-epic-create`, `/x-story-implement`, `/x-telemetry-analyze` e demais skills criam e leem artefatos no local correto automaticamente, sem necessitar de configuração manual por operador.

## 8. Decision Rationale

**Decisão:** Usar placeholders `{{epicDir}}` em SKILL.md ao invés de chamar PathResolver diretamente em código Java embutido nos markdowns.

**Motivo:** Skills são Markdown executados pelo LLM em runtime, não código Java. O LLM substitui `{{epicDir}}` chamando `PathResolver.epicDir(epicId)` da sua própria instância ou via Bash. Isso mantém skills legíveis sem requerer parsing de chamadas Java em Markdown.

**Alternativa descartada:** Embutir chamadas Bash `$(java -cp ... PathResolver.epicDir 0060)` inline nas skills. Descartada por acoplamento forte ao classpath Java em contexto de execução do LLM onde `java` pode não estar disponível.

**Consequência:** O LLM deve resolver os placeholders corretamente em cada invocação. Risco: se o LLM ignora o placeholder e usa string hardcoded, o teste `SkillPathResolverSmokeTest` não captura isso em runtime — apenas captura no arquivo Markdown em repositório.
