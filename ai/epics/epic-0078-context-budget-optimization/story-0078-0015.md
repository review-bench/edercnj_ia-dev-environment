## 1. Contexto & Escopo

Como **SRE / Governance**, eu quero um audit script `audit-kp-references.sh` que detecte Knowledge Packs órfãos (não referenciados por nenhuma skill via `Read <path>`), garantindo que toda migração de conteúdo rule→KP mantenha o pacto de "KPs lazy-loaded são acessíveis sob demanda" (RULE-002).

À medida que stories 0078-0005 a 0078-0012 movem conteúdo de rules para KPs sob `knowledge/{security,lifecycle,governance}/`, surge o risco de KP "morto": arquivo existe mas nenhuma skill o lê. Sem detecção mecânica, o conteúdo continua compilado/copiado mas é inacessível em runtime — pior dos mundos (carga de disco sem benefício pedagógico). Solução: audit script que para cada `.md` sob `knowledge/`, verifica via `grep -rl` em `src/main/resources/targets/claude/skills/` (source-of-truth) se ao menos uma skill referencia o caminho. CI hard-fail garante invariante.

> **Source-of-truth de scripts (RULE-009):** O `audit-kp-references.sh` vai em `src/main/resources/targets/claude/scripts/audit-kp-references.sh` (universal). NÃO criar diretamente em `scripts/` na raiz do gerador — `CiPipelineLeanSmokeIT` (RULE-007) falha.

### 1.2 Entrega de Valor

- **Valor Principal:** Garantia mecânica de que cada KP tem ≥1 consumer; bloqueia regressão silenciosa.
- **Métrica de Sucesso:** Após introdução, criar um KP órfão experimental falha CI com `KP_ORPHAN`; remover ref correspondente em uma skill faz CI falhar.
- **Impacto no Negócio:** Mantenedores recebem feedback imediato quando KPs ficam desreferenciados (típico em refactors); reduz dívida técnica oculta.

## 3. Contratos & Endpoints

### 3.1 CLI Contract

| Flag | Tipo | M/O | Descrição |
| :--- | :--- | :--- | :--- |
| `--self-check` | bool | O | Valida prerequisites (`grep`, paths existentes); exit 0 ou 2 |
| `--knowledge-root <path>` | string | O | Override default `src/main/resources/targets/claude/knowledge/` |
| `--skills-root <path>` | string | O | Override default `src/main/resources/targets/claude/skills/` |
| `--security-strict` | bool | O | Modo estrito: skills com plan tocando camada sensível (auth/persistence/network) DEVEM declarar `Read` em ≥1 KP de `knowledge/security/**`. Implementa RULE-012 do épico §6.1. |
| `--mode=full\|kp-orphan\|security-coverage\|json\|sarif` | string | O | Seleciona escopo do audit. Default `full`. `json`/`sarif` controlam formato de saída para CI. |
| `--format=json\|sarif` | string | O | Formato estruturado para integração CI (espelha contrato de `audit-context-budget.sh` da story-0078-0001). |

### 3.2 Output / Exit Codes

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `OK` | Todo KP referenciado por ≥1 skill |
| 1 | `KP_ORPHAN` | KP existe mas nenhuma skill o referencia |
| 2 | `OPERATIONAL_ERROR` | Prereqs ausentes (grep não encontrado, root path inválido, path traversal) |
| 3 | `BASELINE_CORRUPT` | Baseline de exempt-list malformada |
| 4 | `SECURITY_KP_MISSING` | `--security-strict` ativo e plan de skill toca camada sensível sem `Read knowledge/security/**` (RULE-012) |

### 3.3 Error Codes Mapeados

| HTTP Status | Error Code | Condição |
| :--- | :--- | :--- |
| N/A | `KP_ORPHAN` | `<path> não referenciado em nenhuma skill` na stderr |

### 5.2 Acceptance Criteria (Gherkin)

```gherkin
Cenario: Diretório knowledge vazio (caso degenerado)
  DADO que `knowledge/` não contém arquivos `.md`
  QUANDO `audit-kp-references.sh` executa
  ENTÃO retorna exit 0 sem warnings

Cenario: Todo KP tem referência (happy path)
  DADO que `knowledge/security/anti-patterns/j1-sql-concat.md` existe
  E `skills/x-review-qa/SKILL.md` contém `Read knowledge/security/anti-patterns/j1-sql-concat.md`
  QUANDO `audit-kp-references.sh` executa
  ENTÃO retorna exit 0

Cenario: KP órfão (cenário de erro)
  DADO que `knowledge/governance/capability-composition.md` existe
  E nenhuma skill em `skills/` faz `grep` por esse path
  QUANDO `audit-kp-references.sh` executa
  ENTÃO retorna exit 1 com mensagem `KP_ORPHAN: knowledge/governance/capability-composition.md not referenced`

Cenario: Self-check sem grep instalado (boundary)
  DADO que `grep` não está no PATH
  QUANDO `audit-kp-references.sh --self-check` executa
  ENTÃO retorna exit 2 `OPERATIONAL_ERROR: grep required`

Cenario: Path traversal em --knowledge-root (security)
  DADO que operador passa `--knowledge-root '..'`
  QUANDO `audit-kp-references.sh` executa
  ENTÃO retorna exit 2 `OPERATIONAL_ERROR: knowledge-root path traversal rejected`
  E não realiza qualquer leitura recursiva fora da raiz do projeto

Cenario: Symlink dentro de knowledge-root é rejeitado (security)
  DADO que `knowledge/security/anti-patterns/j99-evil.md` é symlink apontando para `/etc/passwd`
  QUANDO `audit-kp-references.sh` executa
  ENTÃO o arquivo é descartado da varredura (`find -type f -not -lname '*'`)
  E nenhuma `Read` por skill em path-symlink é considerada válida

Cenario: --security-strict aciona SECURITY_KP_MISSING (RULE-012)
  DADO que `--security-strict` está ativo
  E `skills/x-some-auth-skill/plan-task-...md` declara escrita em `adapter.inbound.security.*`
  E nenhum `Read knowledge/security/**` aparece na skill ou em seu plano
  QUANDO `audit-kp-references.sh --security-strict` executa
  ENTÃO retorna exit 4 `SECURITY_KP_MISSING: skill x-some-auth-skill touches sensitive layer without security KP Read`

Cenario: Audit executa dentro do SLO de performance
  DADO que o repositório contém 15 KPs e 40+ SKILL.md files
  QUANDO executo `audit-kp-references.sh` (modo completo)
  ENTÃO exit code é 0
  E tempo de execução total é <3s (P99) medido via `time`
```

## 8. Decision Rationale

**Decisão:** Audit script Bash + Java test wrapper (Camada 2 + 3 do Rule 26).
**Motivo:** Bash permite `grep -rl` rápido e legível para mantenedores; Java wrapper garante execução em `mvn verify` (RULE-007 EPIC-0061).
**Alternativa descartada:** Implementar detecção apenas em Java (sem script Bash). Rejeitado: operadores em CLI/dev local preferem script direto; duplicação de "audit Bash + Java test" é convenção do projeto (Rule 26).
**Consequência:** Manutenção dual (Bash + Java) — mitigado por Java test apenas invocar o script.
