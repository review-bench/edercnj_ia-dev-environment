## 1. Contexto & Escopo

Como **SRE / Governance**, eu quero um audit script `audit-kp-references.sh` que detecte Knowledge Packs órfãos (não referenciados por nenhuma skill via `Read <path>`), garantindo que toda migração de conteúdo rule→KP mantenha o pacto de "KPs lazy-loaded são acessíveis sob demanda" (RULE-002).

À medida que stories 0078-0005 a 0078-0012 movem conteúdo de rules para KPs sob `knowledge/{security,lifecycle,governance}/`, surge o risco de KP "morto": arquivo existe mas nenhuma skill o lê. Sem detecção mecânica, o conteúdo continua compilado/copiado mas é inacessível em runtime — pior dos mundos (carga de disco sem benefício pedagógico). Solução: audit script que para cada `.md` sob `knowledge/`, verifica via `grep -rl` em `src/main/resources/targets/claude/skills/` (source-of-truth) se ao menos uma skill referencia o caminho. CI hard-fail garante invariante.

> **Source-of-truth de scripts (RULE-009):** O `audit-kp-references.sh` vai em `src/main/resources/targets/claude/scripts/audit-kp-references.sh` (universal). NÃO criar diretamente em `scripts/` na raiz do gerador — `CiPipelineLeanSmokeIT` (RULE-007) falha.

### 1.2 Entrega de Valor

- **Valor Principal:** Garantia mecânica de que cada KP tem ≥1 consumer; bloqueia regressão silenciosa.
- **Métrica de Sucesso:** Após introdução, criar um KP órfão experimental falha CI com `KP_ORPHAN`; remover ref correspondente em uma skill faz CI falhar.
- **Impacto no Negócio:** Mantenedores recebem feedback imediato quando KPs ficam desreferenciados (típico em refactors); reduz dívida técnica oculta.

## 3. Contratos & Endpoints

### 3.1 CLI Contract

| Flag | Tipo | M/O | Descrição |
| :--- | :--- | :--- | :--- |
| `--self-check` | bool | O | Valida prerequisites (`grep`, paths existentes); exit 0 ou 2 |
| `--knowledge-root <path>` | string | O | Override default `src/main/resources/targets/claude/knowledge/` |
| `--skills-root <path>` | string | O | Override default `src/main/resources/targets/claude/skills/` |

### 3.2 Output / Exit Codes

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `OK` | Todo KP referenciado por ≥1 skill |
| 1 | `KP_ORPHAN` | KP existe mas nenhuma skill o referencia |
| 2 | `OPERATIONAL_ERROR` | Prereqs ausentes (grep não encontrado, root path inválido) |

### 3.3 Error Codes Mapeados

| HTTP Status | Error Code | Condição |
| :--- | :--- | :--- |
| N/A | `KP_ORPHAN` | `<path> não referenciado em nenhuma skill` na stderr |

## 8. Decision Rationale

**Decisão:** Audit script Bash + Java test wrapper (Camada 2 + 3 do Rule 26).
**Motivo:** Bash permite `grep -rl` rápido e legível para mantenedores; Java wrapper garante execução em `mvn verify` (RULE-007 EPIC-0061).
**Alternativa descartada:** Implementar detecção apenas em Java (sem script Bash). Rejeitado: operadores em CLI/dev local preferem script direto; duplicação de "audit Bash + Java test" é convenção do projeto (Rule 26).
**Consequência:** Manutenção dual (Bash + Java) — mitigado por Java test apenas invocar o script.
