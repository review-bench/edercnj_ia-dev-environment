## 1. Contexto & Escopo

Como **Architect**, eu quero adicionar declarações explícitas `Read <kp-path>` em todas as skills que consomem detalhes hoje embutidos nas rules a serem reduzidas, garantindo que nenhuma skill perca acesso a exemplos/matrizes/BNF/decision-trees após o slim.

Esta é a **história gating de toda a fase de slimming** (RULE-007). Sem ela, reduzir rules implica perda silenciosa de contexto operacional — o LLM da skill consumidora não saberia onde buscar o detalhe. Por isso, deve ser concluída antes de stories 0078-0005 a 0078-0009 e 0078-0011/0078-0012.

### 1.1 Regras Transversais Aplicáveis

| ID | Título |
| :--- | :--- |
| RULE-007 | Skills consumidoras de KP MUST declarar `Read <path>` |

### 1.2 Entrega de Valor

- **Valor Principal:** Pré-requisito de slimming. Garante que nenhuma skill perca acesso a detalhe operacional.
- **Métrica de Sucesso:** Smoke test verifica para cada KP planejado que ≥1 skill contém `Read <kp-path>`.
- **Impacto no Negócio:** Habilita as 7 stories de slim (5/6/7/8/9/11/12) sem regressão funcional.

## 8. Decision Rationale

**Decisão:** Esta história é gating absoluto para todas as 7 stories de slim.
**Motivo:** Sem `Read` explícito, slim significa perda silenciosa de contexto. RULE-007 do épico codifica essa precedência.
**Alternativa descartada:** Adicionar `Read` no mesmo PR de cada slim (acoplamento). Rejeitado: aumenta risco de regressão por skill, dificulta rollback.
**Consequência:** PR desta história lista 8-15 SKILL.md tocados de uma vez. Reviewer paga custo concentrado, mas slim subsequente fica trivial.

### 8.1 Risk & Rollback Plan

**Risco principal:** Skill ganha `Read` apontando para KP ainda não merged → audit falha com `KP_READ_MALFORMED` ou `KP_NOT_FOUND` no PR de slim subsequente, bloqueando lifecycle.

**Mitigação:**
1. Story-0078-0010 é gating de stories 0005-0009/0011/0012 — KPs DEVEM existir antes do slim das rules.
2. `KpReadDirectiveAuditorTest` (TASK-004) detecta KP órfão antes do merge.

**Rollback procedure:**
- Caso a SKILL.md gain um Read pointing to KP not yet merged (ordem de merge incorreta), revert via:
  ```bash
  git revert <skill-update-commit>
  ```
- **Forbidden:** `git commit --amend` (Rule 27 — sem skip de hooks). Reverts geram novo commit auditável.
- Após revert, abrir nova PR ajustando a ordem (criar KP primeiro, depois skill update).
