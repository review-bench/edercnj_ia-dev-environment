## 1. Contexto & Escopo

Como **Architect**, eu quero migrar todos os YAML examples (a-d), capability ID format details, e glob rules de `Rule 28 — Capability Frontmatter Contract` para um KP `knowledge/governance/capability-composition.md`, mantendo na Rule 28 reduzida (≤60 linhas) os 8 Invariants, Forbidden list, tabela de Audit (6 scripts) e link para o KP.

A `Rule 28` atual carrega ~180 linhas com 4 YAML examples extensos (skill condicional, rule fragmentada, composite skill, agent condicional), formato `category.subcategory.atomic`, glob rules com prefixos válidos/inválidos. Esse conteúdo é referência operacional consumida apenas pela skill `x-frontmatter-migrate` e por autores de novos artefatos — economiza ~2.5k tokens always-loaded ao migrar.

A `Rule 28` final mantém: 8 Invariants (numerados, contrato), Forbidden, Permitted, Audit table (6 scripts × validação × exit), Self-Audit, link para KP. O KP recebe os 4 YAML examples completos, capability ID format, glob rules detalhadas, migration notes.

## 8. Decision Rationale

**Decisão:** Manter os 8 Invariants completos na Rule 28 mesmo após slim, ao invés de migrar parte para o KP.
**Motivo:** Invariants são o contrato normativo — audits enforcem cada um por número (e.g., "Invariant 4 — Excludes simétrico"). Mover quebraria rastreabilidade.
**Alternativa descartada:** Reduzir Invariants a 1-line e expandir no KP. Rejeitado: contrato precisa estar inteiro na rule.
**Consequência:** Rule 28 fica ~60 linhas (vs ~40 ideal). Aceitável dado que invariants são curtos (1-2 linhas cada).
