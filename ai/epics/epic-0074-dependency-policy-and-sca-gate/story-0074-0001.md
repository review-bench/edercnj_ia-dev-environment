## 2. Entrega de Valor

- **Valor primário:** schema executável (validado em build via `governance/schemas/`) substitui o "policy declarativo em README" pelo contrato de máquina.
- **Valor secundário:** capability families permitem skills downstream (`x-dep-policy-validate`, futuras `x-license-check`, etc.) ramificarem por build tool sem hardcode.
- **Valor terciário:** Rule + ADR fixam o invariant "policy ausente ≠ policy permissive" (default=disabled, sem fallback silencioso).
- **Métrica primária:** capability YAML + Rule .md + ADR .md + KP .md publicados em commit único; `mvn verify` verde (`Epic0064SmokeIT` valida frontmatter v3.0 dos 4 artefatos novos).
- **Métrica secundária:** schema YAML rejeita ≥ 5 inputs malformados em testes parametrizados (sintaxe ambígua D-R9, scope inexistente D-R11, block-on enum inválido D-R10).

## 6. Decision Rationale

**Decisão:** sub-bloco `dependencies.policy` no YAML principal (single file). **Motivo:** YAML do projeto é a single source of truth da configuração; arquivo dedicado (`dependency-policy.yaml`) cria duas fontes propensas a drift. **Alternativa descartada:** arquivo dedicado por build tool. Rejeitada — viola DRY do YAML, complica `DocsAssembler`, fragmenta visão. **Consequência:** YAML cresce (~30-40 linhas para policy completa), mas agrupamento sob `dependencies:` mantém leitura.

## 7. Refinement Notes (consolidadas)

- **Cross-stack syntax (D-R9):** três formatos disjuntos validados via `oneOf` no schema JSON-Schema. KP documenta com exemplo de cada (Maven `<dependency>`, Gradle `implementation`, npm `package.json`, pip `requirements.txt`, go.mod `require`).
- **Defaults `block-on` (D-R10):** matriz pinada no schema — `severity-cve: HIGH` (block), `license: any-violation` (block), `min-version: any-violation` (block), `max-version: warn-only`, `freshness: warn-only`, `denied-cves: hard-block` (sempre, RULE-074-01 inegociável). Operador override total via YAML.
- **Scope (D-R11):** enum `{compile, runtime, test, provided, dev, build}`; default policy aplica em `compile`+`runtime`, scopes `test`/`dev` recebem `warn-only` por default.
- **Capability hierarchy:** mãe `governance.dependency-policy` é universal (`requires-capabilities: []`); sub-families `governance.dependency-policy.<tool>` declaram `requires-capabilities: [build-tool.<tool>]` para parametrização condicional via Rule 28 §Composition.
