# História: Skill `/x-pentest-dynamic` (tier smoke + full) + template + KP DAST

**ID:** story-0073-0003
**Status:** Refinada
**Refinement Verdict:** approved

## 1. Visão

Como **security guardian**, quero a skill `/x-pentest-dynamic` com dois tiers de profundidade:

- **`--smoke`** (default — roda em PR via `dast-smoke.yml`): ZAP passive scan + Nuclei lightweight templates (top-50 CVE templates curados). Tempo-alvo 2-3min. Gate de PR.
- **`--full`** (nightly via `dast-full.yml`): ZAP active scan completo (envia payloads de injection/XSS/path-traversal) + Nuclei full templates + custom payloads conforme `security.compliance` declarada (PCI/LGPD specific). Tempo 10-15min. **Informativo (não-gate de PR)**.

…produzindo SARIF 2.1.0 + relatório Markdown navegável em `results/security/dast/dast-{smoke|full}-YYYY-MM-DD.md`.

## 2. Entrega de Valor

- **Valor primário:** vulnerabilidades DAST-detectáveis ganham gate sintético em PR (smoke) e profundidade nightly (full) — antes desta story, `x-security-pipeline` cobre apenas ZAP **passive** (read-only).
- **Valor secundário:** SARIF 2.1.0 padronizado integra com GitHub Security tab + Defender/Snyk/etc consumidores SARIF — investimento de findings reaproveitado.
- **Métrica primária:** ≥ 1 finding HIGH/CRITICAL detectado e mitigado nos 3 primeiros projetos pós-rollout (sinal de "DAST está rodando, não só configurado").
- **Métrica secundária:** zero false-positive HIGH/CRITICAL reportado pela equipe em sprint 1 pós-rollout (template Nuclei v9.x curado tem boa sinalização — checar).
- **Métrica terciária:** smoke tier executa em < 5min P95 (gate de PR aceitável).

## 3. Acceptance Criteria (Gherkin — 4 categorias mandatórias)

```gherkin
Cenario: Happy — smoke tier detecta Reflected XSS em PR
  DADO PR muda endpoint que reflete user input sem encode
  E quality.dast.target=local-container e docker-compose.yml está up
  QUANDO /x-pentest-dynamic --smoke roda
  ENTÃO ZAP passive (apenas observa tráfego) + Nuclei lightweight (top-50 CVE) executam
  E finding HIGH "Reflected XSS" detectado pelo Nuclei template `xss-reflected`
  E SARIF 2.1.0 emitido em results/security/dast/dast-smoke-YYYY-MM-DD.sarif
  E Markdown report em results/security/dast/dast-smoke-YYYY-MM-DD.md (template _TEMPLATE-PENTEST-PLAN.md)
  E exit 1 (DAST_FINDING_HIGH) — gate falha em PR

Cenario: Happy — full tier diferenciado encontra finding active-only
  DADO cron nightly dispara dast-full.yml
  E target staging acessível
  QUANDO skill roda --full
  ENTÃO ZAP active (envia payloads SQLi/XSS/path-traversal) + Nuclei full templates rodam (10-15min wall)
  E findings adicionais (NÃO detectáveis por smoke passive) são reportados — exemplo: SQL Injection blind detectado por payload time-based
  E NÃO bloqueia merge (modo nightly = informativo)
  E artifact retido por 30 dias para review humano

Cenario: Degenerate — opt-out via YAML
  DADO projeto declara quality.dast.enabled=false (opt-out explícito)
  QUANDO PR é aberto e dast-smoke.yml dispara
  ENTÃO workflow detecta flag e emite "DAST_DISABLED — skipping (opt-out)" no log
  E exit 0 (no-op)
  E nenhum SARIF é gerado

Cenario: Error — DAST target indisponível
  DADO quality.dast.target=local-container
  E docker-compose.yml não existe OU container não sobe
  QUANDO skill --smoke roda
  ENTÃO erro DAST_TARGET_UNREACHABLE é emitido
  E mensagem orienta troubleshooting (verificar `docker-compose ps`, verificar porta exposed)
  E exit 2 (OPERATIONAL_ERROR — não é bug do código sob teste)

Cenario: Boundary — Nuclei templates pinned version conflita com tooling
  DADO quality.dast.nuclei.templates-version=v9.0.0 (pin estrito)
  E Nuclei runtime instalado é v8.x
  QUANDO skill --smoke roda
  ENTÃO erro DAST_NUCLEI_VERSION_MISMATCH é emitido com sugestão de upgrade
  E exit 2 (OPERATIONAL_ERROR)

Cenario: Boundary — full tier cap de runtime
  DADO --full roda em projeto com 200+ endpoints
  QUANDO 30min de wallclock se passam
  ENTÃO skill aborta com DAST_FULL_TIMEOUT
  E SARIF parcial é emitido com findings já coletados
  E sumário lista quais endpoints NÃO foram cobertos (transparência)
  E artifact ainda é uploaded
```

## 6. Decision Rationale

**Decisão:** tier dual numa skill (`--smoke` + `--full`). **Motivo:** análogo ao `--self/--service` da regression-shell — lógica compartilhada de SARIF render + report Markdown ~50% do código. **Alternativa descartada:** 2 skills (`x-pentest-smoke`, `x-pentest-full`). **Consequência:** SKILL.md mais compacto, mas dois fluxos distintos no Phase 2 dispatch.

**Decisão complementar:** **DAST é CI-only**, NÃO em Phase 3 do `x-story-implement`. **Motivo:** Phase 3 roda na máquina do dev (Claude Code); DAST exige target ambiente rodando (preview env, staging, local-container). Forçar isso em Phase 3 seria inviável para >70% dos projetos. **Alternativa descartada:** DAST em Phase 3 com docker-compose local up automático. **Rejeitado por:** complexidade alta + dependência de Docker no host do dev. **Consequência:** DAST está fora da invocação MANDATORY conditional do `x-story-implement` (story-0073-0007); ele entra via CI (stories 0073-0005 / 0073-0006). Skill é user-invocável manualmente para troubleshooting de findings.

**Decisão complementar:** SARIF 2.1.0 (não 2.0). **Motivo:** GitHub Security tab espera 2.1.0; tooling moderno (Snyk, Defender) idem. **Alternativa descartada:** Markdown-only sem SARIF. **Rejeitado por:** inviabiliza integração com GitHub Security tab — perda de valor secundário grande.

## 7. Refinement Notes (consolidadas)

- **ZAP target selection (D-R9):** workflow injeta env-var `DAST_TARGET_URL`; skill usa este valor como `-target=` para ZAP/Nuclei. Para `local-container`, workflow faz `docker-compose up` antes de invocar skill (timeout 60s para healthy). Para `preview-env`, workflow upstream emite URL via output. Para `staging`, URL é fixa em secret `STAGING_BASE_URL`.
- **Nuclei templates pinning (D-R8):** `quality.dast.nuclei.templates-version: v9.x` é o default permitido (faixa). Pin estrito `v9.0.0` é opt-in para reprodutibilidade máxima. Upgrade de major (v9 → v10) **sempre** via PR explícito em `setup-config.yaml` + smoke test rerun.
- **Active scan policy (D-R9 stretch):** `quality.dast.zap.active-scan-policy: default | custom-pci | custom-lgpd`. Custom policies vivem em `java/src/main/resources/targets/claude/security/zap-policies/<name>.policy` (XML do ZAP). PCI policy desabilita testes destructivos em endpoints de payment; LGPD adiciona testes de PII leak.
- **Findings policy:** smoke tier emite **HIGH/CRITICAL como gate** (exit 1 falha PR). LOW/MEDIUM são reportados mas não bloqueiam (exit 0). Full tier emite **tudo informativo** (exit 0 sempre — gate é semantic, não syntactic). Decisão registrada no ADR de story-0073-0001.
