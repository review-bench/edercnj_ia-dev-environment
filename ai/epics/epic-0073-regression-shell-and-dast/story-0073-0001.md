## 6. Decision Rationale

**Decisão:** publicar 5 capability files atomic em vez de 1 bundle. **Motivo:** glob `quality.dast.*` em frontmatter + composição parcial (projeto pode ter ZAP sem Nuclei). **Alternativa descartada:** capability única `quality.regression-and-dast` — rejeitado pelo princípio Rule 28 §Capability ID válido (`category.subcategory.atomic`). **Consequência:** 5 arquivos pequenos em vez de 1 grande; permite skills declararem `requires-capabilities: [quality.dast.zap-active.*]` quando lógica é específica para active scan.

**Decisão complementar:** dispensar Rule nova (default D-R3). **Motivo:** Rules 06 + 24 + 26 + 28 cobrem Security Baseline / Execution Integrity / Audit Lifecycle / Frontmatter; um épico de DAST/regression não introduz invariantes normativos novos que não caibam em capability + ADR + script. **Critério de inversão:** ≥ 2 invariantes não cobertas pelas Rules existentes → publicar Rule nova com NN TBD. **Consequência:** menos rules para manter; mais atrito quando time precisa de governança DAST específica futura (ADR + capability será atualizado, não uma Rule).
