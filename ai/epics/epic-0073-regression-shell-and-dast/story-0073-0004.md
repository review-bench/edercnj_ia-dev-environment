# História: `tests/regression/scenarios.yaml.template` stack-aware + integração `ScriptsAssembler`

**ID:** story-0073-0004
**Status:** Refinada
**Refinement Verdict:** approved

## 1. Visão

Como **time recebendo o CLI**, quero que projetos novos sejam gerados com um `tests/regression/scenarios.yaml` skeleton **stack-aware** — um cenário exemplo por interface declarada em `interfaces[]` (cURL para REST, grpcurl para gRPC, wscat para Socket) — para que o time tenha um harness funcional pronto a customizar e não invente "cada um o seu smoke YAML".

## 2. Entrega de Valor

- **Valor primário:** o time recebe harness pronto + 1 cenário smoke executável, eliminando a fricção "qual schema usar?".
- **Valor secundário:** consistência cross-projeto — todos os times usam o mesmo formato `scenarios.yaml`, o que torna os logs do `/x-test-regression-shell --service` comparáveis e evolutivos.
- **Métrica primária:** 100% dos projetos gerados pós-rollout (`ia-dev-env generate`) têm `tests/regression/scenarios.yaml` quando `interfaces[]` declarado e `quality.regression.enabled` não é `false`.
- **Métrica secundária:** ≥ 70% dos projetos pós-rollout ampliam o skeleton com ≥ 3 cenários customizados em sprint 1 (sinal de adoção real, não scaffolding zumbi).

## 3. Acceptance Criteria (Gherkin — 4 categorias mandatórias)

```gherkin

  DADO YAML projeto declara interfaces=[rest, grpc]
  E quality.regression.enabled é absent (default true)
  QUANDO ia-dev-env generate roda
  ENTÃO tests/regression/scenarios.yaml é criado
  E contém ≥ 1 cenário rest (cURL) com endpoint /health placeholder
  E contém ≥ 1 cenário grpc (grpcurl) com método HealthCheck placeholder
  E header explicativo (5-10 linhas) cita /x-test-regression-shell e link para KP regression-shell-playbook
  E formato YAML valida contra schema implícito de `_TEMPLATE-REGRESSION-SHELL.md` (story-0073-0002)

  DADO YAML projeto declara interfaces=[cli]
  QUANDO ia-dev-env generate roda
  ENTÃO tests/regression/scenarios.yaml é criado com 0 cenários executáveis
  E contém comentário "Projeto CLI: regressão shell roda em modo --self automaticamente; este arquivo serve para cenários auxiliares"
  E não emite WARN (caso esperado)

Cenario: Degenerate — interfaces[] vazio
  DADO YAML projeto não declara interfaces[]
  QUANDO ia-dev-env generate roda

  DADO YAML projeto declara quality.regression.enabled=false
  QUANDO ia-dev-env generate roda
  ENTÃO tests/regression/scenarios.yaml NÃO é criado
  E sumário de generate emite "regression-shell: disabled (opt-out)"
  E exit 0

Cenario: Boundary — projeto existente NÃO é overwritten
  DADO projeto já existe e contém tests/regression/scenarios.yaml customizado pelo time
  QUANDO ia-dev-env generate roda em modo update (não-overwrite)
  ENTÃO arquivo existente é preservado
  E sumário emite "regression-shell scenarios.yaml already exists — preserved"
  E nenhum diff é gerado

Cenario: Boundary — força sobrescrever via flag explícita
  DADO projeto já existe com scenarios.yaml customizado
  QUANDO ia-dev-env generate roda com --force-regen-regression-scenarios (flag opt-in destrutiva)

  DADO YAML projeto declara interfaces=[rest, grpc] com quality.regression habilitado
  QUANDO ia-dev-env generate roda
  ENTÃO renderização do scenarios.yaml (template + snippets) completa em ≤ 5s
  E tempo total de generate não regride > 10% vs baseline sem regression habilitado

Cenario: Security — template rendering não injeta secrets do ambiente no output
  DADO ambiente host tem variáveis sensíveis (DB_PASSWORD, API_KEY)
  E template usa placeholders Mustache ({{PROJECT_NAME}}, {{INTERFACE_REST_BLOCK}})
  QUANDO ScriptsAssembler.renderRegressionScenarios() executa
  ENTÃO scenarios.yaml output contém APENAS tokens do ProjectConfig (nenhum env var do host)
  E grep -E "(DB_PASSWORD|API_KEY|SECRET)" no output retorna zero matches
  E placeholders não resolvidos ({{...}} residuais) são ausentes
```

## 6. Decision Rationale

**Decisão:** skeleton + 1 cenário exemplo por interface (não autopop com cenários por endpoint). **Motivo:** autopop exige conhecer endpoints — informação ausente no YAML do gerador (vive na implementação). Skeleton + comentário pedagógico maximiza adoção sem prometer mais do que o gerador sabe. **Alternativa descartada:** parsing OpenAPI/proto para autopop. **Rejeitado por:** dependência de spec presente + falsos positivos (specs frequentemente desatualizadas em projetos reais). **Consequência:** time edita o arquivo manualmente (esperado e desejado); skill `--service` valida que ≥ 1 cenário existe antes de rodar.

**Decisão complementar:** preservar arquivo existente por default; flag opt-in `--force-regen-regression-scenarios` para sobrescrever. **Motivo:** customização do time é alto-investimento; perder em regen seria fricção máxima. **Alternativa descartada:** overwrite sempre. **Rejeitado por:** desconfiança imediata de generate. **Consequência:** lógica simétrica a outros arquivos preservados (`docs/architecture/system.md` em EPIC-0070, `.env.example` herdado).
