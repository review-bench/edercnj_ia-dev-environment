## 1. Contexto & Escopo

Como **QA Engineer**, eu quero um teste E2E `Epic0063LocalFirstSmokeTest` que cria fake story em sandbox e exercita os 5 cenários completos do AC12 do épico (push sem review, push com stub, push com review real, PR sem epic review, recovery mode), validando ponta-a-ponta que toda a Camada 0 funciona como esperado.

Este teste é o **gate final** do épico: se ele falha, o épico não pode ser mergeado para develop. É a última história em ordem topológica e bloqueada por todas as anteriores. É também um exemplo executável dos contratos definidos pelas demais stories.

Os 5 cenários (AC12 do épico, FR20 do SPEC):

1. **Push sem reviews** — sandbox cria fake story; tenta `git push` SEM review-story-*.md → hook exit `2` (BLOCKED) e stderr contém `REVIEW_CONTENT_INSUFFICIENT` (preflight gate 3 falhou)
2. **Push com reviews stub** — cria reviews stub (< 50 linhas, sem decisão) → hook exit `2` e stderr contém `REVIEW_CONTENT_INSUFFICIENT`
3. **Push com reviews completos + telemetry** — cria reviews legítimos + appenda eventos NDJSON → hook exit `0` (preflight green)
4. **PR sem epic-level review** — try `gh pr create --base develop` SEM review-epic-*.md → hook exit `2` e stderr contém `REVIEW_CONTENT_INSUFFICIENT` ou `TELEMETRY_EVIDENCE_MISSING` (gate 3 ou 4)
5. **CLAUDE_RECOVERY_MODE=1** — repete cenário 1 com env var set → hook exit `0` + stderr contém `WARN [recovery_mode]` + evento `recovery_mode_used` no NDJSON

> **Distinção exit code hook vs preflight gate:** o **hook** PreToolUse usa exclusivamente `0` (OK) ou `2` (BLOCKED) conforme contrato Claude Code. A causa do bloqueio (qual preflight gate falhou — códigos 1-12 conforme §3.2 da story-0063-0001) é surfaced via stderr com formato estruturado `PREFLIGHT_FAILED: <CODE> — ...`. Cenários assertam ambos: o exit do hook (process exit) e o conteúdo da mensagem em stderr (gate específico).

Implementação em Java JUnit 5 (alinhamento com codebase existente — `LifecycleIntegrityAuditTest`, `Epic0058Rule26SmokeTest`). Sandbox é diretório temp com fake git repo + fake jacoco + fake NDJSON. Hook é invocado em-process via `ProcessBuilder`. Exit codes verificados.

```java
private int invokeHook(Path sandbox, String toolCommand, Map<String, String> env) {
  String hookInput = """
      {"tool_name": "Bash", "tool_input": {"command": "%s"}}
      """.formatted(toolCommand);

  ProcessBuilder pb = new ProcessBuilder(
      sandbox.resolve(".claude/hooks/enforce-preflight-gates.sh").toString());
  pb.directory(sandbox.toFile());
  pb.environment().putAll(env);

  Process p = pb.start();
  p.getOutputStream().write(hookInput.getBytes());
  p.getOutputStream().close();
  return p.waitFor();
}
```

## 8. Decision Rationale

**Decisão:** Java JUnit 5 ao invés de bash test (bats).
**Motivo:** Codebase existente usa Java/JUnit (`LifecycleIntegrityAuditTest`, `Epic0058Rule26SmokeTest`). Consistency. CI integration via `mvn verify` é mais limpa.
**Alternativa descartada:** Bash bats. Rejeitado por inconsistency com codebase.
**Consequência:** Test invoca shell scripts via ProcessBuilder. Mitigação: helper class `ShellHookInvoker` encapsula complexidade.

**Decisão:** Sandbox isolado via `@TempDir` ao invés de docker container.
**Motivo:** Docker adiciona ~15s overhead por test (5 tests = 75s extras). TempDir + `git init` é < 1s.
**Alternativa descartada:** Docker container com setup completo. Rejeitado por overhead.
**Consequência:** Sandbox compartilha host filesystem (não totalmente isolado de side effects). Mitigação: hook lê apenas paths derivados do sandbox; não modifica host.

**Decisão:** Fake jacoco.csv ao invés de mvn test real.
**Motivo:** mvn test real adiciona ~30s+ por test. Fake CSV é deterministic e testa apenas o parsing (não jacoco em si).
**Alternativa descartada:** mvn test real em sandbox. Rejeitado por overhead.
**Consequência:** Test valida hook + preflight + audits, NÃO o pipeline mvn completo. Aceito (smoke test é integration, não end-to-end full).
