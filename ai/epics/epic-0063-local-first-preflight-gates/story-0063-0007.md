## 1. Contexto & Escopo

Como **Quality Gate Owner**, eu quero um script `scripts/audit-coverage-local.sh` que parsea `target/site/jacoco/index.html` (ou jacoco.csv) e valida ≥95% line / ≥90% branch coverage localmente, garantindo que o gate de cobertura execute antes de qualquer push (FR4 do SPEC, AC7 do épico).

Hoje a validação de coverage é feita pela CI gate (`Build + verify`), descobrindo `COVERAGE_BELOW_THRESHOLD` apenas após push. Camada 0 exige validação local-first: `audit-coverage-local.sh` é invocado por `preflight.sh` como gate 3 e por `enforce-preflight-gates.sh` (via preflight) antes de `git push`.

O script implementa Rule 26 contract (`audit-*.sh` prefix, exit codes 0..3, `--self-check`). Parsea o arquivo HTML do JaCoCo extraindo "Total" row (line/branch percentages), aplica thresholds (default 95/90, override via `--line-min` / `--branch-min`), retorna exit 0 (OK) ou 1 (`COVERAGE_BELOW_THRESHOLD`). Suporta `--report-path` para customizar (default `target/site/jacoco/index.html`).

Modo `--changed-only` filtra coverage apenas para arquivos modificados pela story (via `git diff`), oferecendo gate mais rápido para SIMPLE scope. Default é coverage global do projeto (Rule 05 absolute gate).

### 3.2 Response

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `OK` | line ≥ line-min AND branch ≥ branch-min |
| 1 | `COVERAGE_BELOW_THRESHOLD` | line < line-min OR branch < branch-min |
| 2 | `OPERATIONAL_ERROR` | jacoco report ausente OR pup/sed/awk ausente |
| 3 | `INVALID_ARGS` | argv malformados |

stderr format: `COVERAGE_FAIL: line=85.3% min=95.0% branch=78.1% min=90.0% — fix: add tests`

### 3.3 Parsing strategy

JaCoCo HTML format (Total row in main table). Para portabilidade preferimos `jacoco.csv` se presente:

```bash
# CSV header: GROUP,PACKAGE,CLASS,INSTRUCTION_MISSED,INSTRUCTION_COVERED,...,LINE_MISSED,LINE_COVERED,...,BRANCH_MISSED,BRANCH_COVERED
awk -F, 'NR>1 { lm+=$8; lc+=$9; bm+=$13; bc+=$14 } END { printf "%.1f %.1f", lc*100/(lm+lc), bc*100/(bm+bc) }' target/site/jacoco/jacoco.csv
```

Fallback HTML parsing via `grep -oP` para casos sem CSV.

## 8. Decision Rationale

**Decisão:** AWK para CSV parsing ao invés de jq ou regex puro.
**Motivo:** AWK é nativo POSIX, fast, com strong CSV semantics. jq não é ideal para CSV. Regex puro é frágil para floats.
**Alternativa descartada:** Reuse de class Java `JaCoCoCsvParser`. Rejeitado por adicionar JVM startup ao path crítico (~3s overhead).
**Consequência:** Lógica duplicada com possíveis classes Java existentes. Mitigação: extração para shared lib em epic futuro se ambiente justifica.
