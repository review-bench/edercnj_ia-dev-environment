## 1. Contexto & Escopo

Como **Tech Lead**, eu quero scripts `audit-review-content.sh` e `audit-verify-envelope.sh` que rejeitam reviews stub e envelopes placeholder por heurística sintática, garantindo que arquivos de evidência tenham conteúdo mínimo verificável.

Os 8 stubs do EPIC-0062 motivam esta história: `review-story-0062-XXXX.md` com 2 linhas (`Verdict: GO\n`), `verify-envelope-0062-XXXX.json` com 5 campos fixos, todos passaram a Camada 3 atual porque `audit-execution-integrity.sh` valida apenas presença. As novas auditorias aplicam heurística sintática (não-LLM) que pega ~80% dos stubs medidos contra o baseline EPIC-0062: ≥50 linhas não-vazias, ≥3 seções H2/H3, ≥2 refs a arquivos do diff via `grep -E "[a-z/]+\.(java|md|sh)"`, decisão GO/NO-GO/GO-WITH-RESERVATIONS presente, frontmatter `generated-by: <skill>@<sha>`.

`audit-verify-envelope.sh` valida o JSON: `failures` é array (não null nem string), `acCheckResults` ≥ N entradas se `passed=true`, coverage values numéricos, timestamp ISO 8601 válido. Ambos suportam marker `<!-- audit-exempt-content: <reason> -->` para SCOPE=SIMPLE legítimos com <50 linhas. Self-check obrigatório (Rule 26). Exit codes 0/1/2/3 conforme Rule 26 §Standardized Exit Codes.

### 3.2 Response (CLI exit codes)

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `OK` | Conteúdo válido |
| 1 | `REVIEW_CONTENT_INSUFFICIENT` (review audit) ou `ENVELOPE_SCHEMA_INVALID` (envelope audit) | Heurística falha |
| 2 | `OPERATIONAL_ERROR` | jq, grep, wc ausente |
| 3 | `BASELINE_CORRUPT` ou `INVALID_EXEMPTION` | baseline malformado |

### 3.3 Heurísticas (review content)

| Critério | Threshold | Escape |
| :--- | :--- | :--- |
| Linhas não-vazias | ≥ 50 | `<!-- audit-exempt-content: <reason> -->` |
| Seções H2/H3 | ≥ 3 (ex: `## Findings`, `## Decision`, `## Per-file observations`) | mesmo marker |
| Refs a arquivos do diff | ≥ 2 (`grep -E "[a-z/]+\.(java|md|sh)"`) | mesmo marker |
| Decisão presente | grep `(GO|NO-GO|GO-WITH-RESERVATIONS)` | obrigatório, sem escape |

> **Removido na refinement.** Heurística `frontmatter generated-by` foi cortada — exigiria modificar x-review/x-review-pr para emitir o frontmatter, fora do escopo desta story. Tier-2 backlog: heurística ML-based (densidade de termos técnicos, similaridade contra reviews legítimos históricos).

### 3.4 Heurísticas (verify envelope)

| Critério | Threshold | Escape |
| :--- | :--- | :--- |
| Campo `failures` é array | `jq 'type == "array"'` | sem |
| Se `passed=true`, `acCheckResults.length >= ac-count` | jq length | sem |
| Coverage values numéricos quando presentes | `jq '.coverage.line | type == "number"'` | sem |
| Timestamp ISO 8601 | regex `^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}` | sem |

### 3.5 `--ac-count` derivation

Quando `--ac-count` não é passado, audit deriva automaticamente:

```bash
story_md="ai/epics/epic-${epic_id}-*/story-${story_id}.md"
ac_count=$(awk '/^## 5\.2 Acceptance Criteria/,/^## /' $story_md | grep -c "^Cenario:")
```

Conta blocos `Cenario:` dentro da seção `## 5.2 Acceptance Criteria` (até próxima H2). Layout v3 usa `plans/epic-XXXX/story-*.md`; PathResolver decide. Se story.md não-encontrada → exit 2 OPERATIONAL_ERROR.

## 8. Decision Rationale

**Decisão:** Heurísticas independentes (linhas, seções, refs) ao invés de score único composto.
**Motivo:** Score composto é black-box; heurísticas independentes geram mensagens de erro precisas ("linhas=12 < 50" vs "score=0.3 < 0.7").
**Alternativa descartada:** ML-based classifier treinado em reviews históricos. Rejeitado por overhead de treino + inferência adiciona ~5s ao audit.
**Consequência:** Heurísticas calibradas conservativamente. Iteração futura pode adicionar densidade de termos técnicos (Rule 24 anti-stub backlog).
