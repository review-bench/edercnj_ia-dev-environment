## 1. Contexto & Escopo

Como **Operator/LLM**, eu quero que `x-pr-fix` e `x-pr-fix-epic` validem que cada iteração de fix produziu **diff real** (commits novos com mudança efetiva no diff) antes de re-rodar review, garantindo que o loop de fix não fique em "LLM diz applied fix mas não produziu diff" — apenas re-emitindo review com mesmo NO-GO indefinidamente até `GATE_FIX_LOOP_EXCEEDED` (Rule 20 / EPIC-0043).

Hoje EPIC-0043 introduziu o guard-rail de "no máximo 3 fix attempts antes de abortar". Isso evita loops infinitos. **Mas não detecta** o caso degenerate em que LLM "aplica fix" sem efetivamente alterar arquivos: cada attempt termina com `git status` clean, sem commit novo, mas o re-review é emitido (e provavelmente herda o mesmo NO-GO). Em 3 attempts, o operador pode chegar a `GATE_FIX_LOOP_EXCEEDED` sem ter efetivamente endereçado nenhum finding.

A história introduz `scripts/audit-pr-fix-diff.sh` que:

1. **Snapshot pre-fix** — antes de cada iteração, computa hash do `git rev-parse HEAD` da branch atual.
2. **Snapshot pos-fix** — após `x-pr-fix` retornar, computa hash novo e diff vs pre-fix.
3. **Validação:**
   - HEAD não mudou → `FIX_NO_DIFF` (exit 1) — claro que LLM não aplicou nada.
   - HEAD mudou mas diff é só whitespace/comments → `FIX_TRIVIAL_DIFF` (exit 2) — fix superficial.
   - HEAD mudou mas nenhum file from review-finding-paths foi tocado → `FIX_OFF_TARGET` (exit 3) — fix não endereçou findings.
   - HEAD mudou e ≥1 finding-path foi tocado → `OK` (exit 0).

`x-pr-fix` e `x-pr-fix-epic` SKILL.md são modificadas para invocar o audit entre fix-attempt-N e re-review:

```
Phase: fix loop
  for attempt in 1..3:
    Skill(skill: "x-pr-fix") [required]
    Skill(skill: "audit-pr-fix-diff") [required]   # NEW gate
    if exit != 0:
      abort with FIX_NO_DIFF / FIX_TRIVIAL_DIFF / FIX_OFF_TARGET
    Skill(skill: "x-review-pr") [required]   # re-review
    if GO:
      break
```

A história também adiciona o `<finding-paths>` block ao output de `x-review-pr` — cada finding lista os file paths que ele aponta. Isso vira input para o audit (compara vs commits do fix attempt).

### 3.2 Exit codes

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `OK` | Diff real e on-target |
| 1 | `FIX_NO_DIFF` | HEAD não mudou |
| 2 | `OPERATIONAL_ERROR` | argv malformado OR review malformado (no `**Files:**` field) (Rule 26 conformance) |
| 3 | `FIX_TRIVIAL_DIFF` | Só whitespace/comments (com `--strict-trivial`) |
| 4 | `FIX_OFF_TARGET` | Diff existe mas nenhum file matching review finding-paths |

> **Contrato canônico (pós-refinement 2026-04-28).** A numeração oficial de exit codes deste audit é exatamente a tabela acima. Referências legadas em cenários a `FIX_TRIVIAL_DIFF=2` ou `INVALID_ARGS=4` foram corrigidas (ver §5.2 abaixo) — qualquer ocorrência remanescente em outros artefatos do épico deve ser tratada como obsoleta após a reclassificação de "review/argv malformado" para `OPERATIONAL_ERROR=2`.

### 3.3 Finding-paths extraction (from review)

Each finding em `techlead-review-story-*.md` deve ter:

```markdown
### Finding F-001: ...
**Severity:** high
**Files:**
- src/main/java/dev/iadev/Foo.java:42-89
- src/main/java/dev/iadev/Bar.java
```

Audit faz `git diff --name-only HEAD pre-sha` e checa se interseção com lista files dos findings é não-vazia.

### 3.4 Trivial diff detection

Diff é "trivial" se TODAS as linhas do diff são:
- Whitespace-only (`^[+-]\s*$`)
- Comments (`^[+-]\s*//`, `^[+-]\s*#`, `^[+-]\s*\*`)
- Imports re-arrangement
- Anotações sem efeito (`@SuppressWarnings`, etc — heurística limitada, opt-in via `--strict-trivial`)

## 8. Decision Rationale

**Decisão:** Detection de off-target via intersection paths de finding ↔ paths de diff.
**Motivo:** Heurística simples e determinística. Filtra fix completamente fora do escopo.
**Alternativa descartada:** AST-based diff matching (LLM-judge). Rejeitado por custo + complexidade.
**Consequência:** Falso positivo possível se finding cita arquivo X mas fix correto é em arquivo Y relacionado. Operador pode override via marker `<!-- audit-exempt-fix-target: <reason> -->` no commit message (rare).

**Decisão:** Trivial-diff detection é opt-in via `--strict-trivial`.
**Motivo:** Fix legitimo as vezes é só remover comentário ou ajustar imports. Default permissivo evita falsos positivos.
**Alternativa descartada:** Strict por padrão. Rejeitado.
**Consequência:** Operador que quiser strictness ativa o flag; CI activa em PRs `epic/* → develop`.
