## 1. Contexto & Escopo

Como **Operator/LLM**, eu quero um PreToolUse hook `.claude/hooks/enforce-preflight-gates.sh` que intercepta `git push origin feat/story-*`, `gh pr create --base epic/*`, `gh pr create --base develop` e `Skill x-pr-create`, invocando `scripts/preflight.sh` como gate físico — se preflight exit ≠ 0, o tool call é BLOQUEADO antes de executar.

O hook é a peça operacional que torna a Camada 0 vinculante. Rule 24 (Camadas 1-4) é normativa + audit pós-fato; pode ser ignorada por LLM via inlining ou por operator via shell direto. Hook PreToolUse é o ÚNICO ponto onde o tool call pode ser bloqueado fisicamente antes de executar — Claude Code consulta hooks PreToolUse antes de despachar `Bash` ou `Skill` calls e respeita o exit code.

A história também implementa RULE-004 do épico: `CLAUDE_RECOVERY_MODE=1` é o ÚNICO bypass aceito (Rule 27). Hook intercepta o tool call, deriva `story-id` ou `epic-id` da branch atual via `git symbolic-ref HEAD` (regex strict), invoca `scripts/preflight.sh --scope={story|epic} --story-id=X`, e retorna exit 0 (permite) ou ≠0 (bloqueia com mensagem clara). Outras vars (`CLAUDE_SKIP_AUDIT`, `CLAUDE_NO_ENFORCE`) são IGNORADAS — apenas `CLAUDE_RECOVERY_MODE=1` registra evento `recovery_mode_used` em NDJSON e permite com WARNING visível em stderr.

### 1.1 Regras Transversais Aplicáveis

| ID | Título |
| :--- | :--- |
| RULE-004 | `CLAUDE_RECOVERY_MODE=1` é único bypass |
| RULE-005 | Hook fail-CLOSED para gates |

### 1.2 Entrega de Valor

- **Valor Principal:** `git push` é fisicamente bloqueado se gates falham — não depende de disciplina do LLM ou operator.
- **Métrica de Sucesso:** 100% de tentativas push em branch sem reviews completos retornam exit 2 do hook; recovery_mode usage rate < 5% das stories em janela 30d.
- **Impacto no Negócio:** Elimina classe de bypass "esqueci de invocar review" — fisicamente impossível.

## 3. Contratos & Endpoints

### 3.1 Hook contract

| Trigger | Pattern matched | Action |
| :--- | :--- | :--- |
| PreToolUse `Bash` | `git push origin feat/story-*` | Invocar preflight `--scope=story --story-id=$(derive)` |
| PreToolUse `Bash` | `gh pr create.*--base epic/` | Invocar preflight `--scope=story --story-id=$(derive)` |
| PreToolUse `Bash` | `gh pr create.*--base develop` (epic-level) | Invocar preflight `--scope=epic --epic-id=$(derive)` |
| PreToolUse `Skill` | `x-pr-create` skill name | Invocar preflight `--scope=story` (deriva da branch) |
| PreToolUse `Bash` | `git commit -n` OR `git commit --no-verify` | Bloqueia exit 2 (BLOCKED) — stderr emite `PREFLIGHT_BYPASS_BLOCKED [vector=git-no-verify]` |
| PreToolUse `Bash` | `gh pr merge.*--admin` | Bloqueia exit 2 (BLOCKED) — stderr emite `PREFLIGHT_BYPASS_BLOCKED [vector=gh-merge-admin]` |

> **Convenção única de exit code:** o hook PreToolUse usa exclusivamente `0` (OK) ou `2` (BLOCKED) conforme contrato Claude Code (§3.3). A causa do bloqueio (preflight gate específico ou bypass-vector detectado) é surfaced via stderr com formato estruturado, não via exit code distinto.

### 3.2 Hook input format (Claude Code PreToolUse contract)

```json
{
  "tool_name": "Bash",
  "tool_input": {
    "command": "git push origin feat/story-0063-0001-impl"
  }
}
```

Hook reads stdin JSON, parses with `jq`, applies regex matching, invokes preflight if matched.

### 3.3 Hook exit codes

| Exit | Code | Meaning |
| :--- | :--- | :--- |
| 0 | `OK` | Permite tool call (preflight green OR pattern não-matched) |
| 2 | `BLOCKED` | Bloqueia tool call (preflight failed); stderr identifica gate |

Note: Hook returns exit 2 (specific to PreToolUse contract — Claude Code surfaces stderr to LLM and blocks the tool call).

### 3.4 Branch ID derivation

Cobertura completa de Rule 09 (Branching Model):

```bash
branch=$(git symbolic-ref HEAD 2>/dev/null | sed 's|refs/heads/||')

# story branch: feat/story-XXXX-YYYY[-suffix]
if [[ "$branch" =~ ^feat/story-([0-9]{4})-([0-9]{4})(-.*)?$ ]]; then
  story_id="${BASH_REMATCH[1]}-${BASH_REMATCH[2]}"
fi

# task branch: feat/task-XXXX-YYYY-NNN[-suffix]
if [[ "$branch" =~ ^feat/task-([0-9]{4})-([0-9]{4})-([0-9]{3})(-.*)?$ ]]; then
  story_id="${BASH_REMATCH[1]}-${BASH_REMATCH[2]}"
  task_id="${BASH_REMATCH[1]}-${BASH_REMATCH[2]}-${BASH_REMATCH[3]}"
fi

# epic branch: epic/XXXX
if [[ "$branch" =~ ^epic/([0-9]{4})$ ]]; then
  epic_id="${BASH_REMATCH[1]}"
fi

# fix/hotfix branches: fix/STORY-ID OR hotfix/STORY-ID — out of scope, hook no-op
```

If branch doesn't match any pattern (e.g., `main`, `develop`, `feat/wip-experiment`) → hook exits 0 (no-op, not interception zone). Operadores que usam branches custom invocam `preflight.sh` manualmente.

### 3.5 NDJSON path derivation

Hook delega para `telemetry-lib.sh`:

```bash
source "$CLAUDE_PROJECT_DIR/.claude/hooks/telemetry-lib.sh"
ndjson_path=$(resolve_ndjson_path "$epic_id")  # function provided by telemetry-lib
```

`resolve_ndjson_path` testa primeiro v4 (`ai/epics/epic-XXXX-*/telemetry/events.ndjson`) e cai-back para v3 (`plans/epic-XXXX/telemetry/events.ndjson`). Se não encontrar nenhum, returns empty string e hook log WARN + recovery_mode_used event vai só para stderr (fail-OPEN para telemetria).

### 3.5 CLAUDE_RECOVERY_MODE handling

```bash
if [[ "${CLAUDE_RECOVERY_MODE:-}" == "1" ]]; then
  echo "WARN [CLAUDE_RECOVERY_MODE] bypassing preflight gates for $tool_pattern" >&2
  echo "WARN [CLAUDE_RECOVERY_MODE] Rule 27 — RULE-059-07 exception" >&2
  # Emit telemetry event for audit log
  printf '{"timestamp":"%s","event":"recovery_mode_used","tool":"%s","branch":"%s","pid":%d}\n' \
    "$(date -u +%FT%TZ)" "$tool_pattern" "$branch" "$$" >> "$ndjson_path" 2>/dev/null || true
  exit 0
fi
```

Other env vars (`CLAUDE_SKIP_AUDIT`, etc) → ignored, normal flow proceeds.

## 8. Decision Rationale

**Decisão:** Exit code 2 para BLOCKED (não 1).
**Motivo:** Claude Code PreToolUse contract: exit 2 surfaces stderr to LLM as blocking notification; exit 1 é treated as soft warning.
**Alternativa descartada:** Exit 1 com mensagem em stdout. Rejeitado porque LLM pode ignorar mensagens stdout em hooks.
**Consequência:** Hook deve ser disciplinado em usar exit 2 apenas para bloqueio real, não para erros operacionais.

**Decisão:** Branch derivation via regex strict ao invés de parsing flexível.
**Motivo:** Pattern `feat/story-XXXX-YYYY` é determinístico (Rule 09 branching). Parsing flexível abre vulnerabilities (e.g., `feat/story-0001-0001/../../../etc/passwd`).
**Alternativa descartada:** Aceitar qualquer branch e derivar story-id via metadata file. Rejeitado por adicionar dependency.
**Consequência:** Branches off-pattern → hook é no-op. Operadores que usam branches custom devem invocar preflight manualmente.
