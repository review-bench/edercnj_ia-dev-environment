**ID:** story-0063-0017
**Chave Jira:** —
**Status:** Pendente

## 1. Contexto & Escopo

Como **Compliance Officer**, eu quero um audit periódico que agrega eventos `recovery_mode_used` no NDJSON, calcula a taxa de uso (`recovery_mode_uses / total_stories`) numa janela de 30 dias, e bloqueia o release se taxa > 5% — implementando o SLO declarado em RULE-004 / Section 7 do épico.

RULE-004 declara que `CLAUDE_RECOVERY_MODE=1` é único bypass aceito e seu uso é "audit-logged em events.ndjson para análise periódica". A Section 7 do épico promete SLO `< 5% das stories em janela 30d`. Mas **nenhuma story do escopo original cria o audit, dataset, dashboard ou alerta**. Sem isso, a métrica é órfã.

A história entrega 3 componentes:

1. **Audit script** — `scripts/audit-recovery-mode.sh` agrega eventos `recovery_mode_used` de todos os NDJSONs sob `ai/epics/*/telemetry/events.ndjson` + legado `plans/epic-*/telemetry/events.ndjson` (PathResolver), calcula taxa, retorna exit 1 se > threshold.
2. **Dataset gerado** — `audits/recovery-mode-stats.json` produzido pelo audit, listando per-story uses (vector breakdown), per-epic totals, rolling 30d/60d/90d windows. Atualizado em CI noturno (`audit.yml` cron job).
3. **Dashboard markdown** — `docs/recovery-mode-dashboard.md` renderizado via x-internal-report-write a partir do dataset, com top-5 vectors mais usados, top-5 stories com mais uses, trending (3 windows). Atualizado em commit pelo cron CI.

Threshold (5%) é configurável via `--threshold-pct`. Override por epic possível via `audits/recovery-mode-overrides.json` (rare, reviewed exceptions, e.g., epic de migração emergencial).

A história **NÃO** introduz alertas externos (Slack, email) — fica como backlog. Usa apenas: exit code (CI integration) + dashboard committed.

## 3. Contratos & Endpoints

### 3.1 Request

| Campo | Tipo | M/O | Validações | Exemplo |
| :--- | :--- | :--- | :--- | :--- |
| `--mode` | enum `aggregate\|gate\|render` | M | aggregate=produz JSON; gate=read JSON + check threshold; render=produz dashboard | `--mode=gate` |
| `--threshold-pct` | float | O | default 5.0 | `--threshold-pct=5.0` |
| `--window-days` | int | O | default 30 | `--window-days=30` |
| `--output` | path | O | default depends on mode | — |
| `--self-check` | flag | O | — | — |

### 3.2 Exit codes

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `OK` | aggregate/render success OR gate threshold respected |
| 1 | `RECOVERY_RATE_EXCEEDED` | rate > threshold (gate mode) |
| 2 | `RECOVERY_DATASET_CORRUPT` | recovery-mode-stats.json malformado |
| 3 | `INSUFFICIENT_DATA` | menos de 5 stories na janela |
| 4 | `INVALID_ARGS` | argv malformado |

### 3.3 Dataset schema (recovery-mode-stats.json)

```json
{
  "generated_at": "2026-04-28T15:00:00Z",
  "windows": {
    "30d": {
      "total_stories": 24,
      "stories_with_recovery": 1,
      "rate_pct": 4.17,
      "vectors": {
        "mvn-skipTests": 1,
        "git-commit-direct": 0
      }
    },
    "60d": { ... },
    "90d": { ... }
  },
  "per_story": [
    {
      "story_id": "0063-0099",
      "epic_id": "0063",
      "uses": 1,
      "vectors": ["mvn-skipTests"],
      "first_use_at": "2026-04-28T10:00:00Z",
      "merged_at": "2026-04-28T11:00:00Z"
    }
  ],
  "per_epic": {
    "0063": { "stories": 11, "stories_with_recovery": 1, "rate_pct": 9.09, "override": false }
  }
}
```

### 3.4 Override format (recovery-mode-overrides.json)

```json
{
  "0063": {
    "threshold_pct": 15.0,
    "reason": "epic de migração crítica — override aprovado via PR #999",
    "expires_at": "2026-06-01T00:00:00Z"
  }
}
```

Override expira automaticamente; após `expires_at`, threshold volta para default global.

3. Top-5 vectors usados (bar chart ASCII ou tabela)
4. Top-5 stories com mais uses
5. Per-epic breakdown (tabela)

## 8. Decision Rationale

**Decisão:** Dashboard committed (markdown) ao invés de URL externa.
**Motivo:** Reuso da infra existente (x-internal-report-write); zero custo operacional; auditável via git history.
**Alternativa descartada:** Dashboard externo (Grafana, Looker). Rejeitado por dependência adicional.
**Consequência:** Dashboard atualiza só em commit (não real-time). Aceito (uso é per-release decision).

**Decisão:** Override per-epic com expiração obrigatória.
**Motivo:** Sem expiração, override esquecido vira hole permanente. Expiração força revisão.
**Alternativa descartada:** Override permanente. Rejeitado.
**Consequência:** Operadores precisam estender override se ainda válido (PR explícito). Aceito.
