## 1. Contexto & Escopo

Como **DevOps engineer**, eu quero um único script `scripts/preflight.sh` que executa toda validação local-first em sequência — **12 gates totais**: format, tests, coverage, content audits, telemetry check, self-check, tool-call grammar, wave-dispatch, planning-content, hooks-integrity, telemetry-chain, phase-gate audits — garantindo que operadores e hooks tenham um entry-point determinístico para gate de pre-push.

> **Nota sobre EPIC-0061 RULE-007.** `preflight.sh` em `scripts/` é um **runner** que invoca audits via `audit-*.sh`. Não é em si um audit. EPIC-0061 RULE-007 ("bash audits não vivem no raiz") cobre apenas `audit-*.sh`; runners ficam em `scripts/` por convenção.

Hoje a validação local está distribuída entre `mvn spotless:check`, `mvn test`, `audit-execution-integrity.sh`, `audit-flow-version.sh` etc — cada um chamado manualmente em ordem ad-hoc. Sem um runner único, hooks PreToolUse precisariam replicar a sequência (duplicação) e operators dependem de muscle memory. O script consolida toda a sequência em um CLI estável com exit codes nomeados (FR2 do SPEC + extensões da expansão deste épico) que orchestrators podem dispatchar por nome (não por número raw).

O script é o coração da Camada 0. Ele é invocado pelo PreToolUse hook (story-0063-0004 + extensões da story-0063-0013), pelo `x-story-implement` Phase 2.7 (story-0063-0005), pelo `x-epic-implement` Phase 4.5 (story-0063-0006), e diretamente pelo operator. Idempotente, fail-fast, com mensagens de erro identificando exatamente qual gate falhou.

**Integração com EPIC-0055 (Rule 25 — Task Hierarchy & Phase Gates).** O preflight invoca `audit-phase-gates.sh` e `audit-task-hierarchy.sh` (gates 12) consolidando a Camada 0 com a Camada Rule 25 — sem duplicar lógica, mas garantindo que os dois sistemas de gate executem juntos quando a story é validada localmente.

### 1.2 Entrega de Valor

- **Valor Principal:** Operator pode validar localmente em 1 comando antes de qualquer push, eliminando ciclo "push → CI red → fix → push".
- **Métrica de Sucesso:** P95 wallclock < 5min para story scope; 0 false positives em `Epic0063LocalFirstSmokeTest`.
- **Impacto no Negócio:** Reduz time-to-merge médio em ~30% (estimativa baseada em retrabalho EPIC-0062: 8 stories × 1h CI cycle = 8h economizadas).

### 3.2 Response (CLI exit codes)

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `SUCCESS` | Todos gates GREEN |
| 1 | `TESTS_FAILED` | `mvn test` exit ≠ 0 |
| 2 | `COVERAGE_BELOW_THRESHOLD` | line < 95 OR branch < 90 (D4=A: aplicado ao **repo todo** — Rule 05 RULE-005-01 absolute gate, sem pre-existing exemption) |
| 3 | `REVIEW_CONTENT_INSUFFICIENT` | `audit-review-content.sh` exit 1 |
| 4 | `TELEMETRY_EVIDENCE_MISSING` | `audit-execution-integrity.sh --scope=telemetry` exit 1 |
| 5 | `FORMAT_VIOLATION` | `mvn spotless:check` exit ≠ 0 |
| 6 | `AUDIT_SELF_CHECK_FAILED` | algum `audit-*.sh --self-check` exit ≠ 0 |
| 7 | `GRAMMAR_VIOLATION` | `audit-tool-call-grammar.sh` exit ≠ 0 (story-0063-0012) |
| 8 | `WAVE_DISPATCH_INCOMPLETE` | `audit-wave-dispatch.sh` exit ≠ 0 (story-0063-0014) |
| 9 | `PLANNING_CONTENT_INSUFFICIENT` | `audit-planning-content.sh` exit ≠ 0 (story-0063-0015) |
| 10 | `HOOKS_INTEGRITY_FAILED` | `verify-hooks-integrity.sh` exit ≠ 0 (story-0063-0018) |
| 11 | `TELEMETRY_CHAIN_BROKEN` | `audit-execution-integrity.sh --check-chain` exit ≠ 0 (story-0063-0019) |
| 12 | `PHASE_GATE_AUDIT_FAILED` | `audit-phase-gates.sh` ou `audit-task-hierarchy.sh` exit ≠ 0 (Rule 25 — EPIC-0055 audits integrados) |
| 13 | `INVALID_ARGS` | argv malformado (e.g., `--scope=story` sem `--story-id`) |
| 14 | `OPERATIONAL_ERROR` | `mvn`, `jq`, `git`, `sha256sum` ausente do PATH |

> **Exit codes únicos:** cada código de 0 a 14 é exclusivo — orquestradores (hook, x-story-implement, x-epic-implement) podem branch-ar deterministicamente. Códigos 13 e 14 são "fora de runtime" (validação de input vs ambiente operacional) e não consomem slot dos gates 1-12.

> **Gate ordering (D2=C — lightweight-first):** `5 → 3 → 4 → 9 → 7 → 6 → 10 → 1 → 2 → 8 → 11 → 12`.
>
> Rationale: format (gate 5, ~1s) + audits leves (gates 3/4/9/7/6/10, total ~30s) detectam **stubs** e violações sintáticas em <40s. Tests pesados (gate 1, ~3min) e coverage parsing (gate 2, ~5s) só rodam se evidência leve passa. Audits dependentes de telemetria do build (gates 8/11/12) ficam no final. Resultado: feedback de stub-review em <10s; feedback completo de "tudo OK" em ~4min; SLO P95 < 8min.

### 3.3 Error Codes Mapeados

stderr format: `PREFLIGHT_FAILED: <CODE> — <human readable> — fix: <suggested action>`

Example: `PREFLIGHT_FAILED: REVIEW_CONTENT_INSUFFICIENT — review-story-0063-0001.md has 12 lines (min 50) — fix: invoke /x-review for story-0063-0001`

### 4.1 Regras Aplicáveis do Épico

| :--- | :--- | :--- |
| RULE-001 | Pre-Flight runner é gate único | Esta história IMPLEMENTA o runner |
| RULE-005 | Hook fail-CLOSED | Runner exit ≠ 0 → caller (hook) deve bloquear tool call |

### 4.2 Princípios SOLID Aplicáveis

- **SRP:** O script orquestra; cada gate (format, test, coverage, content, telemetry) é função separada (`run_format_gate`, `run_tests_gate`, etc).
- **OCP:** Adicionar novo gate = adicionar nova função + entrada em array `GATES_ORDER`. Não modifica gates existentes.

### 4.3 Coding Constraints

- Bash strict mode: `set -euo pipefail`
- Cada função ≤ 25 linhas
- Stderr para logs estruturados, stdout reservado (vazio em modo silent ou JSON envelope opcional)

## 8. Decision Rationale

**Decisão:** Bash strict-mode (`set -euo pipefail`) ao invés de Python ou Java para o runner.
**Motivo:** Hooks Claude Code são bash; `mvn`, `jq`, `gh` são CLI nativos; reduzir runtime dependencies. Bash ≤ 25 lines/function é mantível.
**Alternativa descartada:** Python script que invoca subprocess. Rejeitado por adicionar dependência (python3 + virtualenv) ao path crítico.
**Consequência:** Bash error handling exige disciplina (`set -e` + `trap` for cleanup). Mitigação: lint via `shellcheck` no CI.
