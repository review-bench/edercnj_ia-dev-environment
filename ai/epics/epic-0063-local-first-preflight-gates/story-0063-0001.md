## 1. Contexto & Escopo

Como **DevOps engineer**, eu quero um único script `scripts/preflight.sh` que executa toda validação local-first em sequência (format, tests, coverage, content audits, telemetry check), garantindo que operadores e hooks tenham um entry-point determinístico para gate de pre-push.

Hoje a validação local está distribuída entre `mvn spotless:check`, `mvn test`, `audit-execution-integrity.sh`, `audit-flow-version.sh` etc — cada um chamado manualmente em ordem ad-hoc. Sem um runner único, hooks PreToolUse precisariam replicar a sequência (duplicação) e operators dependem de muscle memory. O script consolida toda a sequência em um CLI estável com exit codes nomeados (FR2 do SPEC) que orchestrators podem dispatchar por nome (não por número raw).

O script é o coração da Camada 0. Ele é invocado pelo PreToolUse hook (story-0063-0004), pelo `x-story-implement` Phase 2.7 (story-0063-0005), pelo `x-epic-implement` Phase 4.5 (story-0063-0006), e diretamente pelo operator. Idempotente, fail-fast, com mensagens de erro identificando exatamente qual gate falhou.

### 1.1 Regras Transversais Aplicáveis

| ID | Título |
| :--- | :--- |
| RULE-001 | Pre-Flight runner é gate único |
| RULE-005 | Hook fail-CLOSED para gates |

### 1.2 Entrega de Valor

- **Valor Principal:** Operator pode validar localmente em 1 comando antes de qualquer push, eliminando ciclo "push → CI red → fix → push".
- **Métrica de Sucesso:** P95 wallclock < 5min para story scope; 0 false positives em `Epic0063LocalFirstSmokeTest`.
- **Impacto no Negócio:** Reduz time-to-merge médio em ~30% (estimativa baseada em retrabalho EPIC-0062: 8 stories × 1h CI cycle = 8h economizadas).

## 3. Contratos & Endpoints

### 3.1 Request (CLI args)

| Campo | Tipo | M/O | Validações | Exemplo |
| :--- | :--- | :--- | :--- | :--- |
| `--scope` | enum `story\|epic` | M | exactly one of {story, epic} | `--scope=story` |
| `--story-id` | regex `[0-9]{4}-[0-9]{4}` | O (M se scope=story) | strict format | `--story-id=0063-0001` |
| `--epic-id` | regex `[0-9]{4}` | O (M se scope=epic) | strict format | `--epic-id=0063` |
| `--changed-only` | boolean flag | O | nenhuma | `--changed-only` |
| `--self-check` | boolean flag | O | nenhuma | `--self-check` |

### 3.2 Response (CLI exit codes)

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | `SUCCESS` | Todos gates GREEN |
| 1 | `TESTS_FAILED` | `mvn test` exit ≠ 0 |
| 2 | `COVERAGE_BELOW_THRESHOLD` | line < 95 OR branch < 90 |
| 3 | `REVIEW_CONTENT_INSUFFICIENT` | `audit-review-content.sh` exit 1 |
| 4 | `TELEMETRY_EVIDENCE_MISSING` | `audit-execution-integrity.sh --scope=telemetry` exit 1 |
| 5 | `FORMAT_VIOLATION` | `mvn spotless:check` exit ≠ 0 |
| 6 | `AUDIT_SELF_CHECK_FAILED` | algum `audit-*.sh --self-check` exit ≠ 0 |
| 2 (operational) | `OPERATIONAL_ERROR` | `mvn`, `jq`, `git` ausente do PATH |

### 3.3 Error Codes Mapeados

stderr format: `PREFLIGHT_FAILED: <CODE> — <human readable> — fix: <suggested action>`

Example: `PREFLIGHT_FAILED: REVIEW_CONTENT_INSUFFICIENT — review-story-0063-0001.md has 12 lines (min 50) — fix: invoke /x-review for story-0063-0001`

## 4. Materialização SOLID

### 4.1 Regras Aplicáveis do Épico

| ID | Título | Impacto nesta história |
| :--- | :--- | :--- |
| RULE-001 | Pre-Flight runner é gate único | Esta história IMPLEMENTA o runner |
| RULE-005 | Hook fail-CLOSED | Runner exit ≠ 0 → caller (hook) deve bloquear tool call |

### 4.2 Princípios SOLID Aplicáveis

- **SRP:** O script orquestra; cada gate (format, test, coverage, content, telemetry) é função separada (`run_format_gate`, `run_tests_gate`, etc).
- **OCP:** Adicionar novo gate = adicionar nova função + entrada em array `GATES_ORDER`. Não modifica gates existentes.

### 4.3 Coding Constraints

- Bash strict mode: `set -euo pipefail`
- Cada função ≤ 25 linhas
- Stderr para logs estruturados, stdout reservado (vazio em modo silent ou JSON envelope opcional)

## 8. Decision Rationale

**Decisão:** Bash strict-mode (`set -euo pipefail`) ao invés de Python ou Java para o runner.
**Motivo:** Hooks Claude Code são bash; `mvn`, `jq`, `gh` são CLI nativos; reduzir runtime dependencies. Bash ≤ 25 lines/function é mantível.
**Alternativa descartada:** Python script que invoca subprocess. Rejeitado por adicionar dependência (python3 + virtualenv) ao path crítico.
**Consequência:** Bash error handling exige disciplina (`set -e` + `trap` for cleanup). Mitigação: lint via `shellcheck` no CI.
