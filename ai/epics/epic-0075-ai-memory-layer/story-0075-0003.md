## 1. Contexto & Escopo

Como **mantenedor**, quero a skill interna `/x-internal-epic-summary` (Rule 22 — não user-invocable) que lê os artefatos de um épico (epic-XXXX.md, stories, ADRs, story-completion-reports), extrai problema/hipótese/decisões/alternativas/padrões/antipadrões via heurística determinística, e materializa `ai/memory/epic-XXXX-summary.md` via template + atualização de `_index.yaml`.

Esta é a **skill-motor do épico**. Determinismo é não-negociável: re-execução com mesmos inputs deve produzir output bytewise idêntico (`audit-capability-determinism.sh` pattern). Modelo `haiku` com instruções rigidamente template-driven garante isso a um custo ínfimo (~$0.01/summary).

### 1.1 Regras Transversais Aplicáveis

| ID | Título |
| :--- | :--- |
| Rule 22 | Skill Visibility — `x-internal-*` prefix, `visibility: internal`, `user-invocable: false` |
| Rule 23 | Model Selection — `model: haiku` (utility, sem reasoning profundo) |
| Rule 13 | Skill Invocation Protocol — frontmatter declarado, allowed-tools mínimo |
| Rule 28 | Capability Frontmatter Contract — `requires-capabilities: [governance.ai-memory]` |

### 1.2 Entrega de Valor

- **Valor Principal:** geração automática + estável; eliminado custo humano de redação por épico.
- **Métrica de Sucesso:** 100% dos épicos pós-rollout com summary gerado em Phase 5; 100% determinismo entre runs (smoke test cobre 2 execuções consecutivas + diff = 0).
- **Impacto no Negócio:** história estratégica auto-documentada sem overhead manual.

## 3. Contratos & Schema

### 3.1 CLI Contract

```
/x-internal-epic-summary --epic-id <EPIC-XXXX> [--out-dir <path>] [--dry-run] [--allow-legacy-fallback]
```

| Flag | Tipo | Default | Descrição |
| :--- | :--- | :--- | :--- |
| `--epic-id` | string `EPIC-\d{4}` | required | Identificador do épico |
| `--out-dir` | path | `ai/memory/` | Diretório de saída (override para testes) |
| `--dry-run` | bool | false | Imprime conteúdo sem escrever / atualizar índice |
| `--allow-legacy-fallback` | bool | false | Quando seção 6 (Decisões Arquiteturais) ausente (épicos pré-EPIC-0070 v2), gera summary com placeholder em vez de exit 4 EXTRACTION_FAILED. Restrito a uso pelo retro-seed (story 0006); orquestradores normais (Phase 5.4.5) NÃO devem passar este flag. |

### 3.2 Exit Codes

| Exit | Code | Condição |
| :--- | :--- | :--- |
| 0 | OK | Summary gerado e índice atualizado |
| 1 | EPIC_NOT_FOUND | `ai/epics/epic-XXXX-*/` ausente |
| 2 | SCHEMA_VIOLATION | Frontmatter gerado falha contra `frontmatter-3.0.json` |
| 3 | MEMORY_SUMMARY_TOO_LONG | Body ultrapassa 200 linhas após composição |
| 4 | EXTRACTION_FAILED | Heurística não conseguiu localizar seção 6 (épico v1 sem Decision Rationale). Quando `--allow-legacy-fallback` for passado, este exit é convertido em sucesso com placeholder (`<no formal decisions recorded>`) — degradação graciosa restrita ao retro-seed |
| 5 | INDEX_LOCK_TIMEOUT | Falha ao adquirir `flock` em `ai/memory/_index.yaml` em até 5s (concurrent writer detectado). Caller deve re-tentar |
| 6 | TEMPLATE_VERSION_MISMATCH | `summary-version` no template mudou (campo da seção 3.2 do template); regeneração em massa requerida via batch story-0075-0006-style |
| 7 | MANUAL_REFINEMENT_PRESENT | Summary existente contém marker `<!-- manually-refined: ... -->`; skill aborta para preservar override humano (decisão da story 0006 §8) |

### 3.3 Heurística de extração — decidida

**Estratégia: structured parser sobre markdown headers, não regex livre.**

| Section no summary | Fonte | Estratégia |
| :--- | :--- | :--- |
| `## Why this epic existed` | `epic-XXXX.md` § 1.1 (Problema) + § 1.2 (Hipótese) | Extrai 1º parágrafo de cada, concatena, trunca a 5 linhas |
| `## Hypothesis tested` | `epic-XXXX.md` § 1.2 (Hipótese) + report final (se existir) | Extrai blockquote `> Se ... então ...`. Outcome do report. Se report ausente → "outcome: pending" |
| `## Decisions taken (with why)` | `epic-XXXX.md` § 6 (Decisões Arquiteturais) | Lê cada `### 6.X` header, extrai linhas iniciadas por `**Decisão:**`, `**Motivo:**`, `**Consequência:**` |
| `## Alternatives rejected (with why)` | `epic-XXXX.md` § 6 | Lê linhas `**Alternativa descartada:**` |
| `## Reusable patterns produced` | `epic-XXXX.md` § 6 + heurística por keyword (`pattern`, `padrão`, `convenção`) | Indexação textual + dedup |
| `## Anti-patterns observed` | `epic-XXXX.md` § 6 + keyword (`anti-padrão`, `rejeitado`, `evitar`) | Indexação textual + dedup |
| `## Links` | Determinístico — Epic path, ADRs (frontmatter `adrs-referenced`), PRs (extraídos do report final ou listagem `gh pr list --search "epic-XXXX"`), reports, stories | Determinístico via filesystem walk |

Frontmatter gerado a partir de:
- `tags`: extraídas dos headers do épico v2 (palavras-chave normalizadas pela taxonomia da story 0002)
- `capabilities-affected`: extraídas das capabilities tocadas pelas tasks das stories (varredura de file footprints `## File Footprint`)
- `rules-affected`: extraídas via grep de "Rule \d+" no épico
- `adrs-referenced`: idem para "ADR-\d{4}"
- `patterns-introduced` / `antipatterns-rejected`: alimentados pelas seções homônimas do body
- `dependencies-of` / `dependencies-for`: varredura de "Depende de:" no épico

### 3.4 Idempotência e conflict resolution

- Re-execução sobre o mesmo épico → **regenera** o summary completamente (overwrite). Não há append.
- `_index.yaml`: lock-file via `flock` no diretório `ai/memory/` para serializar writes concorrentes (caller responsability quando rodando paralelo).
- Re-execução sobre épico já com `archived: true` → preserva `archived: true` e `indexable: false` no índice (não reseta flags humanas).

## 8. Decision Rationale

**Decisão:** structured parser sobre markdown headers (não regex livre).
**Motivo:** Headers são contrato estável (EPIC-0070 templates v2). Regex livre captura ruído narrativo.
**Alternativa descartada:** regex sobre body texto inteiro. Rejeitado: falsos positivos altos.
**Consequência:** quebra se template do épico v1 for usado — daí o flag `--allow-legacy-fallback`.

**Decisão:** re-execução regenera completamente (sem append).
**Motivo:** simplicidade > preservação de edits manuais. Edits manuais perdidos forçam revisão pós-regeneração — fluxo aceitável.
**Alternativa descartada:** merge inteligente (3-way). Rejeitado: complexidade altíssima para benefício marginal.
**Consequência:** se humano editou summary manualmente, regeneração sobrescreve — KP playbook documenta dont.

**Decisão:** flag `--allow-legacy-fallback` + placeholder em vez de falha silenciosa.
**Motivo:** retro-seed (story 0006) precisa funcionar sobre épicos v1; mas chamada normal pós-Phase 5 deve falhar hard se algo deu errado.
**Alternativa descartada:** sempre fallback. Rejeitado: mascara erros reais em épicos novos.

**Decisão:** `model: haiku` + instruções explicitamente determinísticas (sem temperatura criativa).
**Motivo:** custo ~$0.01/summary; determinismo testável; consistência entre runs.
**Alternativa descartada:** sonnet criativo. Rejeitado: instabilidade entre runs quebra `audit-capability-determinism.sh` pattern.
