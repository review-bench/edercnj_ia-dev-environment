## 3. Contratos & Schema

### 3.1 `_index.yaml` — schema decidido

Decisão de refinamento: **lista plana** (não por categoria), com filtragem feita pela skill de busca a partir do frontmatter de cada summary. Categorias podem mudar; o índice deve ser estável.

```yaml
# ai/memory/_index.yaml — schema v1.0
schemaVersion: "1.0"
entries:
  - epic-id: EPIC-XXXX
    slug: epic-slug
    summary-path: epic-XXXX-summary.md
    summary-version: "1.0"
    indexable: true        # false → exclude from /x-memory-search results
    archived: false        # archived = true preserves file but flags it
    superseded-by: null    # EPIC-YYYY when superseded
    created: "YYYY-MM-DD"
    last-updated: "YYYY-MM-DD"
```

Frontmatter completo (tags, capabilities, rules, patterns) **mora no summary**, não no índice — evita duplicação e drift.

### 3.2 Capability `governance.ai-memory`

```yaml
id: governance.ai-memory
name: AI Memory Layer
description: Strategic memory production and retrieval for completed epics
category: governance
universal: true
requires: []
excludes: []
```

### 3.3 Retention policy (decidida)

Sem auto-arquivamento. Manual via toggle `indexable: false` em `_index.yaml`. Arquivos preservados indefinidamente; índice continua filtrável.

## 8. Decision Rationale

**Decisão:** `_index.yaml` em formato lista plana.
**Motivo:** estabilidade do schema. Categorias mudam; índice deve permanecer estável. Filtragem por categoria/tag é responsabilidade da skill de busca, que lê frontmatter.
**Alternativa descartada:** índice estruturado por categoria (ex.: `index.governance`, `index.testing`). Rejeitado: força reorganização ao introduzir nova categoria; aumenta acoplamento entre índice e taxonomia.
**Consequência:** skill de busca (story 0004) precisa parsear frontmatter de cada entry — viável dado volume.

**Decisão:** retention policy manual via `indexable: false` flag em `_index.yaml`.
**Motivo:** decisão de "o que é histórico relevante" é humana, não algorítmica. Auto-arquivamento perderia decisões antigas mas ainda load-bearing.
**Alternativa descartada:** auto-arquivamento por idade. Rejeitado: prematuro até observar drift real.
**Consequência:** operadores precisam revisitar `_index.yaml` periodicamente para podagem.

**Decisão:** integração com `system.md` (EPIC-0070) é solta — links opcionais por entry, sem cross-reference forçada.
**Motivo:** `system.md` descreve "estado atual"; `ai/memory/` descreve "decisões históricas + porquês". Conceitos ortogonais.
**Alternativa descartada:** `system.md` consolidaria histórico. Rejeitado: `system.md` cresceria sem limite e perderia foco.
