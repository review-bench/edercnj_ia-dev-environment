## 1. Contexto & Escopo

Como **operador / LLM futura**, quero a skill **user-invocável** `/x-memory-search` que faz retrieval seletivo em `ai/memory/` por 5 modos (`--by-tag`, `--by-capability`, `--by-rule`, `--by-pattern`, `--by-epic`), com implementação grep + parse de frontmatter + ranking simples — **sem RAG vetorial** (decisão 6.2 do épico).

A skill é o **front-end de leitura** do sistema de memória — sua usabilidade determina se o sistema é adotado. Ranking e formato de output precisam ser bem-modelados.

## 3. Contratos & Schema

### 3.1 CLI Contract

```
/x-memory-search (--by-tag <T> | --by-capability <C> | --by-rule <NN> | --by-pattern <P> | --by-epic <E>)
                 [--depth <N>] [--limit <N>] [--format compact|detailed] [--include-archived]
```

| Modo | Argumento | Match strategy |
| :--- | :--- | :--- |
| `--by-tag` | tag string | exact match em `frontmatter.tags[]` |
| `--by-capability` | capability id (ex.: `governance.refinement-gate`) | exact ou glob (`governance.*`) em `frontmatter.capabilities-affected[]` |
| `--by-rule` | número (ex.: `27`) ou string (ex.: `Rule 27`) | match em `frontmatter.rules-affected[]` (case-insensitive) |
| `--by-pattern` | keyword | substring search em `frontmatter.patterns-introduced[].id` + `summary` (boost para id) |
| `--by-epic` | EPIC-XXXX | direct lookup; expande dependencies-of/for transitivamente quando `--depth >= 2` |

| Flag global | Tipo | Default | Descrição | Aplicabilidade |
| :--- | :--- | :--- | :--- | :--- |
| `--depth` | int (1–2) | 1 | Profundidade de expansão de dependências. `1` = entry direta; `2` = inclui `dependencies-of` e `dependencies-for`. Valores > 2 rejeitados (cap evita expansão de grafo inteiro) | Apenas `--by-epic` (ignorado nos demais modos com warning) |
| `--limit` | int | 10 | Cap em resultados | Todos os modos |
| `--format` | enum | `compact` | `compact` = slug + 1-3 frases; `detailed` = inclui decisions taken summary | Todos os modos |
| `--include-archived` | bool | false | Inclui entries com `indexable=false` ou `archived=true` | Todos os modos |

### 3.2 Ranking Heurística — decidida

Score = `100 * tag_match + 50 * frontmatter_field_match + 10 * body_match + 5 * recency_decay`

- `tag_match`: 1 se tag exato em `frontmatter.tags[]`, else 0
- `frontmatter_field_match`: 1 se match em `capabilities-affected`/`rules-affected`/`patterns-introduced.id`/`adrs-referenced`/`dependencies-of`/`dependencies-for`
- `body_match`: 1 se substring em body (apenas para `--by-pattern`; ignorado nos outros modos para evitar falsos positivos)
- `recency_decay`: `(today - created).days < 90 → 1`, else `0` (boost suave para épicos recentes)

**Rationale:** boost de 10x para tag-match impede falsos positivos onde keyword aparece no body de um summary não-relacionado. Body match só vale para `--by-pattern` (modo explicitamente exploratório).

### 3.3 Output formats

**Compact (default):**
```
[1] EPIC-0064 — capability-driven-composition-refactor (score: 165)
    Why: Generator passou de copy-cego para composição capability-driven via frontmatter.
    Tags: capability, compose, assembler · Created: 2026-04-25

[2] EPIC-0061 — local-first-lifecycle (score: 105)
    Why: ...
    Tags: local-first, governance · Created: 2026-04-22

(showing 2 of 2 results)
```

**Detailed (`--format detailed`):**
```
[1] EPIC-0064 — capability-driven-composition-refactor (score: 165)
    Why: <full ## Why this epic existed (max 5 lines)>
    Decisions taken (top 3):
      - <decision 1 summary>
      - <decision 2 summary>
      - <decision 3 summary>
    Patterns introduced: pattern-id-1, pattern-id-2
    ADRs: ADR-0016
    Tags: capability, compose, assembler
    Created: 2026-04-25 · Last updated: 2026-04-25
    File: ai/memory/epic-0064-summary.md
```

### 3.4 `indexable: false` / `archived: true` semantics

- Entries com `indexable: false` em `_index.yaml` → excluídas por default.
- `--include-archived` faz a skill considerá-las e marcá-las como `[ARCHIVED]` no output.
- File não é deletado — preserva histórico imutável.

## 8. Decision Rationale

**Decisão:** ranking 100/50/10/5 (tag/frontmatter/body/recency).
**Motivo:** tag match é signal humano explícito ("este epic é sobre X"). Body match é signal de keyword incidental — peso 10 evita falsos positivos.
**Alternativa descartada:** TF-IDF. Rejeitado: complexidade desnecessária para volume; degradaria latência.
**Consequência:** body match só vale em `--by-pattern` (modo exploratório explicitamente).

**Decisão:** compact format default; detailed opt-in.
**Motivo:** maior caso de uso é "varredura rápida"; detailed é exploração focada.
**Alternativa descartada:** sempre detailed. Rejeitado: overload visual com 10 entries.

**Decisão:** `indexable=false` excluído por default; `--include-archived` opt-in.
**Motivo:** humano sinalizou explicitamente "não traz nas buscas".
**Alternativa descartada:** sempre incluir com prefixo `[ARCHIVED]`. Rejeitado: ruído por default.

**Decisão:** `--by-epic --depth 2` expande dependencies via grafo do `_index.yaml`.
**Motivo:** retrieval transitivo é caso de uso comum ("o que estava em torno do EPIC-X?").
**Alternativa descartada:** depth ilimitado. Rejeitado: pode retornar grafo inteiro; cap em 2 mantém útil.
