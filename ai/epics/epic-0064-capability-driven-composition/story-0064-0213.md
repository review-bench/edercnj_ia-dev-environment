## 1. Contexto

Hooks são scripts Bash em `targets/claude/hooks/` — não têm frontmatter Markdown nativo. Esta story padroniza um header comentado YAML-style nos hooks (parseado pelo validator com lógica especializada).

Hooks são quase todos universais (`requires-capabilities: []`): `enforce-no-bypass-flags.sh`, `enforce-phase-sequence.sh`, `enforce-preflight-gates.sh`, `verify-phase-gates.sh`, `verify-story-completion.sh`, `post-compile-check.sh`, `stage-telemetry.sh`, `telemetry-pretool.sh`, `telemetry-posttool.sh`, `telemetry-session.sh`, `telemetry-stop.sh`, `telemetry-subagent.sh`, `telemetry-emit.sh`, `telemetry-lib.sh`, `telemetry-phase.sh`. ~15 scripts.

`post-compile-check.sh` requires `lang.java` (executa `mvn`).

## 2. Acceptance Criteria

```gherkin
Scenario: Hook header bem-formado
  Given .sh script em hooks/
  When parsed by FrontmatterValidator (Bash mode)
  Then header tem comentário # @requires-capabilities: [...]
  And # @composition-version: 3.0

Scenario: post-compile-check requires lang.java
  Given post-compile-check.sh
  When inspect header
  Then requires-capabilities: [lang.java]

Scenario: Outros hooks universais
  Given enforce-*, verify-*, telemetry-*
  When inspect header
  Then requires-capabilities: []
```

## 4. DoD

- ~15 hooks com header capability declarado.
- `FrontmatterValidator` estendido para parsear comentários Bash.
- Goldens regenerados.

## 5. Implementation Notes

Sintaxe de comentário inline: `# @requires-capabilities: [lang.java]`. Validator detecta via regex e converte para o mesmo modelo interno do frontmatter Markdown.

Hooks são ativados pelo `HooksAssembler` (legacy) — Phase 3 (composer) substitui esse assembler pelo `CapabilityAwareAssembler` que lê o header e prune hooks sem capability ativa.
