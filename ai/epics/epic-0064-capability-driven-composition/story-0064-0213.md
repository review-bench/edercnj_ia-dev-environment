## 6. Decision Rationale

**Decisão:** Sintaxe `# @requires-capabilities: [...]` (comentário Bash inline) em vez de frontmatter Markdown convertido.
**Motivo:** Hooks são `.sh` files — adicionar bloco YAML no topo entre `---` quebra a primeira linha shebang `#!/usr/bin/env bash` (precisa ser linha 1). Sintaxe `# @key: value` é Bash-natural e parseável por regex.
**Alternativa descartada:** Adicionar arquivo paralelo `.sh.frontmatter.yaml` com metadata. Rejeitada por (a) duplicação fragmentada, (b) inconsistência de pattern (skills usam frontmatter inline, hooks usariam external — fica difícil de manter).
**Consequência:** `FrontmatterValidator` ganha modo Bash com regex `^# @([\w-]+):\s*(.+)$`; converte para o mesmo modelo interno.

## 7. Implementation Notes

Sintaxe de comentário inline: `# @requires-capabilities: [lang.java]`. Validator detecta via regex e converte para o mesmo modelo interno do frontmatter Markdown.

Hooks são ativados pelo `HooksAssembler` (legacy) — Phase 3 (composer) substitui esse assembler pelo `CapabilityAwareAssembler` que lê o header e prune hooks sem capability ativa.
