## 1. Contexto

`CapabilityResolver` é a fachada pública do pacote `dev.iadev.application.capability`. Recebe `Profile` + catálogo, orquestra `MutexValidator` → `CycleDetector` → `PrerequisiteResolver` → `ProfileExpander`, e retorna `ResolvedCapabilitySet` ou `CapabilityError` tipado.

É o único entry point usado pelos assemblers/composer. Encapsula toda a complexidade de validação. Determinístico — duas invocações com mesmo input produzem mesmo output (Rule 04).

## 2. Acceptance Criteria

```gherkin
Scenario: Resolver feliz produz set válido
  Given valid catalog + valid profile
  When CapabilityResolver.resolve(profile)
  Then returns ResolvedCapabilitySet
  And contains all transitive capabilities
  And parameters are effective (profile overrides applied)

Scenario: Resolver detecta ciclo
  Given catalog with A→B→A
  When CapabilityResolver.resolve(profile activating A)
  Then throws CycleDetected

Scenario: Resolver detecta mutex
  Given profile activating [postgres, mongo] que se excluem
  When CapabilityResolver.resolve(profile)
  Then throws MutexConflict

Scenario: Resolver detecta prerequisite ausente
  Given profile activating "x" e x.requires=[y] mas y não está no catálogo
  When CapabilityResolver.resolve(profile)
  Then throws MissingPrerequisite

Scenario: Resolver é determinístico
  Given mesmo profile + catálogo
  When CapabilityResolver.resolve(profile) chamado 2 vezes
  Then output1.equals(output2) == true
  And serializeToJson(output1) == serializeToJson(output2) (bytewise)
```

## 4. DoD

- Fachada `CapabilityResolver.resolve(Profile)` implementada.
- Orquestra os 4 validators na ordem correta (mutex → cycle → prerequisite → expand).
- Determinismo bytewise confirmado em teste.
- Cobertura ≥ 95%/90%.
- 5 cenários Gherkin verdes.

## 5. Implementation Notes

Constructor injection dos 4 validators. Cada validator é stateless. `CapabilityResolver` é a única classe pública do pacote — todos os outros são package-private (boundary explicit).

Ordem de validação importa: mutex primeiro (catálogo bem-formado é pre-condition), depois cycle (no grafo construído), depois prerequisite (assume grafo válido), por fim expansion (compõe resultado).
