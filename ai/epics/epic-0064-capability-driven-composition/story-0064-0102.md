## 1. Contexto

Implementa `YamlCapabilityCatalogAdapter` (`dev.iadev.infrastructure.adapter.output`) — implementação Jackson YAML do port `CapabilityCatalogRepository`. Lê `capabilities/<category>/<id>.yaml` e produz `List<CapabilityDefinition>`. Trata erros de schema (referência ao validador da story-0064-0201) com mensagens estruturadas (path do arquivo + linha do problema).

O parser é tolerante a comentários, mantém ordem de declaração (`LinkedHashMap`) para suportar Rule 04 (determinismo bytewise). Suporta carregamento incremental (apenas uma capability por vez) e em batch (todo o catálogo).

## 2. Acceptance Criteria

```gherkin
Scenario: Arquivo ausente falha estruturadamente (degenerate)
  Given path apontando para arquivo inexistente
  When YamlCapabilityCatalogAdapter.load(path)
  Then throws CapabilityError.UnknownCapability
  And error message contains "file not found"

Scenario: Parse de capability YAML válido (happy)
  Given file capabilities/data/database/postgres.yaml com schema válido
  When YamlCapabilityCatalogAdapter.load()
  Then returns CapabilityDefinition with id "data.database.postgres"
  And kind == DATABASE
  And requires lista correta

Scenario: Parse falha em YAML malformado (error)
  Given file capabilities/broken.yaml com syntax error na linha 5
  When YamlCapabilityCatalogAdapter.load()
  Then throws CapabilityError.UnknownCapability
  And error message contains "broken.yaml:5"

Scenario: Carregamento batch lista todos os capabilities (boundary — empty + populated)
  Given diretório capabilities/ com 80 arquivos
  When loadAll()
  Then returns List<CapabilityDefinition> com size 80
  And ordem é determinística (alphabetical by id)
  And invocação 2x consecutiva retorna mesma sequência

Scenario: Schema v2 (sem requires-capabilities) rejeitado (RULE-006)
  Given file capabilities/legacy.yaml com schema v2
  When YamlCapabilityCatalogAdapter.load()
  Then throws CapabilityError.UnknownCapability
  And message contains "schema v3.0 required"
```

## 6. Decision Rationale

**Decisão:** Jackson YAML (jackson-dataformat-yaml) como parser único.
**Motivo:** Já está no `pom.xml` (usado em outros pontos do projeto), oferece integração nativa com `JsonSchemaValidator` (story-0064-0201), suporta `LinkedHashMap` para preservar ordem de declaração.
**Alternativa descartada:** SnakeYAML standalone. Rejeitada por adicionar dependency sem ganho funcional + não integra automaticamente com o schema validator que já é Jackson-based.
**Consequência:** Mapping de YAML → record é via Jackson `@JsonProperty`; constructors canônicos do record fazem validação cruzada.

## 7. Implementation Notes

Jackson `YAMLFactory` + `ObjectMapper`. Classe POJO interna espelhando o schema, depois mapeia para `CapabilityDefinition` (record imutável). Uso de `LinkedHashMap` ao parsear `requires` e `excludes` para preservar ordem de declaração.

Validação de schema delegada à story-0064-0201 (`FrontmatterValidator` reusa Jackson schema validator). Aqui, apenas parse + mapping.
