## 1. Contexto

Audit script que valida o grafo de capabilities (catálogo `capabilities/**/*.yaml`) sem precisar invocar o composer:

1. **Sem ciclos** (delegando ao `CycleDetector` Java, ou reimplementando em jq/bash).
2. **Mutex simétrico** (`A.excludes B ⇒ B.excludes A`).
3. **Sem capability órfã** (sem referência a IDs inexistentes em `requires` ou `excludes`).
4. **Sem capability sem documentação** (todo `<id>.yaml` tem campo `description` non-empty).

Roda em CI a cada PR que toca `capabilities/**`. Exit codes Rule 26.

## 2. Acceptance Criteria

```gherkin
Scenario: Catálogo válido passa (happy)
  Given catalog íntegro
  When audit-capability-graph.sh
  Then exit 0

Scenario: Ciclo detectado falha (error path)
  Given catalog com A.requires=B + B.requires=A
  When audit roda
  Then exit 1
  And error: "GRAPH_VIOLATION: cycle detected: A → B → A"

Scenario: Mutex assimétrico falha (error path)
  Given A.excludes=[B] mas B.excludes=[]
  When audit roda
  Then exit 1
  And error: "GRAPH_VIOLATION: asymmetric mutex"

Scenario: Capability órfã detectada (error path)
  Given X.requires=[Y] mas Y inexistente
  When audit roda
  Then exit 1
  And error: "GRAPH_VIOLATION: orphan reference Y in X"

Scenario: Capability sem description emite warning (boundary — soft fail)
  Given capability x.yaml com description: "" (vazio)
  When audit roda
  Then stderr contém WARN: "missing description in x.yaml"
  And exit 0 (warning, não erro)

Scenario: --self-check valida pré-requisitos (degenerate)
  Given audit-capability-graph.sh --self-check
  When script roda
  Then verifica jq, java disponíveis
  And exit 0
```

## 6. Decision Rationale

**Decisão:** Bash + jq + reimplementação simplificada de Tarjan SCC (não invoke Java CLI).
**Motivo:** Audit deve rodar em CI mesmo se Java code base estiver broken (e.g., compile error em PR). Independência de build é essencial. Tarjan SCC simplificado em ~50 linhas Bash é viável para grafos pequenos (<100 capabilities).
**Alternativa descartada:** Invoke `dev.iadev.cli.GraphAuditCli`. Rejeitada porque (a) requer build success antes de audit rodar, (b) circular dependency no CI (audit deveria ser pre-flight do build, não pos-build).
**Consequência:** Bash script é independente; quando Java code está broken, audit ainda funciona — feedback loop mais rápido.
