## 1. Contexto

Após Phase 2 estar completa (todos os 182 artefatos com frontmatter v3.0), esta story flipa o flag de `audit-capability-coverage.sh` de **advisory** para **hard-fail**. Antes da Phase 2, o audit roda mas não bloqueia; depois desta story, qualquer artefato sem `requires-capabilities` no PR quebra a build.

Marca o ponto de não-retorno: a partir daqui, frontmatter v3.0 é contrato inviolável (Rule 28 §Forbidden post-merge).

## 2. Acceptance Criteria

```gherkin
Scenario: audit em modo hard-fail bloqueia artefato sem requires-capabilities
  Given file inserido em PR sem requires-capabilities
  When CI roda audit-capability-coverage.sh
  Then exit 1
  And error message: "RULE_28_VIOLATION: file X missing requires-capabilities"

Scenario: audit hard-fail aceita declaração explicit []
  Given file com requires-capabilities: []
  When audit roda
  Then exit 0

Scenario: --self-check passa
  Given audit-capability-coverage.sh --self-check
  When script roda
  Then verifica jq disponível
  And verifica governance/schemas/frontmatter-3.0.json existe
  And exit 0

Scenario: CI workflow chama audit com --hard-fail
  Given .github/workflows/audit.yml (ou equivalente)
  When inspect workflow
  Then job invoca scripts/audit-capability-coverage.sh sem flag --advisory
```
