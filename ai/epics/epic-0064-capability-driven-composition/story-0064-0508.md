## 6. Decision Rationale

**Decisão:** Documentação distingue source-of-truth (maintainer) vs output (user); ambos visíveis na SKILL.md.
**Motivo:** Maintainer trabalha com source `targets/claude/skills/core/review/x-review/SKILL.md` + fragments. User vê output `.claude/skills/x-review/SKILL.md` que tem fragments resolvidos. Documentar a separação evita confusão (e.g., user tentando editar output e perdendo mudanças no regen).
**Alternativa descartada:** Documentar apenas source-of-truth. Rejeitada porque user precisa entender que o SKILL.md que ele invoca é gerado — debugging assume conhecimento do pipeline.
**Consequência:** SKILL.md ganha seção "## Source vs Output" explicando o ciclo de vida. ~10-15 linhas adicionais.

## 7. Implementation Notes

Documental. Output composto (gerado pelo composer) é diferente do source-of-truth — usuário vê o output que tem fragmentos resolvidos. Maintainer trabalha no source.
