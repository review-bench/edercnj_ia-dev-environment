## 1. Contexto

`settings.json` (gerado) lista hooks ativos por evento (`SessionStart`, `PreToolUse`, etc.). Hoje, todos os hooks declarados em `targets/claude/hooks/` são incluídos. Esta story aplica capability filtering aos hooks também:

- `post-compile-check.sh` requires `lang.java` — apenas em projetos Java.
- `enforce-bypass-flags.sh` requires `[]` (universal).
- Hooks específicos de stack (futuros): requires `web.spring.boot`, `web.quarkus`, etc.

Composer (story-0064-0301) já scaneia hooks via header comment (story-0064-0213). Esta story garante que `settings.json` reflete o pruning — entries de hooks excluídos são removidas do JSON gerado.

## 2. Acceptance Criteria

```gherkin
Scenario: settings.json inclui apenas hooks com capabilities ativas
  Given profile java-picocli-cli (lang.java ativo)
  When generate
  Then settings.json contém entry para post-compile-check.sh
  And contém entries para hooks universais (enforce-*, verify-*, telemetry-*)

Scenario: settings.json não inclui hook quando capability ausente
  Given profile minimal (sem lang.java)
  When generate
  Then settings.json NÃO contém entry para post-compile-check.sh
  And contém apenas hooks universais

Scenario: Pruning visível em diff entre 2 perfis
  Given settings.json de java-picocli vs minimal
  When diff
  Then java-picocli tem N+1 entries (universal + post-compile)
  And minimal tem N entries (apenas universal)
```
