## 1. Contexto

JSON Schema (Draft 2020-12) que valida frontmatter de skills, rules, KPs, agents, hooks e templates. Define contrato canônico v3.0 do EPIC-0064.

Campos obrigatórios: `name`, `requires-capabilities`. Campos opcionais: `requires-any`, `excludes-capabilities`, `parameters-from`, `fragment-slot`, `fragment-slots`, `composition-priority`, `visibility`, `user-invocable`, `platform`, `model`, `allowed-tools`, `description`, `argument-hint`, `context-budget`.

## 2. Acceptance Criteria

```gherkin
Scenario: Schema validates a minimal v3.0 frontmatter
  Given a skill frontmatter with only `name` and `requires-capabilities: []`
  When validated against governance/schemas/frontmatter-3.0.json
  Then validation passes

Scenario: Schema rejects v2 frontmatter
  Given a skill frontmatter without `requires-capabilities` field
  When validated against frontmatter-3.0.json
  Then validation fails with REQUIRED_FIELD_MISSING

Scenario: Schema validates capability ID format
  Given a frontmatter with `requires-capabilities: ["bad-id-no-dot"]`
  When validated
  Then validation fails (capabilityRef pattern requires dotted form)

Scenario: Schema accepts glob in requires-capabilities
  Given a frontmatter with `requires-capabilities: ["data.database.*"]`
  Then validation passes
```
