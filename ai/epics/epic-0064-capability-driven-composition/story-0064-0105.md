## 1. Contexto

Implementa `PrerequisiteResolver` que expande recursivamente a lista de `requires` de uma capability até chegar ao fechamento transitivo. Por exemplo, `web.spring.boot` requires `web.servlet`, que requires `runtime.jvm` — o resolver retorna `{web.spring.boot, web.servlet, runtime.jvm}` em ordem topológica (dependências primeiro).

Usa Kahn's algorithm para topological sort após expansão. Falha se algum prerequisite estiver ausente do catálogo (`MissingPrerequisite`) ou se ciclo for detectado (delegado à story-0064-0103).

## 2. Acceptance Criteria

```gherkin
Scenario: Expansão transitiva produz fechamento correto
  Given web.spring.boot requires [web.servlet], web.servlet requires [runtime.jvm]
  When PrerequisiteResolver.expand("web.spring.boot")
  Then returns ordered list [runtime.jvm, web.servlet, web.spring.boot]

Scenario: Capability sem prerequisites retorna apenas ela mesma
  Given runtime.jvm com requires=[]
  When PrerequisiteResolver.expand("runtime.jvm")
  Then returns [runtime.jvm]

Scenario: Prerequisite ausente do catálogo falha
  Given web.spring.boot requires [web.unknown] mas catálogo não tem web.unknown
  When PrerequisiteResolver.expand("web.spring.boot")
  Then throws MissingPrerequisite
  And error message lists "web.unknown referenced by web.spring.boot"

Scenario: Glob requires expande para todas matches
  Given x.requires=[data.database.*] e catálogo tem postgres, mongo, mysql
  When PrerequisiteResolver.expand("x")
  Then returns [postgres, mongo, mysql, x] in topological order
```

## 4. DoD

- Expansão transitiva implementada com Kahn's algorithm.
- Glob no `requires` expandido para matches concretas no catálogo.
- `MissingPrerequisite` retornado quando referência aponta para capability inexistente.
- Cobertura ≥ 95%/90%.
- Ordem topológica determinística (tie-break alphabetical).

## 5. Implementation Notes

Kahn's algorithm com fila FIFO. Tie-break em casos de múltiplos nós com indegree 0 simultaneamente: ordenar alfabeticamente por id (Rule 04 determinismo).

`CycleDetector` é invocado antes da expansão para fail-fast em ciclos. Resolver assume catálogo já validado pelo `MutexValidator`.
