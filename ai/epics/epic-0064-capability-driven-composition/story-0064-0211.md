## 6. Decision Rationale

**Decisão:** Precisão de `requires-capabilities` em KPs é crítica — review manual obrigatório por subdiretório.
**Motivo:** KPs são o caso de uso mais sensível ao output pruning. `database-patterns/` em projeto java-cli sem DB é exatamente o contra-exemplo que motivou EPIC-0064. Se `requires-capabilities` for inferido mal, pruning falha no `audit-output-pruning.sh` (story-0064-0411).
**Alternativa descartada:** Confiar 100% no AI fallback de `/x-frontmatter-migrate`. Rejeitada porque false positives (KP universal marcado como Spring) ou false negatives (KP DB marcado universal) são caros para detectar later.
**Consequência:** PR review extenso por subdir (~5-7 sub-PRs por categoria de KP). Pruning real validado em Phase 3 (story-0064-0306..0309 goldens).

## 7. Implementation Notes

KP é o caso de uso mais sensível — output pruning (`audit-output-pruning.sh`, story-0064-0411) garante que projeto Java CLI sem DB **não** receba `database-patterns/`. A precisão das `requires-capabilities` aqui determina o sucesso desse pruning.

Migrar em batch por subdiretório, validar pruning manualmente em 3 perfis canônicos antes do commit.
