## 1. Contexto

Migra todos os Knowledge Packs sob `targets/claude/knowledge/` para frontmatter v3.0. Inclui ~33 KPs:

- Universais: `coding-standards`, `testing`, `architecture`, `protocols`, `patterns`, `layer-templates`, `story-planning`, `parallelism-heuristics`, `planning-standards`, `dockerfile`, `observability/index`, `security/index`, `performance-engineering`, `incident-response`, `release-management`, `mcp-recommendations`, etc.
- Stack-specific: `stack-patterns/spring-patterns/`, `stack-patterns/quarkus-patterns/`, `database-patterns/`, `data-management/`, `data-modeling/`, `messaging-patterns/`, `event-driven-patterns/`, `microservices-patterns/`.

Universais → `requires-capabilities: []`. Stack-specific → declaram dependência apropriada (`web.spring.boot`, `web.quarkus`, `data.database.*`, etc.).

## 5. Implementation Notes

KP é o caso de uso mais sensível — output pruning (`audit-output-pruning.sh`, story-0064-0411) garante que projeto Java CLI sem DB **não** receba `database-patterns/`. A precisão das `requires-capabilities` aqui determina o sucesso desse pruning.

Migrar em batch por subdiretório, validar pruning manualmente em 3 perfis canônicos antes do commit.
