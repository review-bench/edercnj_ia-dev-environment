## 6. Decision Rationale

**Decisão:** Orquestradores `dev/*` declaram `requires-capabilities: []` (universais).
**Motivo:** Rule 21 (Epic Branch Model) + Rule 22 (Skill Visibility) estabelecem que orquestradores são stack-agnósticos por contrato. Conteúdo stack-specific vive em fragments (Phase 4) ou em sub-skills (`x-spring-controller`).
**Alternativa descartada:** Declarar `requires: [lang.java]` para tornar dev/* dependente de Java. Rejeitada porque orquestradores não emitem código Java diretamente — apenas chamam outras skills/agents que podem ser stack-specific.
**Consequência:** Output em qualquer profile contém todos os orquestradores `dev/*` — comportamento desejado (stack-agnostic CLI).

## 7. Implementation Notes

Sem AI fallback necessário aqui — orquestradores são universais por contrato (Rule 21/22). Heurística por path resolve diretamente para `requires-capabilities: []`.
