## 1. Contexto

Property-based testing suite (`CapabilityResolverPropertyTest`) executa 10K casos contra 4 invariantes do resolver:

1. **Idempotência:** `resolve(p) == resolve(p)` (bytewise) para todo profile p válido.
2. **Determinismo:** mesmo input em 3 invocações consecutivas produz mesmo output (SHA igual).
3. **Mutex preservada:** se profile ativa A e A.excludes B, output não contém B.
4. **Prerequisite preservada:** todo capability no output tem seus requires também presentes (ou erro com `MissingPrerequisite`).

Detecta corner cases que test cases manuais não cobrem (e.g., Unicode em IDs, profiles vazios, catálogos com 1 capability, etc.).

## 2. Acceptance Criteria

```gherkin
Scenario: Invariante idempotência verde em 10K casos

Scenario: Invariante determinismo verde em 10K casos
  Given catalog + profile

  Then 100% pass

Scenario: Falsificação reportada com shrinking
  Given simulated bug (introduced manually)
  When propertyTest runs
  Then test fails AND jqwik reports shrunken counter-example (smallest catalog/profile reproducing bug)

Scenario: Total runtime < 60s em 10K casos
  When the property suite runs end-to-end
  Then wall clock < 60s
```

## 4. DoD

- 4 properties implementadas (idempotência, determinismo, mutex, prerequisite).
- 10K casos por property (`@Property(tries = 10000)`).
- Suite executa < 60s (target Phase 1 baseline; ajustável conforme telemetria).
- Falsificação produz contra-exemplo encolhido.
- Output JSON estruturado em `target/jqwik-reports/`.

## 5. Implementation Notes

`@Property(tries = 10000)` em cada método. `@ForAll @From("catalogs")` injeta generators registrados via `@Provide`.

Para idempotência/determinismo: serialize via `Jackson canonical writer` + SHA-256. Para mutex/prerequisite: re-validate output structurally (não chamar resolver novamente).

Configuração de jqwik em `src/test/resources/jqwik.properties` para deterministic seeds em CI (mesmo seed = mesma falha = reproduzível).
