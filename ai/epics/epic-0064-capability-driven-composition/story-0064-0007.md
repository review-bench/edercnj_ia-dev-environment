# Story: 0064-0007 — LifecycleIntegrity para artefatos novos

**Epic:** EPIC-0064
**Phase:** 0
**Wave:** A
**Tamanho:** S
**Predecessores:** story-0064-0005
**Status:** Pendente

---

## 1. Contexto

`LifecycleIntegrityAuditTest` (introduzido por EPIC-0046) escaneia artefatos com Status frontmatter e valida transições do enum canônico. Os novos artefatos do EPIC-0064 (capabilities/*.yaml, fragments/*.md, schemas/*.json) precisam ser reconhecidos pelo audit.

Esta story estende o teste para:
- Detectar arquivos sob `capabilities/` (novo namespace).
- Detectar arquivos sob `targets/claude/skills/x-review/fragments/` (novo padrão fragment-slot).
- Validar que JSON schemas em `governance/schemas/` não exigem Status (são puros schemas, não artefatos lifecycle-controlados).

## 2. Acceptance Criteria

```gherkin
Scenario: LifecycleIntegrityAuditTest reconhece capabilities/
  Given file capabilities/data/database/postgres.yaml
  When LifecycleIntegrityAuditTest runs
  Then it does NOT flag the file as missing Status (capabilities are config, not lifecycle artifacts)

Scenario: Fragments are recognized
  Given file targets/claude/skills/x-review/fragments/db.md with fragment-slot frontmatter
  When LifecycleIntegrityAuditTest runs
  Then it treats the file as fragment (no standalone Status needed)

Scenario: Schemas exempted from Status check
  Given files governance/schemas/*.json
  When test runs
  Then they are excluded from Status field requirement
```
