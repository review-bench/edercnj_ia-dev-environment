## 1. Contexto

Audit script que valida que cada perfil canônico (9 perfis) **não** contém artefato com capability requerida ausente. Por exemplo, perfil java-cli-picocli (sem DB) não pode conter `database-engineer.md` no output.

Estratégia:

1. Para cada perfil em `setup-configs/*.yaml`: invocar `generate --dry-run --output-format json`.
2. Listar artefatos `included`.
3. Para cada artefato included: extrair `requires-capabilities` de seu frontmatter.
4. Verificar que cada capability requerida está presente no profile's resolved set.

Detecta drift: capability adicionada/removida sem regen golden, ou frontmatter desatualizado.

## 6. Decision Rationale

**Decisão:** Reusar `--dry-run --output-format json` (story-0064-0305) como input do audit; sem chamar internals do composer diretamente.
**Motivo:** Boundary clean — audit é consumer externo do CLI (mesmo contrato que CI consume). Mudanças internas do composer não quebram audit enquanto API CLI estável.
**Alternativa descartada:** Audit invoke composer programaticamente (Java embedded). Rejeitada porque (a) acopla audit a internals, (b) shells script mais simples, (c) testabilidade independente.
**Consequência:** Performance dominated by `generate --dry-run` per profile. 9 perfis × ~500ms = ~5s total. Aceitável.
