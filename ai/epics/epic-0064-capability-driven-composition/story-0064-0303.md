## 1. Contexto

`CompositionEngine` resolve marcadores de fragmento dentro do body de artefatos parent:

- `{{ slot: <name> }}` — substitui pelo body concatenado de fragments com `fragment-slot: { slot: <name> }`.
- `{{ #each fragments.<name> }} <template> {{ /each }}` — itera sobre fragments, expande template per-fragment.

Roda **antes** do Pebble (Rule 28 RULE-005 — three-level templating). Output do engine é entrada do Pebble. LLM placeholders (`{{UPPER_SNAKE}}`) ficam intocados.

### 1.1 Regras Transversais Aplicáveis

| RULE-004 | Determinismo bytewise | Fragments ordenados por `fragment-order` ascending; tie-break alphabetical |
| RULE-005 | Three-level templating discriminado | Engine roda antes de Pebble; LLM placeholders preservados |
| RULE-007 | Fragment ≠ artifact | Engine consome fragments declarados via `fragment-slot:` |

## 2. Acceptance Criteria

```gherkin
Scenario: Slot vazio produz string vazia (degenerate)
  Given parent com "{{ slot: missing-slot }}"
  And nenhum fragment com slot=missing-slot
  When CompositionEngine.render(parent, fragments)
  Then output contém string vazia onde marker estava
  And no error

Scenario: {{ slot: X }} substituído por concatenação de fragments (happy)
  Given parent com "## Specialists\n{{ slot: review-specialist }}"
  And 2 fragments com slot=review-specialist (qa.md ordem=10, db.md ordem=20)
  When CompositionEngine.render(parent, fragments)
  Then output contém qa body antes de db body

Scenario: {{ #each }} itera com template per-fragment (composition)
  Given parent com "{{ #each fragments.review-specialist }}- /{{ name }}{{ /each }}"
  When CompositionEngine.render(parent, fragments)
  Then output contém "- /qa\n- /db"

Scenario: LLM placeholders preservados (RULE-005 enforcement)
  Given parent com "{{TASK_ID}}" e "{{ slot: X }}"
  When CompositionEngine.render(parent, fragments)
  Then {{TASK_ID}} preservado
  And {{ slot: X }} resolvido

Scenario: Determinismo — fragments ordenados por fragment-order (RULE-004)
  Given fragments com order [30, 10, 20]
  When CompositionEngine.render() chamado 2x
  Then ambos produzem mesma sequência (10, 20, 30)

Scenario: Parent sem fragment-slots (boundary — passthrough)
  Given parent sem markers {{ slot }} ou {{ #each }}
  When CompositionEngine.render(parent, fragments)
  Then output igual ao parent input (passthrough)
```

## 6. Decision Rationale

**Decisão:** Regex parser simples para markers (`{{ slot: X }}`, `{{ #each }}`) em vez de full AST.
**Motivo:** O subset suportado é pequeno e bem-definido. AST completo (estilo Mustache/Handlebars) introduziria dependência ou implementação complexa para cobertura desnecessária. Regex é debugável e ~50 LOC.
**Alternativa descartada:** Adotar Mustache.java ou Handlebars.java. Rejeitada porque (a) introduz dep externa, (b) ambos processam ALL `{{ }}` markers — quebra RULE-005 (LLM placeholders precisam ser preservados).
**Consequência:** Adicionar novo tipo de marker exige modificar engine + adicionar regex + cobertura. Aceitável — markers raramente mudam (contrato Rule 28).

## 7. Implementation Notes

Parser regex simples: `\{\{ slot: ([\w-]+) \}\}` e `\{\{ #each fragments\.([\w-]+) \}\}(.*?)\{\{ /each \}\}`. Sem AST completo — regex suficiente para esse subset.

Pre-flight check (RULE-005): após render, regex `\{\{[A-Z_]+\}\}` deve retornar matches (LLM placeholders). Se não houver matches em template que tinha LLM placeholder, falhar com erro indicando que Pebble processou indevidamente.
