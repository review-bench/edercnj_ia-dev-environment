## 1. Contexto

Property-based test focado na idempotência do `CapabilityAwareComposer`:

- **Property 1:** `compose(p) == compose(p)` em 1000 perfis aleatórios (gerados pela jqwik suite da story-0064-0110).
- **Property 2:** `compose(p1).equals(compose(p2))` se `p1` e `p2` resolvem para mesmo `ResolvedCapabilitySet`.
- **Property 3:** Adicionar capability inativa ao profile não muda output (composer apenas inclui capabilities ativas — atomics no `ResolvedCapabilitySet`).

Detecta nondeterminism em casos extremos (sets/maps unordered, threading issues, timestamps no output, paths absolutos no metadata).

## 2. Acceptance Criteria

```gherkin
Scenario: Idempotência sobre 1000 profiles aleatórios
  Given jqwik generators
  When propertyTest("idempotency-composer") runs 1000 cases
  Then 100% pass (compose(p) bytewise equal compose(p))

Scenario: Equivalência semântica entre profiles redundantes
  Given p1 e p2 que ativam mesmo set de capabilities (ordem diferente em listing)
  When compose(p1) e compose(p2)
  Then output igual (set-based, não list-based)

Scenario: Capabilities inativas (presente no profile mas requer outras inativas) não afetam output
  Given p com capability X que requires Y, mas Y não no profile
  When compose(p)
  Then output não inclui X
  And output identicamente igual a compose(p sem X)
```
