# Story: 0064-0608 — Test matrix shrinking via pairwise covering (≤50 combos)

**Epic:** EPIC-0064
**Phase:** 6 — Audit, Tests, Golden Regen
**Wave:** N
**Tamanho:** M
**Predecessores:** story-0064-0607 (property suite 10K)
**Status:** Pendente

---

## 1. Contexto

Sem otimização, o cross-product de capabilities × profiles × engines × frameworks explode (180+ perfis possíveis — risco R3). Esta story aplica **pairwise covering** (técnica clássica de combinatorial testing — TestNG `@Combinatorial` ou jqwik built-in) para reduzir a matriz de testes para **≤50 combinações** que ainda cobrem todos os pares de inputs.

Aplica-se a:

- Cross-product de framework × DB × messaging × cloud → perfis sintéticos.
- Property test suite — limita generators para gerar combinações pairwise.

## 2. Acceptance Criteria

```gherkin
Scenario: Pairwise covering reduz matrix para ≤50
  Given full cross-product de 180 combos
  When pairwise covering aplicado
  Then matriz reduz para ≤50 combinations

Scenario: 100% dos pares cobertos
  Given matriz pairwise
  When inspect coverage
  Then todos os pares (capability_X, capability_Y) aparecem em ≥1 combination

Scenario: Suite executa em < 2min
  Given 50 combinations
  When test suite runs
  Then wall clock < 2min em CI

Scenario: Documentação em test class

  Then JavaDoc explica pairwise covering rationale + tool usado
```

## 5. Implementation Notes

Algoritmo Allpairs: implementação manual ~150 LOC, ou usar lib como `combinatoricslib3`. jqwik 1.8+ tem suporte built-in via `@Combinatorial`.

Saída do generator é List<Map<String, Object>> — cada map é uma combinação aplicável a profile builder.
