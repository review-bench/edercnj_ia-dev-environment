## 1. Contexto

Adiciona instrumentação telemétrica ao `CapabilityResolver`: emite eventos `phase.start` / `phase.end` + métricas (`tempoResolve`, `numCapabilitiesAtivas`, `numProfilesExpandidos`) em `events.ndjson` (mesmo padrão do resto do épico, ADR-0005).

Permite detectar regressão de performance (Rule 04 — composer ≤ 1.2× copy legacy). Métrica baseline será capturada em Phase 3 (story-0064-0306, primeiro golden). Story-0064-0606 (`audit-capability-determinism.sh`) consome esses eventos para verificar 3 builds consecutivos.

## 2. Acceptance Criteria

```gherkin
Scenario: resolver emite phase.start (happy)
  When CapabilityResolver.resolve(profile)
  Then events.ndjson contém entry { "type": "phase.start", "skill": "x-internal-resolver", "phase": "resolve" }

Scenario: resolver emite phase.end com métricas (happy)
  When CapabilityResolver.resolve(profile) completes
  Then events.ndjson contém phase.end with metrics:
    - "tempoResolveMs" (long)
    - "numCapabilitiesAtivas" (int)
    - "numProfilesExpandidos" (int)
    - "outputSha256" (string — for RULE-004 audit)
    - "status": "ok" or "failed"

Scenario: emissão respeita CLAUDE_TELEMETRY_DISABLED (degenerate)
  Given env CLAUDE_TELEMETRY_DISABLED=1
  When CapabilityResolver.resolve(profile)
  Then events.ndjson não recebe entries
  And resolve continua funcional (fail-open)

Scenario: telemetria não viola Rule 20 (privacy — boundary)
  When events.ndjson is parsed
  Then não contém paths absolutos do user
  And não contém values de parameters (apenas keys/counts)
```

## 6. Decision Rationale

**Decisão:** Decorator pattern para wrappear `CapabilityResolver` (não interceptor / aspect-oriented).
**Motivo:** Decorator é explícito (vis. no código), simples (sem AOP runtime), e fail-open por construção (try/catch wrap). RULE-006 (sem retrocompat) sugere preferência por explicitness.
**Alternativa descartada:** Spring AOP aspect ou bytecode interceptor. Rejeitada por (a) projeto não usa Spring, (b) AOP esconde behavior, dificulta debug.
**Consequência:** `CapabilityResolver` exposes `resolveInternal()` package-private; decorator wrap em construção via factory method.

## 7. Implementation Notes

`CapabilityResolverTelemetry` é um decorator estilo cross-cutting. Reusa `TelemetryScrubber` existente (Rule 20). Não introduz novo formato — segue o NDJSON canônico.

Para baseline de performance: o CI captura `tempoResolveMs` em runs noturnos e plota tendência via `/x-telemetry-trend`. Alarme em P95 > 50ms (target — ajustar conforme medição).
