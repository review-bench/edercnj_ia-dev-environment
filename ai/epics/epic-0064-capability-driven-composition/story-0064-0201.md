## 1. Contexto

`FrontmatterValidator` (Java) é o gate técnico da migração: lê todo `.md` sob `targets/claude/` (skills, rules, KPs, agents, hooks, templates), parseia frontmatter YAML, valida contra `frontmatter-3.0.json` schema, e reporta violações estruturadas. Sai com exit 1 quando 1+ artefato falha — bloqueia merge da PR de migração.

Implementado como classe + CLI (`FrontmatterValidatorCli`). Reusa Jackson + JsonSchemaValidator. Integra com `audit-capability-coverage.sh` em Phase 6 (story-0064-0602) como hard-fail.

## 2. Acceptance Criteria

```gherkin
Scenario: Arquivo sem frontmatter falha (degenerate)
  Given file sem bloco --- frontmatter ---
  When FrontmatterValidator.validate(file)
  Then returns ValidationResult.failed
  And error: "missing frontmatter block"

Scenario: Artefato válido v3.0 passa (happy)
  Given file with frontmatter v3.0 valid (requires-capabilities present)
  When FrontmatterValidator.validate(file)
  Then returns ValidationResult.ok()

Scenario: Frontmatter v2 (sem requires-capabilities) falha (RULE-006 enforcement)
  Given file with frontmatter v2 (legacy)
  When FrontmatterValidator.validate(file)
  Then returns ValidationResult.failed
  And error contém "missing required field: requires-capabilities"
  And exit code = 1

Scenario: Capability ID inexistente flagrada (warning, não fatal)
  Given frontmatter requires-capabilities: [data.unknown.fake]
  When FrontmatterValidator.validate(file, catalog)
  Then warning emitted: "capability data.unknown.fake not found in catalog"
  And ValidationResult.ok() (warning, não erro)

Scenario: CLI batch mode reporta todas as falhas (boundary)
  Given diretório com 100 arquivos, 5 inválidos
  When FrontmatterValidatorCli.main(["--root", "targets/claude/"])
  Then stderr lista 5 arquivos com line numbers
  And exit code = 1
  And --json mode produz JSON estruturado
```

## 6. Decision Rationale

**Decisão:** `networknt/json-schema-validator` (já no pom) como engine de validação.
**Motivo:** Já dependency do projeto, integra nativamente com Jackson (parser usado em story-0064-0102), suporta JSON Schema 2020-12, ativo em manutenção.
**Alternativa descartada:** Custom validator hand-rolled. Rejeitada por (a) reinvenção de roda madura, (b) JSON Schema é o padrão para frontmatter — validator deve seguir o spec, não interpretação custom.
**Consequência:** Validator depende de schema bem-formado em `governance/schemas/`; mudança de schema = breaking change.

## 7. Implementation Notes

`networknt/json-schema-validator` (já no pom). Parseia frontmatter via SnakeYAML (delimitadores `---`). Lookup de capability IDs delegado ao `CapabilityResolver` (carrega catálogo uma vez, valida em batch).

Saída JSON estruturada (modo `--json` para CI consumir).
