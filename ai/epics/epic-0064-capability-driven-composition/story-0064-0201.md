## 1. Contexto

`FrontmatterValidator` (Java) é o gate técnico da migração: lê todo `.md` sob `targets/claude/` (skills, rules, KPs, agents, hooks, templates), parseia frontmatter YAML, valida contra `frontmatter-3.0.json` schema, e reporta violações estruturadas. Sai com exit 1 quando 1+ artefato falha — bloqueia merge da PR de migração.

Implementado como classe + CLI (`FrontmatterValidatorCli`). Reusa Jackson + JsonSchemaValidator. Integra com `audit-capability-coverage.sh` em Phase 6 (story-0064-0602) como hard-fail.

## 2. Acceptance Criteria

```gherkin
Scenario: Artefato válido passa
  Given file with frontmatter v3.0 valid
  When FrontmatterValidator.validate(file)
  Then returns ValidationResult.ok()

Scenario: Frontmatter v2 (sem requires-capabilities) falha
  Given file with frontmatter v2 (legacy)
  When FrontmatterValidator.validate(file)
  Then returns ValidationResult.failed
  And error contém "missing required field: requires-capabilities"
  And exit code = 1

Scenario: Capability ID inexistente flagrada
  Given frontmatter requires-capabilities: [data.unknown.fake]
  When FrontmatterValidator.validate(file, catalog)
  Then warning emitted: "capability data.unknown.fake not found in catalog"

Scenario: CLI batch mode reporta todas as falhas
  Given diretório com 100 arquivos, 5 inválidos
  When FrontmatterValidatorCli.main(["--root", "targets/claude/"])
  Then stderr lista 5 arquivos com line numbers
  And exit code = 1
```
