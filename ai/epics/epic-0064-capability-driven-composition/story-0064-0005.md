## 1. Contexto

Rule 28 codifica que toda decisão de incluir/excluir/parametrizar um artefato passa por frontmatter declarativo, validado por schema, auditado por CI. É o contrato normativo do EPIC-0064.

Define 8 invariantes (declaração obrigatória, schema v3.0 estrito, capability ID válido, excludes simétrico, composition-priority bounded, fragment ≠ artifact, slot↔fragment coerência, sem retrocompat), examples canônicos, lista forbidden/permitted, audit script catalog, migration path, self-audit contract.
