## 1. Contexto

Refina os agents (story-0064-0212 já migrou frontmatter) para verdadeiramente serem condicionais por capability. Hoje, mesmo após migration, alguns agents podem ter conteúdo body que pressupõe stack que não está ativa.

Esta story:

1. Inspeciona body de cada agent (especialmente `database-engineer`, `event-architect`, `compliance`, `data-engineer`).
2. Garante que conteúdo é coerente com `requires-capabilities`.
3. Ajusta conteúdo onde necessário (e.g., `database-engineer.md` não menciona Mongo se requires for `data.database.*` (todos), mas faz sentido nesse caso; verificar coerência).

Adicionalmente, valida que `x-review` (story-0064-0501) corretamente delega ao agent specialist correto via fragments.

## 6. Decision Rationale

**Decisão:** Escopo limitado a body coherence — sem fragmentation interna de agents (e.g., `database-engineer/fragments/postgres.md`).
**Motivo:** Agents são ~50-150 linhas — fragmentação adiciona complexidade sem ganho proporcional. Coherence check (body keywords match requires) é suficiente para garantir output limpo.
**Alternativa descartada:** Fragmentar `database-engineer` por engine (postgres/mongo/mysql). Rejeitada por (a) escopo creep, (b) precedente que toda capability-driven artifact precisa fragmentação — falso, glob `data.database.*` no requires já cobre.
**Consequência:** Future story dedicada (potencial follow-up epic) pode fragmentar agents se demanda real surgir.
