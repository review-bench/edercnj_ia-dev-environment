## 1. Contexto

Implementa `MutexValidator` (`dev.iadev.application.capability`) que valida a invariante simétrica de `excludes`: se A.excludes contém B, então B.excludes contém A. Também detecta tentativas de ativar duas capabilities mutuamente exclusivas no mesmo profile (e.g., `data.database.postgres` + `data.database.mongo` quando ambos se excluem).

Falha de simetria é defeito de catálogo (sempre erro de autoria); ativação simultânea é erro de profile (corrigível pelo dono do projeto). Ambos retornam `CapabilityError.MutexConflict` com mensagem distinta.

## 2. Acceptance Criteria

```gherkin
Scenario: Catálogo sem excludes passa (degenerate)
  Given catalog onde nenhuma capability tem excludes
  When MutexValidator.validateCatalog(catalog)
  Then no error
  And no warnings

Scenario: Catálogo com excludes simétricos válida (happy)
  Given postgres.excludes=[mongo] AND mongo.excludes=[postgres]
  When MutexValidator.validateCatalog(catalog)
  Then no error

Scenario: Catálogo assimétrico falha (error path — defeito de autoria)
  Given postgres.excludes=[mongo] BUT mongo.excludes=[]
  When MutexValidator.validateCatalog(catalog)
  Then throws MutexConflict
  And message contains "asymmetric mutex: postgres excludes mongo but mongo does not exclude postgres"

Scenario: Profile com par excluído falha (error path — uso incorreto)
  Given profile activates [postgres, mongo] AND postgres.excludes=[mongo]
  When MutexValidator.validateProfile(profile, catalog)
  Then throws MutexConflict
  And message lists conflicting pair
  And error message distinct from catalog asymmetry case
```

## 6. Decision Rationale

**Decisão:** Dois modos de validação separados (`validateCatalog` + `validateProfile`) com mensagens distintas.
**Motivo:** Falha de simetria no catálogo é bug de autoria (corrigir o YAML do catálogo); conflito em profile é configuração do consumidor (corrigir o profile YAML). Mensagens distintas guiam quem deve agir.
**Alternativa descartada:** Validação unificada com mensagem genérica "mutex violation". Rejeitada por dificultar troubleshooting — operador precisa saber se é defeito de catálogo (PR para `ia-dev-env`) ou de profile (PR no projeto-alvo).
**Consequência:** Validator tem 2 entry points públicos; testes cobrem cada modo independentemente.

## 7. Implementation Notes

Implementação direta com `Set` checks. `Map<CapabilityId, Set<CapabilityId>>` indexada por id permite O(1) lookup. Iteração determinística sobre `TreeMap.entrySet()` para garantir Rule 04 (resultado idêntico em runs consecutivas).
