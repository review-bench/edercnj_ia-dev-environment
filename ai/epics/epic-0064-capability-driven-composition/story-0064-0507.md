## 1. Contexto

Adiciona telemetria ao `CapabilityAwareComposer` (análoga à story-0064-0112 do resolver). Métricas:

- `tempoComposeMs` — tempo total do `compose()`.
- `numArtefatosIncluidos` — count de included.
- `numArtefatosPruneados` — count de excluded.
- `numFragmentosResolvidos` — count de fragments injetados.
- `tempoCompose / tempoCopyLegacy` — ratio para baseline (Rule 04 — composer ≤ 1.2× legacy).

Permite Rule 04 enforcement via `audit-capability-determinism.sh` (story-0064-0606): ratio > 1.2× alerta.

## 2. Acceptance Criteria

```gherkin
Scenario: Composer emite phase.start + phase.end com métricas
  When CapabilityAwareComposer.compose(profile)
  Then events.ndjson contém entry phase.end com 5 métricas

Scenario: Ratio composer/legacy reportado em log
  Given CLAUDE_TELEMETRY_DISABLED não setado
  When generate runs
  Then log line contém "composeRatio: X.YY"
  And X.YY < 1.2

Scenario: Privacy compliance (Rule 20)
  Given events.ndjson
  When parse
  Then sem paths absolutos do user, sem values de parameters

Scenario: Fail-open quando telemetria desabilitada
  Given CLAUDE_TELEMETRY_DISABLED=1
  When CapabilityAwareComposer.compose(profile)
  Then events.ndjson não recebe entries
  And compose continua funcional
```
