## 1. Contexto

Audit script que valida coerência entre `fragment-slots` declarados no parent e `fragment-slot:` declarados nos fragments + referências `{{ slot: X }}` ou `{{ #each fragments.X }}` no body do parent.

Casos de incoerência detectados:

1. Parent declara slot X em frontmatter mas body não referencia.
2. Body referencia slot X mas frontmatter não declara.
3. Fragment declara slot X mas nenhum parent declara o mesmo X.
4. Parent declara slot X mas nenhum fragment com slot X existe (warning, não erro).

Roda em CI no PR. Exit 1 se incoerência ≥ 1.

```gherkin
  Given parent declara fragment-slots: [X] AND body referencia {{ slot: X }} AND fragment declara fragment-slot.slot: X

Scenario: Slot não referenciado falha (error path — declared but unused)
  Given parent declara slot X mas body não tem {{ slot: X }}
  When audit roda
  Then exit 1
  And error: "FRAGMENT_COHERENCE_VIOLATION: parent declares slot X but does not reference it"

Scenario: Slot órfão (sem fragment) emite warning (boundary — soft fail)
  Given parent declara slot X mas nenhum fragment com slot=X existe
  When audit roda
  Then exit 0 (não é erro fatal)
  And stderr contém WARN: "slot X has no fragments"

Scenario: --self-check passa (degenerate — pre-flight)
  Given audit-fragment-coherence.sh --self-check
  When script roda
  Then verifica jq + grep disponíveis
  And exit 0

Scenario: Body referencia slot não declarado (error path — undeclared use)
  Given parent body com {{ slot: Y }} mas frontmatter não declara Y
  When audit roda
  Then exit 1
  And error: "FRAGMENT_COHERENCE_VIOLATION: body references slot Y not declared in fragment-slots"
```

## 6. Decision Rationale

**Decisão:** Distinguir "violation" (parent declara slot mas não usa, ou usa slot não declarado) de "warning" (parent declara slot mas nenhum fragment existe).
**Motivo:** Violation = inconsistência interna do parent (always wrong). Warning = estado válido temporário (parent prepara slot que será usado quando fragment for adicionado em PR futuro).
**Alternativa descartada:** Tudo violation — slot sem fragment = erro. Rejeitada porque PR pattern de "add fragment-slot first, then add fragment" seria bloqueado, forçando atomic PRs grandes demais.
**Consequência:** Workflow PR pattern: PR1 adiciona slot ao parent (passa com warning); PR2 adiciona fragment (warning some).

## 7. Implementation Notes

Bash + grep + jq. Para cada `.md`: parsear frontmatter, extrair `fragment-slots` ou `fragment-slot`, grep body por `{{ slot: }}` e `{{ #each fragments. }}`, cross-reference.

Exit code 1 com mensagem que aponta arquivo + linha do problema (operador-action-able).
