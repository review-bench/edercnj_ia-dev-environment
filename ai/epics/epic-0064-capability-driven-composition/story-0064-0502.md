## 1. Contexto

`CLAUDE.md` (root) é o arquivo de instruções carregado em toda conversa. Hoje é universal — mesmo conteúdo para qualquer projeto. Esta story refatora para suportar fragments capability-driven:

- Conteúdo universal preservado em `shared/templates/CLAUDE.md` (parent).
- Fragments por capability: `fragments/database.md` (regras data), `fragments/messaging.md`, `fragments/security-pci.md`, `fragments/microservices.md`, etc.
- Parent declara `fragment-slots: [{slot: domain-specific}]`.

Resultado: `CLAUDE.md` gerado para Java CLI sem DB é mais curto e focado; projeto Spring + Postgres + PCI tem instruções específicas de DB e PCI.

## 6. Decision Rationale

**Decisão:** Frontmatter via comentário HTML `<!-- composition: ... -->` em vez de bloco YAML `---` no topo.
**Motivo:** CLAUDE.md é Markdown que vira instrução LLM — qualquer YAML frontmatter no topo pode confundir o LLM (que pode interpretar como conteúdo). Comentário HTML é invisível ao LLM mas parseável pelo composer via regex.
**Alternativa descartada:** Frontmatter YAML padrão `---`. Rejeitada porque (a) LLM pode interpretar literalmente, (b) outras instruções LLM no projeto já evitam frontmatter YAML em arquivos lidos por LLM.
**Consequência:** `FrontmatterValidator` (story-0064-0201) ganha modo `--html-comment` para CLAUDE.md; parsing é leve (regex `<!-- composition: (.+?) -->`).
