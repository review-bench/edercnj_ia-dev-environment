## 1. Contexto

Adiciona flag `--dry-run` ao comando `generate` (CLI Picocli em `dev.iadev.cli`). Quando ativa:

- Composer roda completo: load profile → resolve → plan → render fragments → render Pebble.
- **Não escreve em disco** (OutputPruner skip).
- Output: relatório estruturado em stdout (text default; JSON com `--output-format json`).

Útil para diagnose ("o que entra/sai do meu output?") e para o pipeline de gates pre-merge (story-0064-0706 — baseline grandfathered).

## 2. Acceptance Criteria

```gherkin
Scenario: Dry-run não cria output dir (degenerate)
  Given output dir não existe
  When generate --config x.yaml --dry-run
  Then output dir continua não existindo
  And stdout mostra plan

Scenario: Plan listado em texto humano (happy)
  Given valid config
  When generate --dry-run
  Then stdout contém:
    - "Included artifacts: N"
    - "Excluded artifacts: M"
    - "Regenerated: K"

Scenario: --output-format json produz JSON parseável (composition)
  Given valid config
  When generate --dry-run --output-format json
  Then stdout é JSON válido
  And contém keys: included, excluded, regenerated, warnings

Scenario: Errors propagados mesmo em dry-run (error path)
  Given config com mutex conflict
  When generate --dry-run
  Then exit code = 1
  And stderr contém MutexConflict message

Scenario: Specific artifact check via --check (boundary — diagnostic)
  Given dry-run + flag --check database-engineer.md
  When generate
  Then stdout reporta "database-engineer.md: INCLUDED" ou "EXCLUDED (reason: X)"
```

## 6. Decision Rationale

**Decisão:** Dry-run reusa `plan()` do composer; não chama `execute()`. Output JSON é input estruturado para `audit-output-pruning.sh` (story-0064-0411).
**Motivo:** Plan/execute split (story-0064-0301) já oferece dry-run natural. JSON estruturado padroniza CI consumer (audit script + future tooling).
**Alternativa descartada:** Dry-run que faz execute em tmp dir + lista resultantes. Rejeitada por (a) overhead de I/O desnecessário, (b) inconsistência semântica (dry-run que cria arquivos é confuso).
**Consequência:** `audit-output-pruning.sh` em CI invoca `generate --dry-run --output-format json` e parseia output via jq.

## 7. Implementation Notes

Picocli `@Option(names = "--dry-run")`. Bypass do `OutputPruner` quando flag ativa. JSON via Jackson com `JsonInclude.Include.NON_EMPTY` para limpeza visual.

Story-0064-0411 (`audit-output-pruning.sh`) consome este formato JSON em CI.
