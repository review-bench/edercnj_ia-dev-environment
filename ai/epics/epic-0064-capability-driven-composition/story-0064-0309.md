## 1. Contexto

Regenera os goldens dos 6 perfis canônicos restantes (não cobertos por 0306-0308):

1. `setup-config.spring-fintech-pci.yaml` — Spring + Postgres + Kafka + PCI compliance.
2. `setup-config.quarkus-reactive-mongo.yaml` — Quarkus reactive + MongoDB.
3. `setup-config.spring-microservices.yaml` — Spring + multi-service + RabbitMQ.
4. `setup-config.quarkus-cloud-native.yaml` — Quarkus + GraalVM native + observability.
5. `setup-config.minimal.yaml` — apenas runtime.jvm + lang.java (perfil mínimo absoluto).
6. `setup-config.full-featured.yaml` — todos os capabilities (perfil de teste de carga).

Cada perfil valida um corner case distinto da composição.

## 2. Acceptance Criteria

```gherkin
Scenario: 6 goldens regenerados deterministicamente
  Given 6 setup-config.*.yaml files
  When generate executa para cada um
  Then 6 golden directories produzidos
  And cada um determinístico em 3 builds

Scenario: spring-fintech-pci contém compliance fragments
  Given setup-config.spring-fintech-pci.yaml
  When inspect output
  Then rules/06-security-baseline.md contém fragment pci-dss
  And agents/compliance.md presente

Scenario: minimal perfil produz output mínimo (<10 arquivos)
  Given setup-config.minimal.yaml
  When generate
  Then output total ≤ 10 arquivos

Scenario: full-featured produz output máximo (todos os artefatos)
  Given setup-config.full-featured.yaml com todos os capabilities ativados
  When generate
  Then output contém todos os artefatos do catálogo (modulo excludes simétricos resolvidos)
```
