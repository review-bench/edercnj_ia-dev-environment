## 1. Contexto

Smoke test end-to-end do `CapabilityResolver` consumindo um catálogo + profile reais (não mocks). Garante que toda a cadeia (load → mutex → cycle → prereq → expand) funciona contra dados materializados em `capabilities/` e `profiles/`.

Primeiro de uma série de smokes do EPIC-0064 (10 totais até Phase 6). Foco: detectar regressão em refatorações futuras do resolver.

## 2. Acceptance Criteria

```gherkin
Scenario: Resolver feliz com profile java-cli-picocli
  Given catálogo capabilities/ populado (5 capabilities mínimas para o smoke)
  And profile profiles/java-cli-picocli.yaml
  When CapabilityResolver.resolve(profile)
  Then returns ResolvedCapabilitySet
  And contains [runtime.jvm, build.maven, lang.java, cli.picocli, runtime.docker]
  And no ResolutionWarning

Scenario: Resolver falha em profile que ativa pair excludes
  Given profile que ativa data.database.postgres + data.database.mongo simultaneamente
  When CapabilityResolver.resolve(profile)
  Then throws MutexConflict

Scenario: Resolver determinístico em 3 invocações
  Given mesmo profile, mesmo catálogo
  When CapabilityResolver.resolve() chamado 3 vezes consecutivas
  Then todas as 3 produzem ResolvedCapabilitySet com SHA idêntico (serialized JSON canonical)
```
