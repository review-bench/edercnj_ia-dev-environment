## 1. Contexto

Profile (`profiles/<name>.yaml`) é a unidade de declaração que o consumidor escolhe. Lista capabilities atômicas + parameters override. Esta story implementa:

1. `ProfileLoader` — lê `profiles/<name>.yaml` via Jackson e produz `Profile` record.
2. `ProfileExpander` — combina `Profile` + catálogo + `PrerequisiteResolver` para produzir `ResolvedCapabilitySet` (set de atomics + parameters effective + warnings).

`ResolvedCapabilitySet` é a entrada do `CapabilityResolver` (story-0064-0107).

## 2. Acceptance Criteria

```gherkin
Scenario: Profile minimalista (degenerate)
  Given profile listing apenas [runtime.jvm]
  When ProfileExpander.expand(profile, catalog)
  Then ResolvedCapabilitySet contains exactly 1 capability
  And no parameter overrides
  And no warnings

Scenario: Profile complexo expande prerequisites transitivamente (happy)
  Given profile [web.spring.boot]
  When ProfileExpander.expand(profile, catalog)
  Then ResolvedCapabilitySet contains [runtime.jvm, web.servlet, web.spring.boot]

Scenario: Parameter override aplicado (composition)
  Given profile com parameter "data.database.postgres.version=15"
  When ProfileExpander.expand(profile, catalog)
  Then ResolvedCapabilitySet.parameter("data.database.postgres.version") == "15"

Scenario: Profile com excludes simétrico falha (error path)
  Given profile lists [data.database.postgres, data.database.mongo]
  And postgres.excludes=[mongo]
  When ProfileExpander.expand(profile, catalog)
  Then throws MutexConflict (delegado para MutexValidator)

Scenario: Override de parameter de capability não declarada (boundary — warning)
  Given profile com parameter "x.y.z=foo" mas capability "x.y" não no profile
  When ProfileExpander.expand(profile, catalog)
  Then ResolutionWarning emitido: "override target 'x.y' not in profile"
  And expansion continua sem aplicar o override
```

## 6. Decision Rationale

**Decisão:** Profile parameter sobrescreve default da capability; override de parameter de capability inativa emite warning não-fatal.
**Motivo:** Override permite consumer customizar (e.g., versão do Postgres) sem editar o catálogo. Warning não-fatal mantém forward-compat: profile pode listar params de capability futura sem quebrar build hoje.
**Alternativa descartada:** Override silenciosamente ignorado quando target inativo. Rejeitada porque mascara bugs (consumer pensa que override está aplicado).
**Consequência:** `ResolvedCapabilitySet` tem 3 campos: capabilities (Set), parameters (Map), warnings (List). Warnings ficam visíveis no resultado para CLI reportar.

## 7. Implementation Notes

Profile YAML é estruturalmente simples: `capabilities: [...], parameters: { id.name: value }`. Reusa o ObjectMapper do `YamlCapabilityCatalogAdapter`.

Override de parâmetros: profile ganha sobre default da capability. Mas se profile listar parameter de capability não declarada, emite `ResolutionWarning` e ignora o override.
