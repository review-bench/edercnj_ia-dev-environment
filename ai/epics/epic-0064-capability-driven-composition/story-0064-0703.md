## 6. Decision Rationale

**Decisão:** Pebble placeholder `{{ activeCapabilities | sort | join(", ") }}` injetado em build-time; `ReadmeAssembler` popula contexto.
**Motivo:** Pebble já roda em Phase 3 pipeline (RULE-005 — Composer → Pebble → LLM). Reuso natural sem nova infraestrutura. README é gerado uma vez por build — performance ideal.
**Alternativa descartada:** README estático sem capabilities listadas. Rejeitada porque (a) downstream devs precisam saber o que está ativo, (b) onboarding sem essa info é guessing game.
**Consequência:** `ReadmeAssembler` é pequena classe (~30 LOC); reusa contexto Pebble do composer pipeline.
