## 1. Contexto

`OutputPruner` aplica o `CompositionPlan` ao `outputRoot`, escrevendo apenas os `included` e omitindo os `excluded`. Substitui o copy cego atual que duplica todo `targets/claude/` em `.claude/`.

Trata 3 cenários de pruning:

1. **Skill/Rule/KP/Agent excluído inteiro:** arquivo NÃO copiado.
2. **Fragmento excluído de skill incluída:** body do parent é renderizado pelo `CompositionEngine` (story-0064-0303) sem o fragmento.
3. **Hook excluído:** entry correspondente removida de `settings.json` (gerado dinamicamente pelo composer).

## 2. Acceptance Criteria

```gherkin
Scenario: Excluded artifact não é escrito
  Given plan.excludedArtifacts contém database-engineer.md
  When OutputPruner.execute(plan, output)
  Then arquivo .claude/agents/database-engineer.md não existe em output

Scenario: Included artifact é escrito
  Given plan.includedArtifacts contém x-arch-plan/SKILL.md
  When OutputPruner.execute(plan, output)
  Then .claude/skills/x-arch-plan/SKILL.md existe e tem mesmo conteúdo do source

Scenario: Idempotente — execute 2x não gera erro
  Given output já populado por execute prévio
  When OutputPruner.execute(plan, output) novamente
  Then no error
  And output unchanged (mesmo SHA por arquivo)

Scenario: Diretório vazio limpo se todos os filhos excluídos
  Given pruning remove todos os files de stack-patterns/quarkus/
  When OutputPruner.execute(plan, output)
  Then diretório quarkus/ não existe em output
```

## 5. Implementation Notes

Pruning de hooks: lê `settings.json` template, remove entries cuja `script` aponte para hook excluído. Diff aplicado in-memory antes de gravar.

Cleanup de diretórios vazios: pós-write pass com `Files.walk` + reverse-DFS removendo dirs sem children.
