## 6. Decision Rationale

**Decisão:** Cobertura de corner cases descobertos em retrospectiva Phase 4 (ordering inválido, fragment-id duplicado).
**Motivo:** Story 0410 cobriu casos básicos (slot declared but not used, body references undeclared slot). Phase 4 implementation revelou casos adicionais que escapavam — ordering syntax errors, accidental fragment-id collisions.
**Alternativa descartada:** Esperar incidentes em produção. Rejeitada porque audits proativos > reativos; CI catch é ordens de magnitude mais barato que debug em produção.
**Consequência:** audit ganha 2 novos checks (ordering schema + duplicate detection). Performance impact mínimo (regex + Set operations).
