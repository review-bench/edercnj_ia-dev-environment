1. Estende escopo para validar `fragment-slots.ordering` válido (apenas `fragment-order` ou `alphabetical` aceitos).

3. `--json` output para CI consumer.
4. Documentação completa em catalog.

## 2. Acceptance Criteria

```gherkin
Scenario: ordering válido aceito
  Given parent com fragment-slots: [{slot: X, ordering: fragment-order}]
  When audit roda
  Then exit 0

Scenario: ordering inválido falha
  Given parent com ordering: random
  When audit roda
  Then exit 1
  And error: "FRAGMENT_COHERENCE_VIOLATION: invalid ordering 'random'"

Scenario: fragment-id duplicado falha
  Given 2 fragments com mesmo slot=X e mesmo fragment-id=qa
  When audit roda
  Then exit 1
  And error: "FRAGMENT_COHERENCE_VIOLATION: duplicate fragment-id 'qa' in slot 'X'"

Scenario: --json
  Given --json
  When script roda
  Then JSON com violations[] estruturado
```
