## 1. Contexto & Escopo

Como **Engenheiro de Qualidade**, eu quero um teste smoke E2E `Epic0066PrTemplateSmokeTest`
que valide a cadeia completa do EPIC-0066 — render skill → audit gate → telemetria → phase
markers — rodando em `mvn verify`, sem chamadas reais à GitHub API nem criação de PRs reais,
para que a integridade de toda a entrega seja verificável de forma contínua e reproduzível.

Esta story é a última da epic (fase de verificação, bloqueada por todas as anteriores).
Ela traz o epic-level coverage a >= 95% line / >= 90% branch (conforme RULE-005-01 — gate
absoluto — fechando qualquer gap residual aberto pelas stories anteriores).

simulam: eventos de telemetria (50 events NDJSON), review artifacts, tech-lead review, e
verify envelope. Nenhum real `gh pr create` é invocado — o render skill escreve o body para
um arquivo temporário e o test valida a estrutura por parsing.

## 8. Decision Rationale

**Decisão:** smoke test usa subprocessos reais (`ProcessBuilder`) para chamar `audit-pr-template.sh`
e `telemetry-consolidate.sh`, não mocks dos scripts.

**Motivo:** mocking de scripts Bash em Java introduz falsa segurança — o teste passaria mesmo se
o script estivesse corrompido. Invocar o script real (com fixtures) é a única forma de detectar
regressões de shell.

**Alternativa descartada:** mockar chamadas de shell via `ProcessBuilderMock` (library de teste).
Rejeitado porque adiciona dependência de test library não-padrão e cria teste que não detecta
regressões reais nos scripts.

**Consequência:** o smoke test tem dependência ambiental — `jq` e `gh` devem estar instalados
no ambiente de CI. Isso já é garantido pelas stories anteriores: `AuditPrTemplateAuditorTest`
(story-0066-0007) invoca o script via output gerado (`.claude/scripts/audit-pr-template.sh
--self-check`, derivado do source-of-truth `java/src/main/resources/targets/claude/scripts/
audit-pr-template.sh`) durante `mvn verify` e falha o build se as ferramentas estiverem
ausentes (Rule 26 §Java test layer / padrão pós EPIC-0061 — `audit.yml` foi removido;
RULE-007 / `CiPipelineLeanSmokeIT` proíbe `audit-*.sh` em `scripts/` root, daí o caminho
via source-of-truth + output regenerado).

**Decisão secundária:** fixtures em `src/test/resources/fixtures/epic-0066-smoke/` são estáticas.

**Motivo:** fixtures dinâmicas (geradas em `@BeforeAll`) criam dependência de lógica do próprio
sistema testado — circular. Fixtures estáticas são determinísticas e auditáveis via `git diff`.
