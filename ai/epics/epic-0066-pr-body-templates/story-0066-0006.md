## 1. Contexto & Escopo

Como **Operador de Criação de Épico**, eu quero que a skill `x-feature-create` (renomeada de `x-epic-decompose` por EPIC-0065) invoque `x-internal-pr-body-render --kind=backlog` ao final de sua execução — após os artefatos de backlog (epic.md, stories, IMPLEMENTATION-MAP.md) serem commitados no `epic/XXXX` — de modo que a PR de scaffolding (`epic/XXXX → develop`) tenha body gerado a partir do template `_TEMPLATE-PR-BACKLOG.md`, incluindo o marcador `<!-- template-version: 1.0 -->` exigido por `audit-pr-template.sh`.

Hoje `x-feature-create` cria a PR de scaffolding com body inline (prosa ad-hoc) que varia por operador e não possui o marcador de template-version. Após EPIC-0066, toda PR de scaffolding sem o marcador será rejeitada por `audit-pr-template.sh` (story-0066-0007).

Esta story:
1. Adiciona uma **Phase N+1 — PR-BODY-RENDER** (fase final) ao `x-feature-create/SKILL.md`.
2. Invoca `x-internal-pr-body-render --kind=backlog` via Pattern 1 (INLINE-SKILL — Rule 13) como **MANDATORY TOOL CALL** (Rule 24 §Camada-1).
3. Lê o resultado do arquivo `--out` e o passa para `gh pr create --body-file`.
4. Refatora ou remove qualquer construção inline de body existente que possa colidir.
5. Documenta o caminho de **fallback** (body manual) sob `## Recovery` quando a render skill retorna exit ≠ 0 (fail-open, conforme RULE-004).

## 3. Contratos & Endpoints

### 3.1 Phase N+1 — PR-BODY-RENDER (nova fase final)

Esta phase é inserida **após** os commits de artefatos de backlog e **antes** de `gh pr create`. O fluxo existente que invoca `gh pr create` deve ser modificado para usar `--body-file` em vez de `--body`.

```
## Phase N+1 — PR-BODY-RENDER

MANDATORY TOOL CALL — Rule 24 §Camada-1 / Rule 13 Pattern 1 (INLINE-SKILL):

Invoke the `x-internal-pr-body-render` skill via the Skill tool:

    Skill(skill: "x-internal-pr-body-render", model: "haiku", args: "--kind=backlog --epic-id=<EPIC_ID> --out=<TMP_BODY_PATH>")

Se exit=0:
  BODY_FILE=<TMP_BODY_PATH>
  → usar `gh pr create --body-file "$BODY_FILE"` na invocação seguinte
  → registrar INFO: "Render skill produced body with template-version marker"

Se exit≠0:
  WARN "[render-fallback]: x-internal-pr-body-render falhou (exit $?). Usando body manual."
  → ativar caminho de fallback descrito em ## Recovery
  → body manual NÃO conterá o marcador template-version (audit detectará PR_TEMPLATE_VIOLATION)
```

**Notas de implementação:**

- `<EPIC_ID>` é o ID numérico do epic (ex: `0066` ou `EPIC-0066` — a render skill aceita ambos os formatos per §3.3 do epic-0066.md)
- `<TMP_BODY_PATH>` criado com `mktemp -t backlog-body-XXXXXX.md`; chmod 600 aplicado antes do uso (Rule 06)
- Cleanup: `rm -f "$TMP_BODY_PATH"` após `gh pr create` — sucesso ou falha

### 3.2 Modificação de `gh pr create` (Phase de criação do PR)

A invocação existente `gh pr create --body "..."` deve ser refatorada para:

```bash
# ANTES (inline body — pré-EPIC-0066)
gh pr create \
  --base develop \
  --title "$PR_TITLE" \
  --body "$PR_BODY_INLINE"

# DEPOIS (body via arquivo — pós-EPIC-0066)
gh pr create \
  --base develop \
  --title "$PR_TITLE" \
  --body-file "$BODY_FILE"
```

Quando o fallback é acionado, `$BODY_FILE` aponta para um arquivo temporário com o body manual (seção `## Recovery`).

### 3.3 Extração de Dados para a Render Skill

A render skill `--kind=backlog` popula o template a partir dos artefatos de backlog já commitados. O implementador DEVE ler o `IMPLEMENTATION-MAP.md` para extrair a lista de stories:

```bash
# Extrair lista de stories do IMPLEMENTATION-MAP.md (produzido por x-epic-map)
IMPL_MAP_PATH="ai/epics/epic-${EPIC_SLUG}/IMPLEMENTATION-MAP.md"
STORY_COUNT=$(grep -c "^| story-" "$IMPL_MAP_PATH" 2>/dev/null || echo "0")
```

O `x-internal-pr-body-render` consome os artefatos diretamente por path (não precisa de pré-processamento aqui). A Phase N+1 apenas fornece `--epic-id` e `--out`; a render skill resolve os paths internamente via `PathResolver`.

### 3.4 Contrato de Invocação da Render Skill

```
Skill(skill: "x-internal-pr-body-render", model: "haiku", args: "--kind=backlog --epic-id=<EPIC_ID> --out=/tmp/backlog-body-XXXXXX.md")
```

| Argumento | Valor | Fonte |
| :--- | :--- | :--- |
| `--kind` | `backlog` | fixo para x-feature-create |
| `--epic-id` | `${EPIC_ID}` | variável resolvida na Phase 0 de x-feature-create |
| `--out` | `$(mktemp -t backlog-body-XXXXXX.md)` | arquivo temporário; chmod 600 |
| `model` | `haiku` | Rule 23 §Utility — render skill é utilitário de template |

Exit codes que disparam fallback: qualquer exit ≠ 0 (`INVALID_KIND`, `OPERATIONAL_ERROR`, `INVALID_SCOPE`)

### 3.5 Fallback Manual (caminho `## Recovery`)

Quando a render skill retorna exit ≠ 0, um body manual estruturado é gerado diretamente:

```markdown
## Summary

Scaffolding PR: cria epic + stories + IMPLEMENTATION-MAP para <EPIC_ID>.

## Backlog Entregue

| Artefato | Path |
| :--- | :--- |
| Epic | `ai/epics/<epic-slug>/epic-<EPIC_ID>.md` |
| Implementation Map | `ai/epics/<epic-slug>/IMPLEMENTATION-MAP.md` |
| Stories | <STORY_COUNT> arquivos |

## Orchestrator Evidence

| Campo | Valor |
| :--- | :--- |
| Skill | x-feature-create |
| Epic ID | <EPIC_ID> |
| Stories created | <STORY_COUNT> |

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

**WARN explícito emitido:**

```
WARN [render-fallback]: PR body gerado via body manual (sem template-version marker).
     audit-pr-template.sh reportará PR_TEMPLATE_VIOLATION para este PR.
     Investigar: x-internal-pr-body-render --kind=backlog exit code = <N>.
```

## 8. Decision Rationale

**Decisão:** adicionar Phase N+1 ao final de `x-feature-create`, após os commits de artefatos, em vez de refatorar a phase de criação de PR existente.

**Motivo:** A criação de PR já existe como fase bem definida em `x-feature-create`. Adicionar uma fase de "render preparation" antes dela, em vez de modificar a fase de criação, preserva a separação de responsabilidades e facilita revisão de PR (diff menor, mudança cirúrgica).

**Decisão sobre `--body-file` vs `--body`:** `gh pr create --body-file` aceita um arquivo diretamente, evitando problemas com quoting e escape de caracteres especiais em Bash (que afetam o body Markdown com colunas de tabela, backticks, etc.). Mais seguro e idiomático para bodies longos.

**Decisão sobre fallback:** falha-aberto (RULE-004) — PR é criado mesmo sem template. O WARN avisa o operador sobre a ausência do marcador. O audit downstream (story-0066-0007) bloqueará o merge se o PR entrar na CI. Isso é preferível a abortar a criação do PR (que pode ser um backlog de days de planejamento).

**Decisão sobre dependência em EPIC-0065:** esta story é explicitamente blocked por EPIC-0065. Não se tenta compatibilizar o path antigo `x-epic-decompose` — essa would-be gambiarra violaria Rule 13 Pattern 1 (referência ao nome antigo) e Rule 19 §Skill Renaming (manter o nome antigo por 1 release é responsabilidade de EPIC-0065, não desta story).

**Alternativa descartada:** tornar a render skill chamada em Pattern 2 (subagent). Rejeitada pela mesma razão que story-0066-0005 — precisamos do arquivo resultante imediatamente para passá-lo como `--body-file`. Pattern 1 (INLINE-SKILL síncrono) é a escolha correta.
