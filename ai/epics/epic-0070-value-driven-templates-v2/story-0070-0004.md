**Status:** Pendente

> 🟡 **REFINEMENT REQUIRED** — `/x-story-refine` (EPIC-0069) preencherá este bloco antes do kickoff.

## 1. Visão

Como **arquiteto / novo dev**, quero `docs/architecture/system.md` vivo descrevendo a arquitetura técnica completa do sistema, alimentado parcialmente pelo YAML do projeto (stack, persistência, comunicação, observabilidade, segurança baseline) e com seções narrativas para decisões manuais (resilience, perf budget, integrações, decision log).

> **Marco arquitetural** (IMPLEMENTATION-MAP §7): se este template for mal-modelado, o `system.md` produzido nos projetos cliente fica ruim para sempre. Code-review extra recomendado.

## 2. Entrega de Valor

- Arquitetura técnica vive em **um arquivo só**, navegável.
- Onboarding de novo dev passa de "leia 60 arquivos" para "leia 1 arquivo + rules + YAML".
- **Métrica:** novo dev consegue mapear arquitetura completa em ≤ 30min lendo só o `system.md` (medido por survey pós-rollout).

## 6. Decision Rationale

**Decisão:** Template + auto-fill parcial via YAML + seções narrativas manuais. **Motivo:** YAML traz "o quê" (determinístico), operador escreve "como/por quê" (narrativo). **Alternativa descartada:** 100% auto-fill (vira XML rendido — sem narrativa). **Consequência:** placeholders bem documentados no template; convenção `{{KEY}}` documentada em HTML comment no topo.
