This document describes the branch protection configuration applied via `scripts/setup-branch-protection.sh`. Branch protection is the **Camada 4 (defense-in-depth)** of the EPIC-0063 enforcement model — last line of defense if Camadas 0-3 are bypassed.

## Modes

### Standard Mode (default)

```bash
./scripts/setup-branch-protection.sh --branches develop,main
```

Applies:
- `required_status_checks: strict=true, contexts=[...]`
- `enforce_admins: true`
- `required_pull_request_reviews: required_approving_review_count=1, dismiss_stale_reviews=true`
- `restrictions: null`

### Strict Mode (recommended for production)

```bash
./scripts/setup-branch-protection.sh --branches develop,main --apply-strict
```

Adds on top of standard:
- `required_linear_history: true` — bloqueia merge commits que não são fast-forward
- `allow_force_pushes: false` — bloqueia force-push em qualquer branch protegida
- `allow_deletions: false` — bloqueia deletion de branches protegidas

## Idempotência

Re-execução do script é no-op se a configuração já foi aplicada — GitHub API trata PUT como update idempotente.

## Verificação

```bash
gh api repos/edercnj/ia-dev-environment/branches/develop/protection \
  | jq '{
      checks: .required_status_checks.contexts | length,
      reviews: .required_pull_request_reviews.required_approving_review_count,
      linear: .required_linear_history.enabled,
      force_pushes: .allow_force_pushes.enabled,
      deletions: .allow_deletions.enabled
    }'
```

Saída esperada (strict mode):

```json
{
  "checks": 7,
  "reviews": 1,
  "linear": true,
  "force_pushes": false,
  "deletions": false
}
```

## Aplicação

O script é executado **manualmente** uma única vez (FR15 Open Question 3 — manual mas gated em PR review). Não é executado em CI para evitar permission scope creep.

## Bypass

Não há bypass GitHub-side de branch protection — admin pode desabilitar manualmente via UI, mas é auditável via `audit log`. Para emergências, usar `git push -f` é bloqueado por `allow_force_pushes: false`.
